# 记忆

记忆的存储、可见等级投影和修订属于本体；检索器、向量模型、导入器、经历整理器是可替换的扩展（见 `sdk.md`）。每个伴侣一个独立记忆库，SQLite 是唯一事实来源（Markdown 副本只供阅读）。

伴侣身份由第一次写入记录或第一次导入时确定的 companion_uid 标识，32 位十六进制、永不改变；配置编号只是目录与命令名称。该标识仅用于导入判断，不改变伴侣行为，见 memory-spec §1.1a、§9.2。

建库时没有身份，空库指没有 companion_uid；写过再撤销也不是空库。原生包首次导入沿用包的身份，只有本人的记忆可以搬回，具体见 memory-spec §9。

新伴侣不提供预置记忆或初始资料。投影内没有有效记忆时注入“你们之间还没有记住的事”；有记忆但未检索到时不注入这句。人设描述身份、关系和说话方式，具体共同经历只以记忆和任务记录为准。

## 1. 记录字段

除内容、时间、修订号外：

| 字段 | 取值 |
|---|---|
| 可见等级 | 私密 / 公开可见 / 关系。由模型判断，拿不准时归为私密 |
| 写入方式 | 自动 / 用户确认；与可信程度对应，见 memory-spec §1.1 |
| 可信程度 | owner_confirmed / owner_stated / observed，由本体填写；聊天和插件操作只升不降，用户确认的导入操作（含导入器再次导入）例外见 memory-spec §1.3 |
| 可信来源会话 | origin_conversation_id，由本体填写；未知为 null |
| 来源类型 | 私聊 / 群聊 / 用户与伴侣的群内互动 |
| 来源引用 | 账本追踪号（可追溯，不对外暴露） |

## 2. 写入

- A3.3 只从主人的话和主人与她的互动中当场记；模型判断是否值得记，包括敏感内容（默认私密），由本体按身份填写可信程度。修订、去重与撤销见 `../architecture/memory-spec.md` §1–§2；插件只能修订或撤销 observed 记录，owner_confirmed、owner_stated 只读。
- A3.4 中别人说的关于主人的话只能记成“某人说过某话”，不能当作关于主人的事实。
- 不写入：第三方说的话（档案除外）、转述、截图内容、她自己的推测。
- 不从群消息或模型建议中自动确认身份变化。
- 用户说"不用记"时不保存。

## 3. 可见等级投影

由本体按场景过滤，插件和模型拿不到超出场景的记忆。场景类型在实例配置中定义，例如：

| 场景 | 可用等级 |
|---|---|
| 主人私聊 | 全部 |
| 家庭群（只有主人和本部署的伴侣） | 公开可见、关系；默认不含私密，可以在伴侣配置 `memory.private_scenes` 中开启 |
| 其他群 | 公开可见、关系 |

可见等级之外还要满足 `memory-spec.md` §3.2 的来源限制：群来源仅在来源群及所有对内场景可见；主人私聊来源按可见等级使用；未知来源（null）仅在对内场景可见。插件提供的 source_type/scope 不作为投影依据。陌生人私聊不注入记忆，撤销记录任何场景都不可见。

## 4. 检索

- 效果优先：本机向量模型的语义检索 + 中文关键词检索，先投影再两路召回，以 RRF 融合，可选 `memory.reranker` 重排；同等相关时按可信程度排序。契约见 memory-spec §4。
- A3.3 只用假向量和假重排模型，不下载模型。真实模型选型和容量一起实测，下载前经用户同意。
- 向量扩展不可用时退回关键词检索，不报错。

以下 §5–§8 属于 A3.4，具体契约另行确认。

## 5. 经历

把一段时间内的相关对话整理成"经历"条目（`memory.consolidator` 扩展）。私聊经历和主人与伴侣的共同经历永不淡化。

## 6. 档案（群友）

- 跨群共享；只记公开、无害的信息：称呼、常聊话题、说话风格、和伴侣的互动。
- 使用时不提来自哪个群。没有新信息时不刷新、不调用模型。
- **删除只能由主人执行**（WebUI 或主人私聊指令）；对方要求"忘掉我"时用角色口吻带过。

## 7. 软遗忘

只降低检索权重，久了冻结，可以恢复，**永不自动删除**。
- 永不淡化：私聊及其衍生记忆、主人明确表达的偏好和身份、主人与伴侣之间的事件。
- 慢慢淡化：档案中的话题、其他群聊经历、黑话。速度可配置。

## 8. 黑话

- 由行为插件学习，存储使用本体记忆接口。
- 主动使用按群隔离；主人在私聊中提到他所在群的梗时能理解，但不主动使用。

## 9. 接口

A3.3 的本体工具为 `core_remember`、`core_forget`、`core_recall`（memory-spec §2、§5）；所有读取经过本体 `project(scene, conversation_id)`，出站守卫读取见 §7。插件的 search/get/write/revise/retract 按 sdk-spec §7.5 裁剪权限和绑定会话。加密导出、两步导入与撤销导入见 memory-spec §8–§9。所有修改保留修订或审计；回想、档案、软遗忘接口在 A3.4 细化。
