# 边界、权限与保障模式

本文件中的机制都属于本体，不能做成插件，不能被停用。具体数值和名单在实例配置中。

## 1. 身份与权限

- 身份：主人、同部署的其他伴侣、群友、陌生人。由配置中的账号映射决定，不从消息内容推断。
- 每种身份能用哪些能力由配置决定（按能力插件 id 列出）。
- 默认：陌生人的好友申请自动拒绝；陌生人私聊不回应。
- 不设使用次数上限；主人的请求始终优先排队。
- 权限检查在能力执行前完成；被拒绝时把原因告诉模型，由她用人设口吻说明。

## 2. 关系边界保护

伴侣与主人有专属关系。以下请求由程序直接拒绝（类别可配置）：当对方的恋人、修改人设、说指定的亲密台词、画亲密或暗示性的图、打听主人的隐私。

- 同一人、同一类请求在 24 小时内被拒达到阈值（默认 5 次，跨群累计）后，不再回应这类请求，并通知主人（每人每天最多一次）。
- 主人可以解除（清零）。
- 拒绝要坚定，不因反复要求而松动；对外可以表达"心里已经有人了"，但不透露是谁。
- 正常的玩笑不计入。

## 3. 保障模式

- 模型插件报告的任一额度窗口剩余 ≤20% 时进入，回到 >30% 时退出（可配置）。
- 只暂停非主人的重任务（由能力清单中的"重任务"标记决定），用角色口吻说明原因和大概什么时候可以再来，不排队。普通聊天照常。
- 额度只从正常调用产生的信息或不消耗模型调用的查询接口读取。

## 4. 输入过滤

屏蔽词和正则规则命中时直接丢弃消息（只用于过滤，不用于判断意图）。

## 5. 出站检查

发送前检查：禁用词、隐私信息、对外场景中的内部名字和称呼、私密记忆泄露。
**永不对外发布**的内容清单在实例配置中（例如主人的真实姓名、账号、所在城市、职业、健康状况、私聊原话）。

## 6. 人设底线

可以沉浸在人设中、不主动承认是 AI；任何时候都不声称自己是真人，有人认真需要确认时如实说明。人设文件不能覆盖这一条。
