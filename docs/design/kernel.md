# Kernel：账本、防重与交付

## 1. 统一任务账本

每个伴侣一本账本。聊天回复和任务（委托）共用一本账，不允许出现多本账本互相矛盾。

每条记录：追踪号、来源事件、会话、请求人（逻辑身份）、类型（聊天 / 任务）、任务编号、父子关系（例如另一位伴侣协助）、调用的能力、产物（资产引用）、各阶段耗时、交付收据、状态。

- 模型在上下文中能看到自己最近做过什么（任务结果摘要），被问起时如实回答。
- 对方提到一件账本和记忆中都没有的事时，不能顺着认下来（见 `lessons.md`）。

## 2. 防重与恢复

- 入站事件按平台消息 ID 去重。
- 执行能力前计算幂等键；相同键只查询已有结果，不重新执行。
- 进程重启后：未完成的任务标记为"中断"，**不自动重放**；发送结果未知的消息不补发。
- 取消：用户说"取消/停止"走快速路径，任务标记取消，正在执行的能力收到取消信号。

## 3. 交付

- `DeliveryIntent` → 平台插件发送 → `Receipt` 写回账本。
- 拆分发送时，已开始的一组要发完；某一条结果未知时，剩余的不再发送。
- 平台的格式和大小限制在交付前由资产库统一处理。

## 4. 任务编号与任务单

- 编号为 8 位十六进制，生成时在账本中查重。
- 任务单的显示格式是**伴侣配置中的模板**，例如：`【{label} {id} · {name} · 协助：{helper} · 用时约{duration}】`。`label`、名字等都来自伴侣配置，按场景（对内 / 对外）选择不同的显示名。
- 不显示能力类型（只记在日志里）。
- `python -m clytie task <编号>` 查询完整记录。

## 5. 表情回应

- **只有任务**才对用户的消息加表情回应；普通聊天和自然接话一律不加。
- 行为插件可以申请例外（例如睡眠插件的 💤），例外必须在清单中声明 `message.react` 权限，并在其设计文档中写明条件。
- 长任务执行过程中不主动发进度，用户问起时再回答。

## 6. 事件总线

本体发布的事件：`message.received`、`reply.sent`、`task.started`、`task.completed`、`task.failed`、`companion.state_changed`、`quota.changed`、`plugin.enabled/disabled`。插件可以发布带自己 id 前缀的事件（如 `sleep.state_changed`）。事件负载类型在 SDK 中定义。

## 7. 日志

- 每条进入处理流程的请求记一行摘要：追踪号、任务编号、各阶段耗时、调用的能力、结果。**不记录消息正文**；未触发的群消息只计数。
- ERROR / WARN / INFO / DEBUG，默认 INFO；按天切分，保留 14 天，总量 ≤500 MB。
- `python -m clytie status` 显示伴侣、平台、模型、额度状态。
