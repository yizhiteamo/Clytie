# 守护进程

A4.1 实现规格见 `../architecture/supervisor-spec.md`；API 与后台启动在 A4.2，备份与日志轮转在 A4.3。

## 1. 进程结构

A4.1 使用 `python -m clytie supervisor start` 启动前端窗口；真正的守护进程脱离控制台运行（Windows DETACHED_PROCESS，Linux setsid）。按 supervisor-spec §1 的用户确认规则，Ctrl+C 按配置 task_mode，关闭窗口和前端 EOF 固定触发取消模式安全停止，第二次 Ctrl+C 发送 escalate；停止期间再次启动等待锁释放。伴侣子进程独立进程组，Windows 纳入 kill-on-job-close Job Object；子进程通道 EOF 后按取消模式、不等交付，非迁移阶段 5 秒内退出，迁移阶段等待本次迁移和既定恢复完成。A4.2 才提供启动后立即返回的 `--detach` 与双击启动脚本。以下结构包含后续阶段。

```
clytie supervisor（单实例，进程锁在 CLYTIE_HOME/run/）
├─ API 服务（127.0.0.1）
├─ 伴侣进程（每个伴侣一个）
└─ 外部组件（通过 docker 命令管理）
```

`python -m clytie supervisor start|stop|status`。由用户手动启动，不设置开机自启，不创建系统服务或计划任务。

## 3. 重启策略

- 崩溃后按退避间隔重启；连续失败 N 次后停止并通知。
- 凭证失效或额度用完时**不重启，只通知**；不自动重新登录。
- 重启不重放旧任务，发送结果未知的消息不补发。
- 安全停止：停止接收新消息，等待正在交付的消息发完（有超时）；长任务可选择等待或取消。

### 安全停止（A4，用户已确认）

- 关闭期间被取消时，先完成所有伴侣的关闭处理，再向调用方传播取消，不能装作正常返回。同时保留完整关闭结果，包括每个伴侣的 `stopped` / `not_stopped` 及未停止原因，调用方在收到取消后仍能取得这些结果（#7）。
- 同一伴侣内某个插件停止出错时，继续尝试停止其余插件，仍按依赖方先停的顺序；最终在该伴侣的 `not_stopped` 中列出失败插件及原因。一个伴侣的失败不阻止其他伴侣关闭（#10）。
- 上述两项在 A4.1 实现，接口见 supervisor-spec §6：关闭被取消时，在全部伴侣关闭完成后抛出携带完整 `.result` 的 `ShutdownCancelled`。

## 4. 通知

通知渠道是插件（扩展点 `notifier`，由 SDK 定义），例如：通过另一位在线伴侣的平台账号私聊通知主人、Windows 桌面通知。A4.1 在守护进程内装配实例级通知插件，配置为 `notify.plugins`；上下文只有 config、log、clock、subprocess。同一问题默认 6 小时内只通知一次，冷却持久化；未送达不进入冷却，只在问题仍存在时最多每 10 分钟重试。静默期间暂停 outward 通知，其他通知照常。

运行时负责：备份与保留策略清理、恢复校验、日志轮转、软遗忘扫描。

### A4.2 管理收尾

已停止伴侣的记忆管理使用独立工作进程（api-spec §4.3a），守护进程只协调与查询。关窗/EOF 进入取消模式，其他伴侣并行停止；wait 可升级为取消。管理工作进程的停止时限仅为仍在收尾的提醒，不触发自动强杀，完成即退出；普通伴侣子进程时限与迁移保护不变。中断后核验锁、进程身份、事务与文件，不自动重做请求；恢复受阻仅阻止该伴侣。

## A4.3 备份与维护（已批准，待实现）

完整规格见 `../architecture/backup-spec.md`。

复用管理操作的稳定编号、执行者 PID+创建身份、OS 锁、阶段与提交证据。常规备份工作进程只写备份/本次临时区域，不接管活动伴侣的业务写权限；捕获请求由持有数据的组件响应。恢复工作进程只写明确的新目标。
阶段至少为 accepted、preparing、capturing、copying、verifying、publishing、committed、cancelled、failed、recovery_blocked。数据发布前记录明确目标/临时文件、校验值与阶段；目录重建见 §8。进程退出、HTTP 超时与断连不代表成功或取消。
关窗/EOF 拒绝新操作，取消可中断准备/捕获/复制；已进入必要发布或恢复提交的阶段先完成核验收尾。wait 等待，escalate 转协作取消；沿用 A4.2 的 120 秒提醒而非对数据提交强杀。普通伴侣总超时与迁移保护不变。
停止时有未备份记忆或到期完整备份，至多登记一次 shutdown 触发；业务安全停止后从稳定状态获取最终快照，不阻止其他伴侣先完成停止。shutdown 触发不能递归产生新触发；escalate 可取消尚未进入发布的备份。没有待办时立即正常退出，不固定等时间。副本复制可取消并留待下次，不能为了离线乙阻止停止。
强杀重启后只核验已登记操作、发布产物及明确临时文件，不重放旧请求；未发布且无法完成核验的标失败，下一次自动计划是新的备份。备份核验失败不阻止原健康伴侣启动；新恢复目录的不确定状态只阻止该目标启动。

维护模式仅启动本机管理 API，鉴权不变，不启动伴侣或自动备份。恢复目标与维护管理 home 分开；ready_for_switch 目标自身可启动维护模式登记 source_stopped，之后正常启动再 acknowledge。普通日志轮转与审计保留分开，审计不按普通日志份数删除。
