# ADR 0039：插件读取形象资料，以及能力之间的服务调用

状态：草案，随 `comic-spec.md` 一起确认。

## 问题

用户希望她能把每日一报画成漫画，自己当主角（2026-11-25）。要让主角每一页都像同一个人，画图时必须附上她的形象参考图。现在有两处规定挡着：

1. appearance-spec §8 写明画图插件读不到参考图，"以后按 vision-spec §9 V3 的权限开放时另行决定"。
2. 漫画工具要调用画图插件来画每一页。platform-capabilities-spec §3 定过"能力之间的服务调用"的规则，但还没有实现：服务调用不知道是谁、在哪个会话发起的，也不能传递资产。

## 决定

1. 漫画工具做成独立的能力插件 `comic-maker`，画图通过 `image-gen` 的服务 `image.render` 完成。`image-gen` 只负责调用画图接口。
2. 新权限 `appearance.read`：插件可以只读本伴侣当前的形象描述和"当前"参考图。参考图是只在本次调用中有效的临时引用。启用时由用户确认，并提示参考图会发给画图服务商。
3. 服务调用：
   - 服务声明 `context: true` 时收到调用方的记录、说话人、会话和取消令牌；
   - 声明 `scope_as` 时，宿主按调用方的说话人和会话检查对应工具的权限和使用范围；
   - 参数中的资产只在这次调用中交给被调用方；
   - 用量和产物记在调用方的记录下。
4. 角色表和字体库归 `comic-maker` 管，存在插件数据和资产库中。本体不新增存储。
5. 以上属于 SDK 0.20，都是新增。

## 不选的方案

- **把漫画做进 `image-gen`**：`image-gen` 会同时管画图接口、分镜、角色表和字体，越来越重；以后换画图后端时，漫画逻辑也要跟着改。
- **`comic-maker` 自己直接调用画图接口**：凭据、画质设置和错误分类都要再写一遍，用量也记不到同一处。
- **把参考图长期交给插件**：插件可以把参考图存下来另作他用。临时引用只在这次调用中有效。
- **主角写死某个形象**：换了人设或者让别的用户使用时就不对了。主角始终是本伴侣自己的形象资料。
- **由程序把台词排进对话框**：要先识别画面里的对话框位置，很难做稳。参考漫画说明，画图模型直接写短台词的效果可以接受；准确的事实放在配的文字里。

## 影响

- SDK 0.20：`appearance.read` 和 `ctx.appearance`，服务清单的 `context`、`scope_as`，处理函数的 `call` 参数。已有插件不用修改。
- appearance-spec §8：有 `appearance.read` 权限的插件可以读取当前参考图。
- platform-capabilities-spec §3：服务调用的规则在本期实现。
- 漫画每页一次高质量画图，有真实费用。主动开口时的次数由 `proactive.tools` 控制。
