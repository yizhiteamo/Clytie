# ADR 0005：A3.1 账本物理存储与运行方式

状态：实现选型；逻辑契约以 kernel-spec 为准。

每个伴侣使用标准库 sqlite3，文件为 `companions/<cid>/ledger/ledger.sqlite3`。七个逻辑实体各有独立表，保留字符串主键与 JSON 数据；任务编号、来源事件和能力幂等键有唯一索引。原子操作使用短事务，事务内不执行插件、不跨 await。选择 SQLite 是为了复用成熟的事务和崩溃恢复机制，不引入额外数据库服务。

账本运行锁沿用稳定文件上的 Windows 字节锁 / Linux flock，覆盖启动迁移与整个运行期。只读查询以 SQLite `mode=ro` 打开，不创建文件、不迁移、不修正状态。模式版本使用 `PRAGMA user_version`，版本变化由迁移的最后一个事务提交。查询时不会启动平台、模型或插件。

模式升级复用 ADR 0004 的实例密钥和 AES-GCM。账本快照有独立的认证头、路径和保留规则，不调用插件快照的三份保留逻辑。文件树只允许安全相对路径；验证时先解密到实例内临时目录，逐文件比对哈希。恢复不替换 ledger 目录，保留同一把运行锁；新增文件先存入加密失败现场，再逐个移除。

入账时间另存于内容所属实体，用于内容保留期；不以较早的整条任务创建时间清理迟到结果。状态、编号、防重与关联关系不参与内容清理。事件队列和调度计划不持久化，重启不重放任务。

设置内容保留期时，运行持锁期间每 60 秒用注入时钟触发清理，与账本快照过期检查一起执行；有迁移日志时跳过。只读任务查询直接读取系统锁信息，不通过短暂获取锁探测。Linux 匹配设备号和 inode，Windows 读取锁定字节并检查系统错误码；无法判断时返回查询错误。

固定周期按 Decimal 换算秒数，以启动锚点计算每次序号，不累加浮点周期。MockClock 的 `advance_and_drain` 逐个到期点推进；直接 `advance` 用于一次跳过多个周期的测试。日历计划使用 zoneinfo，只给 at/days 应用本地时区。

A3.1 不提供真实平台连接入口；测试显式注入假能力、假平台、MockClock 和临时实例。队列、账本、交付、事件总线和状态回应在本体模块中，插件仍只依赖 SDK。
