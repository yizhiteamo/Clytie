# ADR 0012：记忆管理工作进程与提交核验

状态：实现选型；行为依据为用户确认的 Issue #57 与 api-spec §4.3a。

停止伴侣的管理操作使用独立 Python 子进程，复用 MemoryAPI；不使用守护进程线程执行同步记忆业务。父进程持久接受操作并持有独立跟踪任务，HTTP 请求只等待结果。输入走私有管道，不放进命令行、环境变量或操作日志。每个伴侣共用 OS 锁保护管理接受、工作执行和启动；记录 PID 及 OS 进程创建时间，锁仍由 OS 判定。忙时立即拒绝，不以后台队列改变语义。

操作记录采用版本化 JSON 原子写入，目录位于 companions/<cid>/management/operations。阶段先于危险动作落盘；数据库提交标记与业务修改在同一事务写入现有审计表，避免单独日志成功却事务失败的窗口。文件产物记录明确路径与校验信息，先写临时文件并校验，再原子发布。导出涉及公钥时记录公钥变更及产物发布顺序；核验旧/新值，不覆盖其他已完成操作的结果。公钥不是恢复码原文，恢复码不持久化。

启动核验仅收敛已发生的操作：核对数据库完整性及事务标记、已发布产物和锁持有者；已提交保留结果，未提交核验回滚，清理只涉及记录中的明确临时文件。不能证明安全时持久阻止对应伴侣，不重放原请求、不创建空库替代。HTTP 断线、进程退出和取消请求均不是提交证据。

管理取消从首次进入取消模式计时，用注入 Clock 驱动提醒；到阈值仅提示，不杀工作进程。wait/escalate 与普通伴侣关闭并行。跨进程互斥和强杀边界分别在 Windows/Linux 使用真实测试进程验证，业务时间使用 MockClock。
