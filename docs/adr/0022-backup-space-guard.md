# ADR 0022：备份源估算、临时预算与 WAL 保护

状态：实施说明；依据 backup-spec §4.1、§6.3、§13.10，未新增配置或清理权限。

## 估算

开始创建前只读取明确候选的文件属性：所选伴侣的数据库/WAL、实例内共享与伴侣资产，instance 另含配置、人设、插件目录、管理历史及守护审计。配置凭据值、secrets、普通日志、已有包、旧实例均不作为备份源读取；旧实例与特殊快照只列已有授权范围内的占用摘要。候选估算包含可能最终排除的插件材料，因此是保守估算，不承诺最终包大小。链接、未知对象和读取失败不能作为完整的零字节材料。

记原始候选字节为 S、核心数据库及当前 WAL 总量为 D。格式预算包含容器最大 manifest、逐文件路径与帧、逐 MiB 分块 zlib compressBound 开销及认证帧；不假定压缩收益。包估算为 S 加格式预算，临时峰值为 D 加两份 S 加包估算，分别对应核心物化、捕获材料、验证展开与待发布包。硬链接/移动可能减少实际占用，估算不以此扣减。单卷 WAL 增长预算为 max(一 MiB, min(reserve, max(64 MiB, D)))，为小库正常短突发保留余量，并用 reserve 封顶，是工程保护上限，不是允许业务无限增大 WAL 的承诺。

每个涉及卷分别计入配置 reserve（默认一 GiB），同卷只计一次；工作卷另外计临时峰值、数据库所在卷计 WAL 增长余量。发布目标若在另一卷，额外保留一份包空间；此估算不替代现有原子发布对于文件系统的要求。开始前各卷可用空间必须满足各自需求；运行时检查 reserve、WAL 相对起始长度的增量和本操作临时字节。

## 监测和退出

创建工作进程每个既有 I/O 检查点检查空间，捕获后及发布前再次强制核验。在线伴侣在捕获门闩外，为文件物化、provider prepare/materialize 及核心转换启动注入时钟驱动的监测，间隔四分之一秒；不依赖 provider 再次写 sink 才发现不足。metadata 查询在线程中执行；临时树每次最多处理 128 个文件属性，分批遍历，完成一轮后至少间隔一秒。不在业务提交门闩或 API 事件循环内遍历树。

空间风险沿现有协作取消路径结束本次捕获，SQLite backup 的 finally 关闭固定读视图，provider 的已有释放、迟到任务和关闭 sink 规则保持。不能杀伴侣、删旧包、缩短保留或变更系统权限。源/临时盘仍可能被其他进程消耗，因此状态明确标为 estimated=true、guaranteed=false；不宣称磁盘保证或普通预算涵盖整实例。

## 证据

每操作在 supervisor/backup-space 下保存独立原子证据，用现有跨进程锁串行合并观测峰值与故障；已经 blocked 的事实不会被另一个成功采样覆盖。状态投影仅给逻辑操作编号、各项估算/实测字节、卷标识、原因码与占用未知数，不返回源文件路径或异常原文。持久化失败如实传播，不能当作监测成功。所有验证使用虚构临时实例；真实 SQLite 并发写与暂停 fake provider 分别验证 WAL 触发、读视图释放及无需 sink 写入的取消。
