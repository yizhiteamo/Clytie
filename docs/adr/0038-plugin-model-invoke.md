# ADR 0038：插件自行调用模型的生产接线

状态：草案，随 runtime-services-spec §6 一起确认。

## 问题

`model.invoke` 权限早就定义了（"自行调用模型，计入额度"），但生产宿主只给记忆整理插件接了后端。那条路径会自动附加人设，审计记 `memory.recollect_model`。其他声明这项权限的插件会因为缺少后端而启动失败。

B9b 的 `news-feeds` 要用它判断一条新闻是不是值得马上告诉主人。请求里只有公开的标题、来源和摘要（content-spec §10.4）。

## 决定

1. 所有声明 `model.invoke` 的插件都装配生产后端，接口不变。
2. 记忆整理保留原来的回想模型路径和审计。
3. 其他插件走普通路径：
   - 用伴侣当前的模型和配置；
   - 请求原样交给模型，不附加人设、记忆和聊天记录；
   - 只接受文字消息，不能带工具和图片；
   - 最长 60 秒；同一个插件同时只能有一个调用，每分钟最多 10 次；
   - 保障模式下拒绝。
4. 审计记 `model.usage`，`purpose = plugin`，带插件 ID、插件给的用途代码、耗时和 token，不记内容。伴侣状态中按插件汇总。

## 不选的方案

- **普通路径也附加人设**：判断新闻不需要人设，附加了只会多花 token，还会把人设交给一个不需要它的请求。
- **给插件另选一个便宜的模型**：用户要求不悄悄换模型（AGENTS 3.2）；以后需要时，再由用户在配置里明确选择。
- **为新闻判断新增一种本体判断**（像 B7 的轻量判断那样）：要改 SDK，增加一种专用的判断类型。新闻判断不需要聊天上下文，用已有的 `model.invoke` 就够了。
- **设每天的调用上限**：用户 2026-11-15 撤回了工具每日额度。防故障用并发和每分钟次数就够了。

## 影响

- 新的审计用途 `purpose = plugin`。总用量的统计口径不变：`model.usage` 加上 `memory.recollect_model`。
- 以后任何插件声明 `model.invoke`，都按这条规则得到模型：插件只能发送自己拿得到的内容，结果只回到插件自己。
