# ADR 0040：一条消息放多张图

状态：草案，随 comic-spec 第 10 节（C2）一起确认。

## 问题

C1 真实检查时，两页漫画分成两条消息发出（2026-11-25）。agent-spec §3.5 规定工具结果的每个产物各作为一条独立的 intent。多页漫画、以后的组图都会被拆成好几条消息，读起来不连贯。用户希望合并。

## 决定

1. `ChannelFeatures` 新增 `max_images_per_message: int = 1`（至少 1）。平台插件声明一条消息最多能放几张图。
2. 同一个工具结果的图片产物，按顺序合并为尽量少的 intent：
   - 每条不超过 `max_images_per_message` 张；
   - 每条里图片的总大小不超过 `media_limits.image.max_bytes`，也就是单张图原来的上限；
   - 放不下时另起一条，顺序不变。
3. 不合并的情况：
   - 渠道没有声明（默认 1），和原来一样一张一条；
   - 不同工具结果的产物；
   - 图片以外的产物；
   - 文字回复和任务单，它们照旧各自成条，位置不变。
4. 合并后一条消息作为一个整体：一张收据；发送结果未知时整条不补发（kernel-spec 的原有规则）。
5. `qq-onebot` 声明支持，插件配置 `max_images_per_message`，默认 4，范围 1–9。多张图放在同一条消息的多个 `image` 段里，这是 OneBot 消息数组的标准写法。
6. 属于 SDK 0.21，都是新增。已有插件不用修改。

## 不选的方案

- **合并转发（聊天记录卡片）**：要点开才能看；只有 QQ 有，本体做不成通用规则。
- **拼成一张长图**：平台会压缩长图，台词看不清；也不能单独放大某一页。
- **由平台插件自己合并连续的图片**：每条 intent 有自己的收据和防重，插件合并会破坏账本的语义。
- **文字和图片放进同一条消息**：文字回复要经过回复形态和出站检查，可能拆成多条；放在一起会让这些规则变复杂。这次不做。

## 影响

- agent-spec §3.5：产物按上面的规则合并。
- sdk-spec：`ChannelFeatures.max_images_per_message`；SDK 0.21。
- 一条消息里的图片要么全部发出、要么全部没发，和漫画"一页失败就一页都不发"一致。
- 一条消息的数据量比原来大。总大小不超过单张图原来的上限，所以每次发给平台的数据量不会超过原来允许的最大值；部署后在测试群实测显示效果。
