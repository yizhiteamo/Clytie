# ADR 0045：群聊中由她决定引用哪条，@ 别人时显示身份

状态：草案（2026-11-29）。

## 问题

外部群用了一段时间后发现（用户 2026-11-29 反馈）：

- 她引用的消息由轻量判断在她写回复之前选定。主人连发两条时，她回的是第一条，引用的却是第二条。
- @ 别人在上下文中只显示 `[@某人]`（B3d）。说话人的标注却带有 `actor_id` 和昵称，所以她没法把被 @ 的人和说话的人对上。主人 @ 着向她介绍群友时，她不知道介绍的是谁。

## 决定

1. 群聊回复的上下文中，入站消息带稳定的序号。她在回复开头用 `[回复 #n]` 标出要回哪条，本体去掉标记，把 `ReplyDraft.focus` 换成那条消息。标记无效或没有时保持原来的 `focus`。规则见 chat-behavior-spec §11.1。
2. @ 其他人显示为 `[@<actor_id>（昵称：<昵称>）]`，和说话人标注一致，不显示平台账号。这改变了 B3d 中"不显示逻辑 ID"的规定：说话人标注本来就显示 `actor_id`，单独隐藏被 @ 的人没有保护作用，反而让她认不出人。
3. SDK 0.24：`MentionPart` 新增可选的 `display_name`，由平台插件填写，只用于显示。qq-onebot 用标准接口查群名片，带缓存和 1 秒时限。
4. 主人 @ 的群友在回想中算作出现过，印象可以记主人介绍的称呼和关系。

## 不选的方案

- **写完回复后再判断一次引用哪条**：每次需要引用都多一次模型调用，回复慢 3–5 秒。
- **只用账本中的昵称，不改 SDK**：主人介绍的人可能从没在群里说过话，账本里没有他的昵称。
- **把群成员名单放进上下文**：大群名单很长，大部分人她用不上。
- **显示平台账号**：账号不交给模型（agent-spec §4.4）。

## 影响

- chat-behavior-spec 新增 §11；agent-spec §4.4、sdk-spec、memory-recall-spec §3.1、qq-onebot 兼容契约 §8 同步修改。
- 新增字段有默认值，已有插件不用修改。
- 每次群聊回复的上下文多出约 300 个 token，不增加模型调用。@ 了没说过话的人时，qq-onebot 多一次成员查询。
