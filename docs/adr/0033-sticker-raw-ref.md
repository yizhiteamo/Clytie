# ADR 0033：表情包消息段的原始引用和说明

状态：用户已确认（2026-11-15，Issue #91）。

## 问题

qq-onebot 兼容契约要求把 `mface`（商城表情）映射为 sticker，保留原始数据，并在有说明文字时带上说明。现有 `StickerPart` 只有必填的 `sticker_id` 和可选的 `asset`，放不下原始数据和说明；`mface` 也没有标准规定的编号字段。

## 决定

1. `StickerPart` 增加两个可选字段，默认 `None`：
   - `raw_ref: str | None`：平台的原始引用，含义与 `MediaPart.raw_ref` 相同，只给平台插件自己解读；
   - `summary: str | None`：表情的说明文字，最多 100 字。
2. `sticker_id` 仍然必填。它是平台插件给出的稳定标识，同一个表情多次出现时应该相同。没有现成编号时，由插件从原始数据推导（qq-onebot 的规则见兼容契约第 3 节），不能留空，也不能编造含义。
3. 其他消息段不变。现有插件和数据不受影响。

## 不选的方案

- **把 `sticker_id` 改成可选**：已有的使用方会拿到空值，属于不兼容的改动。
- **把 `mface` 映射成 unknown**：会丢掉"这是一个表情"的信息，模型看不到说明。
- **把原始数据塞进 `sticker_id`**：标识和数据混在一起，长度不受控制。

## 影响

- sdk-spec §1.2 的 sticker 一行同步；SDK 次版本号升级。
- 账本、备份和资产引用的现有处理只看 `asset`，不需要修改。
