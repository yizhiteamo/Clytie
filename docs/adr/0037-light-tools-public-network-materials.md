# ADR 0037：轻量能力、只访问公网与资料保留

状态：草案，随 `content-spec.md` 一起确认。

## 问题

B9a 让她能搜索和读网页，碰到三个现有机制管不到的地方：

1. 每次能力调用都会把记录升级为任务，加任务表情、附任务单。查一下资料也这样，显得生硬。
2. 现有的 `network` 权限可以访问任何地址。读网页的网址来自别人发的链接，有人可以用一个指向本机或局域网的链接，让她去访问本机的服务，比如协议端和管理接口。
3. 工具结果只在本次工具循环中有效。读完一篇文章后被追问，她得重新读。conversation.md 很早就设计了"资料 15 分钟全文、之后摘要"，一直没有实现。

## 决定

1. 工具清单新增 `light`。轻量能力的调用不升级为任务，没有任务编号、任务状态回应和任务单；幂等、调用记录、审计和取消照常。轻量能力不能是 `heavy`，不能返回产物。
2. 新权限 `network.public`。宿主为它提供受限的 HTTP 后端：只访问公网地址，端口只能是 80 和 443，连接使用检查过的地址，每次重定向重新检查。不能和 `network` 同时声明。
3. `ToolResult` 新增可选的 `material`。资料存在原来的调用结果中，按记录的场景可见性投影；15 分钟内附全文，之后只附摘要行，可以用新的本体工具 `core_recall_material` 取回。资料前面写明它不是指令。
4. 以上属于 SDK 0.19，都是新增。

## 不选的方案

- **把搜索和读网页做成本体工具**：它们是可替换的能力，搜索服务也会换，按 AGENTS.md 应该是插件。
- **让插件自己检查网址**：每个插件都要写一遍，写错一个就有漏洞；放在宿主的 HTTP 后端里，插件绕不过去。
- **给所有 `network` 插件都加上公网限制**：模型和画图插件可能要连本机的代理或自建服务，会被误伤。只有按别人给的网址访问的插件才需要这个限制。
- **资料另建一张表**：调用结果本来就存在账本里，也已经有保留期和场景过滤，再存一份只会多一处需要清理。
- **用模型给旧资料写摘要**：每次组装上下文都要多一次调用；用标题加正文开头已经够认出是哪份资料，需要细节时可以取回全文。
- **资料自动写进记忆**：网页内容不是主人说的，按记忆规则不能当作事实记下。

## 影响

- SDK 0.19：`light`、`network.public`、`ToolResult.material`、`core_recall_material`。已有插件不用修改。
- kernel-spec：记录升级为任务的规则多了轻量能力的例外。
- runtime-services-spec：多了受限的 HTTP 后端。
- agent-spec：上下文多了资料一节；工具结果不再只在本次循环内有效。
