# ADR 0017：异盘副本仓库身份与可核验发布

状态：A4.3 规格 §7 的内部实现；整合验收待完成。

生产接纳复用备份配置的 plan/apply：启用副本或更换目录时，计划绑定副本目录核验结果，确认配置时先确认该候选，再保存配置。仅保存候选不声明副本更新成功；复制与校验完成才激活。目录使用实例根解析相对路径。配置写入失败不覆盖旧 active，也不授予清理历史副本的权限。查询分别报告配置、候选和已激活仓库。

镜像核心与主包创建分开返回结果，副本失败不撤销主包。调用方明确提供管理状态目录、主仓库、实例/恢复等禁止根、所有者随机身份和注入时钟。plan 只接纳已存在的目录，绑定 canonical 路径、目录文件身份、卷身份及物理设备身份集合；confirm 要求计划完全未变，再写随机仓库标识/所有权。目录非空且无本工具归属标记不接管。新候选不会覆盖旧 active 登记，全部指定最新组副本有校验回执后才激活；旧仓库转 history，不再清理或复制。

Windows 使用系统卷路径/GUID、卷磁盘 extent 和物理盘设备描述符串号，不按盘符判断；Linux 从 sysfs 设备拓扑追踪到物理祖先并取稳定 WWID/串号。设备集合相交就是同盘；缺少可靠身份、虚拟/无法解析的存储返回 mirror_device_unverified，不猜异盘。每次操作重新探测目录与设备，掉盘后出现同名普通目录不能匹配。测试正例使用显式 fake probe，不访问真实外设。

只接受上层标为 verified/complete 且通过源验证回调的加密主包；复制时必须持有上层提供的主包引用保护上下文。操作记录先写明确 source/target/temp、大小/哈希和阶段；分块复制与空间检查，逐块及发布前复核仓库身份。临时文件完成 fsync、长度与 SHA-256 核验后原子发布，再写明确回执。原有目标不可覆盖。回执只登记本仓库、本操作核验的目标，不复制密钥。

中断后仅核验 pending 中已经发布的明确目标；没有发布的临时文件不重复制、不重放请求，标 interrupted 并保留清理证据。目标内容不符为 recovery_blocked。发布但缺回执的有效文件可补回执，不把部分写入算成功。主源内容变化与副本失败分别记录，不公开任意异常原文。

发布使用 Windows 的 os.rename（目标已存在时必报错）或 Linux renameat2(RENAME_NOREPLACE)；系统/文件系统不支持时报 mirror_publish_unsupported，不回退到可能覆盖的 POSIX rename，也不依赖 FAT/exFAT 不支持的硬链接。发布前登记临时文件身份，恢复必须核对最终目标仍是该文件身份和哈希，不能接管未知同内容文件。依据：[Python os.rename](https://docs.python.org/3/library/os.html#os.rename)、[Linux renameat2](https://man7.org/linux/man-pages/man2/rename.2.html)。

重连选择每个 instance/memory 组最新有效 complete 包，不补全部历史；保留调用既有 plan_mirror_retention，只返回明确回执拥有且当前引用状态已核对的删除计划。核心不递归删除、不自动迁移历史仓库、不把主包淘汰同步到副本。

副本接纳后的源保护登记使用仓库内 `.clytie-repository.json`、索引与引用账本；复制发布同时登记目标身份，后续恢复管理 home 必须遵循同一权威引用。synchronize 先重新选择每组最新 complete、验证已有回执内容并去重，只补缺项后 activate；配置 path 不匹配已确认候选时不得向旧 active 静默写入。rotate 根据副本回执自身完成时间/manual 属性计算保留，即使主索引已轮转，也不丢副本历史；逐项持源仓库删除保护、重验身份/哈希、写删除意图、unlink 明确文件后移除索引。历史仓库从不进入该轮转。重连、复制和轮转失败仍只影响 mirror 轴。
