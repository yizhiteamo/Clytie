# ADR 0004：插件升级快照使用 cryptography AES-GCM

状态：已采纳（实现选型）

## 决定

使用 cryptography 的 AESGCM，实例密钥为库生成的 256 位密钥，每份快照使用系统安全随机数生成独立 96 位 nonce，保留完整认证标签。算法实现交给成熟库，不自行实现。依赖纳入 uv.lock。

密钥保存在用户确认的 secrets/backup.key，首次独占创建，以后不自动替换。首次生成通过结构化警告提示另存密钥，日志只带 SHA-256 指纹；两个备份 CLI 属于 A4。

## 理由和格式

[cryptography 的 AEAD 文档](https://cryptography.io/en/latest/hazmat/primitives/aead/)提供认证加密接口。格式版本、算法、指纹、伴侣/插件和版本元数据作为 AAD 验证，文件内容在内存中编码后整体加密。包内每个文件保留 SHA-256，解密后逐项校验；写快照后重新读取和比较，再允许迁移。格式中不包含密钥；解密失败不创建恢复输出。

采用 JSON/Base64 文件树而非通用压缩包解包，减少路径逃逸入口；拒绝符号链接和越界路径。恢复仅操作本插件目录，每个明确文件的删除均记录，写入使用原子替换。所有测试使用临时目录和测试密钥；Windows 密钥文件沿用用户目录 ACL，创建时同时指定仅用户读写的文件模式，不修改系统 ACL 或环境设置。
