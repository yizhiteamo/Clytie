# ADR 0029：合法测量夹具与固定版本适配

状态：按 Issue #72 用户批准的测量收敛规则实施；机制和正式性能结果尚待验证。

## 问题与决定

旧组件基准使用额外 benchmark_payload 表，不能通过生产完整恢复的结构检查。历史结果保留为诊断，不放宽恢复校验，也不用于新的性能通过判定。正式路径改用统一的 legal_memory_v1 虚构夹具，通过生产记忆保存入口建立当前记录、首条修订、内容指纹、关键词、审计与备份修订；不直接插入孤立的 records 行。

每条内容为固定种子的随机字节转为 ASCII 十六进制，长度四 KiB，记忆为 private fact，身份和编号均为手写虚构规则。各版本使用相同种子、逻辑内容与读取编号序列。原四规模保持：小文本库一百二十八条及八个小文件；大数据库三万二千七百六十八条及八个小文件；多小文件一百二十八条及两千零四十八个小文件；大资产一百二十八条及一个一百二十八 MiB 文件。小文件均一 KiB。大资产经本体登记并由 BackupView.assets 声明，其他文件由不可变快照提供者声明。

账本使用真实运行时创建的合法空业务状态，不添加新的账本负载；逐表记录实际数量。每次保存记录数、修订数、内容长度分布、文件与资产数量、实际记忆/账本数据库、资产和插件文件字节。数据库包含完整记录和修订等结构，文件大小不等于旧诊断表的有效载荷大小；差异必须报告，不能据此减少记录数。备份实际字节由运行结果记录，造数时不假称已经生成。

## 产品版本与测量工具分离

旧存储固定 05ec93c7c4ae972b7475911b0aec9db57bb00390，原备份固定 b40bbbc31cfb2ff012a151d0e0e9c79acf07d903。通过 git archive 提取到各自的新测试目录，保留归档哈希及逐文件清单；不修改旧生产文件、不切换开发分支。新进程只从指定产品树加载 clytie，子进程沿用同一产品导入路径，运行后再次核对源码清单和已加载模块。工具与夹具来自独立记录的当前工具版本，不混作旧生产源码。

旧版本保留事件循环中的同步读取及 admission/事务写入；原备份和候选保留各自 StorageOwner。三者都按同一编号读取完整记录，写同一元数据字段，完成后调用相同零延迟 FakeModel。计时从预定到达至模型返回，包括等待、实际读取、协调、提交和返回，不扣除观察开销。旧版本不通过工作线程优化。只读结果和写事务依然使用各版本原连接、线程检查及跨进程协调。

原备份使用其自身的捕获、工作进程、加密与恢复校验，不注入新预算协议；候选使用已批准的生产预算。微型入口固定八条记录和极小文件，仅检验适配与生命周期，拒绝把它称为正式规模验证。正式基线和矩阵需另外冻结运行计划，不能把微型回归结果换算成性能结论。

## 采样与证据格式

连接观察器必须在连接创建前安装，保留真正的 SQLite 提交/回滚、锁与 fsync 调用；已打开连接不能靠稍后替换 connect 得到提交证据。跨线程观察只记录固定阶段和数值，不记录 SQL 参数或正文。采样错误使本次证据不完整，不丢弃出错样本继续报告成功。

结构化运行清单升级为 format 2，明确候选、实际产品源提交、旧基线与原备份、夹具及工具哈希、固定执行顺序和预热、负载、逻辑/物理规模、有限环境字段。新增 baseline 臂单独对应用户批准的十二次补测预算；三臂仍各平台三十六次。版本一及加密容器版本一保持可读，不改写旧证据。文件仍是原五项白名单，原件的敏感值、路径和未知字段仍拒绝。

正式窗口、预算及顺序在合法性和采样机制验证后计算并冻结；实际文件布局差异、环境差异和所有失败都保留。语义或工作量不能等价时报告不具可比性，不拟合、不选择更有利基线。加密待核验、本机解密及私有扫描、正式审查一轮已用的状态不变。

## 构造与采样修正（正式测量前）

第一份四规模盘点在大数据库构造期中止，保留原目录及原因，不作为性能执行。逐条保存会按 record_id 删除旧关键词，现有生产关键词索引以 token 开头；新记录构造因此反复扫描增长中的表。legal_memory_v2 只在造数事务内增加 measurement_seed_lookup 辅助索引，继续调用各版本原保存入口，写完立即删除该索引，提交后 VACUUM 并 checkpoint。最终 Schema、逻辑数据、修订、关键词和权限不变；测量开始前没有辅助索引或该索引的空闲页。业务阶段不加索引、不修改旧算法、事务或持久性。三版本采用同一构造器，并单独记录实际布局字节。

新采样明确区分物理包字节与逻辑 I/O 计费；原备份没有新预算计费器，因此逻辑计费为未计量，不能以零值假称没有 I/O。备份阶段只读取既有日志的固定阶段枚举，未知或失败读取使采样失败。先记录进程身份再向资源采样线程发布该执行者；身份解析失败也必须关闭并等待已创建的测试子进程，不遗留未跟踪写入者。任意异常诊断仅保存在五文件白名单之外的本地诊断文件，不上传。

上述扩展使用运行清单 format 3，并绑定 legal_memory_v2。已保存的 format 2 微型记录仍按原资源字段核验，不回写其字节或结论；format 1 及 age 容器格式继续保持。正式入口仍需冻结完整计划后启用，微型回归和构造盘点不消耗正式基线、矩阵或独立审查轮次。

合法大库包含完整修订与索引，观察窗口按实际工作量计算。format 3 的每个白名单文件上限预先固定为二百五十六 MiB，每行仍十六 KiB，文件数量仍为五个；format 1/2 保留原六十四 MiB 限制。此项是采集器和封装器的有界容量，不是负载、性能或资源保证的放宽。达到上限仍使证据失败，不截掉样本、不自动扩大容量。缓冲的实际内存计入资源观测，窗口和原始字节预算必须在正式启动前检查。

后续批准允许非敏感计划独立入仓，完整边界见证据保存说明。计划提交不等于被测产品提交；工具/适配器也必须固定并检查实际库存。计划变化重新核验、双扫描并保留旧版本，不能以新文件或 runner 重置已消费的次数。负载、门槛、参数与总预算保持本 ADR 及已批准规格，不将原始几何/环境文件未经白名单提取整份上传。
