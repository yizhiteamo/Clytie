# ADR 0027：实例内备份重 I/O 调度

状态：实施中，未验收。产品参数以 backup-spec 的 Issue #72 有界调度章节为准；本 ADR 不修改已批准限额。

## 边界与执行者

守护进程持有实例唯一内存预算，工作进程及伴侣快照通过既有管道申请阶段和批次。一路执行、八个等待阶段共用就绪 FIFO；释放当前阶段后才能申请下一阶段。阶段编号与原操作/执行者身份绑定，重复传输不能重复收费或产生新执行者。工作进程失联时保持占用，待原进程身份与实际退出核验后释放；不能凭管道断开立即让第二个执行者进入。

StorageOwner 仅产生无内容压力快照。控制面以本地单调时点登记收到的信号，不能比较不同进程的单调时钟绝对值；业务等待/执行持续时间及收尾等待由拥有者计算。信号陈旧和无伴侣运行是不同状态，后者须控制面确认。调度等待使用注入 Clock 和可唤醒通知，不在业务队列、写事务或捕获门闩中等令牌。

256 KiB 是底层读写粒度，不是加密帧格式；同一原帧可通过多次底层读写处理。读、写分别收费，预算与突发在阶段切换时连续。同步工作线程只通过受跟踪的控制请求等待；既有管道的消息接收不能在等待 capture 回复时阻塞其他预算/取消消息。不得新增逐块锁文件或持久确认。

## 快照资源

本体资产存储使用内部读写回调接入备份预算，SDK 和普通工具 put/read 行为不变。插件 sink 只在一块数据就绪后进入阶段，写完释放再等待插件的下一块，避免占着槽位等外部生产者。容器以底层有界缓冲合并小帧，保持认证格式不变。离线数据库也通过相同 SQLite 批次函数，固定读事务仍属于本执行线程。

恢复预览、复制和提交前校验进入预算；原恢复发布边界内的必要校验、资产布局收尾及恢复不增加令牌等待。副本复制和发布前摘要使用预算，已发布副本的恢复核验沿用原协议。内部工具不通过全面修改 digest 或 FileCommands 来使业务提交/恢复意外依赖备份调度。容量拒绝与执行者失联保留固定错误码，未知异常原文不投影。

固定 WAL 读视图仍由原只读线程拥有。基准须包含每库 WAL 文件身份、WAL 头部代次信息及已观察高水位；文件截断、替换或代次变化不能简单用新长度减旧长度。每个新代次的增长累计，无法可靠核对的文件变化明确失败，不能将其当作零增长。检查要在批次及预算等待的可取消检查点进行，保留采样开销证据。

读视图自固定时起五分钟或新增 WAL 达到界限即请求协作取消；取消与已释放分别记录。不可抢占调用未返回时不强杀线程、不释放它仍持有的阶段。原必要发布/恢复提交不插入人为预算等待；重 I/O 阶段不能把整个操作错误地标为不可取消来绕过预算。

## 功能与证据前置

启动失败或取消后，StorageOwner 必须完成关闭结果交付并真实退出，才允许启动调用结束；不通过捕获事件循环关闭异常掩盖遗留线程。

测量原件、清单、代码/环境/参数及哈希与公开摘要分开保存。原件扫描失败不公开，不通过重编码或删字段规避扫描；CI 临时文件不视为归档。用户随后批准并修订的有限例外（CI 加密待核验、本机解密后私有扫描、十四天保留）单独记在 implementation/a4-3-evidence-retention.md。保存链路未验证前不得启动机制/性能验证；既有远端原件缺口不补造。

机制验证与正式矩阵分为两个阶段。机制有正确性/持久性/释放失败就停止；完整矩阵需冻结候选和计划后才执行一次。不得因普通提交自动反复执行矩阵。基于固定规模计算三臂相同请求计划与期限，超出时失败并保留结果，不延长窗口取绿。

## 原生数据库校验的明确例外（Issue #72，用户确认选项二）

SQLite 原生 integrity_check、quick_check 以及必要结构/引用检查保留；其内部读页不计字节令牌，观测值为未知，不是零。不使用文件大小预收费、回调次数推算或预读代替控制。可观察的数据流仍按原预算，不引入 VFS 或新绑定。

校验作用域在后台线程取得或复用实例阶段槽位，覆盖连接创建、完整检查和实际关闭；同线程嵌套不再次取槽。逐调用检查和 SQLite progress_handler 提供协作取消，回调只保存取消原因并中断，退出后恢复原异常，不将 SQLite 的中断转成成功。不可抢占调用结束及连接关闭之前不释放槽位。复制后校验复用同一执行线程，读视图及连接仍在该线程释放。

必要发布/恢复开始前安排阶段准入，已开始提交后的必要收尾保留原取消裁决，不增加字节令牌等待；恢复核验也必须持有同一共享槽位，不以恢复名义并行校验。连接不跨线程、不关闭线程检查；校验区间可被测量观察器记录，但不得采集 SQL 参数或内容。

阶段时间、取消受理与实际退出记录进入完整测量窗口；槽位证明和性能证明分开。真实数据库、实际创建/复制/恢复调用链须验证互斥、无嵌套死锁及失败不发布。所有既定参数、资源界限、性能门槛及正式运行次数不变。

## 管理操作串行交接（Issue #72，用户批准的限定补充）

此前同线程嵌套作用域不足以涵盖在线管理：产生恢复责任后，快照线程和 Owner 分属不同执行者；各自重新取槽会自等待，而 EOF 后才为恢复取槽又依赖已经失效的通道。因此增加仅供可信管理协调者使用的操作凭证，不替换调度器、权限或跨进程锁。

凭证在可退出的前置检查完成后、进入 materializing 前取得；准入由队列外文件执行者等待。宿主绑定实例、操作及执行身份，显式交给后续执行者；操作编号不是凭证。进程内状态以短临界区核验唯一借用者、执行身份和释放状态，不持短锁执行 I/O、不构造通用跨线程锁框架。

| 边界 | 资格及真实结束要求 |
|---|---|
| 前置检查到准入 | 尚未产生恢复责任；失败/取消退出，不能发布 materializing |
| 准备到快照 | 准备借用实际结束后交接；Owner 不持借用权等待捕获线程 |
| 快照到文件 | 等物化、校验及该执行者资源实际关闭后交接，不只等外层 Future |
| 文件到应用 | 文件借用结束后，Owner 在自身线程完成原事务，不在队列中等待取槽 |
| 应用到必要核验/恢复 | 原提交证据决定收尾；使用同一凭证，不因 EOF 重新准入 |
| 最终释放 | 所有借用者实际结束、资源关闭、必要收尾达原协议结果后释放 |

接收者开始前确认凭证与空闲借用状态；重叠/错配/过期/重复释放明确失败。交接空隙保有槽位，不自动转给其他操作。正常读写仍按原预算；必要收尾的无令牌等待作用域显式局限于既有提交或恢复，不借此让普通导入在 EOF 后继续。

控制通道断开时，必要收尾可在已获凭证内完成；释放回执丢失不伪称源端已空闲，协调者依实际执行者结束及原协议核验。旧进程被杀后不复活凭证；恢复使用原日志/提交证据及写锁，无第二写入者、无重放。不新增孤儿回收或强制抢占策略。不能满足现有生命周期时报告冲突。

先验证真实 MemoryAPI、快照、Owner 和进程边界，再进行已批准测量；凭证单测不是完整证据。原 bridge 三项超时和已有无效运行保持。该补充不改变原生 SQLite 内部字节未知的例外、测量门槛或正式审查一轮已用的状态。

启动核验不在 Owner 工厂里等待准入：父进程从本实例该伴侣的既有管理日志选择授权编号，新子进程会话只取得这些编号的调度授权。队列建立前的文件执行者在原管理门锁及运行锁内逐条核验旧执行者已退出，为每条日志取得新的执行凭证、完成原恢复、关闭连接并释放。不是复活旧凭证，也不是重新执行原业务。Owner 工厂仍在原门锁内作最终 pending 检查；中间出现新的管理操作就按原互斥失败处理，不能在工厂补取槽。没有实例控制通道的直接离线调用保持原语义，不以其测试替代真实父子进程的共享调度证明。

## 跨控制器重启准入（Issue #72，用户已确认）

此前仅内存预算不能覆盖父进程被杀后仍存活的执行者。按主规格增加实例级持久执行责任，不增加业务恢复系统。复用稳定文件的 OS 锁及原子写入；在同一短协调边界读取、核验、登记和解除。全部持久协调在后台执行，不持该锁等待业务或执行重 I/O。业务锁、数据库所有权、原日志及提交证据仍为原用途。

责任记录绑定实例、控制代次、执行代次、原操作和执行角色，身份为 PID 与 OS 创建身份；原业务执行与 recover_only 分开。登记在业务交付前完成；记录尚未完成的中间阶段按未知处理。发布记录后才能发执行授权，不能扫描一次后无保护授予。并发控制器在同一 OS 锁下判定，不因内存各自空闲同时通过。

可信完成须在实际收尾和视图释放后，并撤销本次执行的旧授权；墓碑不能随内存 endpoint 一并遗忘。可靠进程退出可结束活跃责任，但不改变数据恢复状态。终态、EOF、超时和心跳不作为解除证据。原生检查及必要恢复沿原凭证完成，重启只核验责任，不恢复凭证或重新执行。

新控制器及后续状态查询可重新核验全实例责任；未知/缺失/损坏阻止冲突重 I/O并保留证据。无关普通聊天仍按原锁/配置/恢复规则执行。具体持久布局与接线随实现记录，不能以局部辅助器测试代替真实 daemon HTTP 重启组合。旧诊断收尾错误、后续清理核验及原失败不覆盖；正式审查一轮已用，性能参数与次数不变。
