# ADR 0023：最小本体资产库与独立归属登记

状态：A4.3 实现草稿，依据已批准的 backup-spec §2.2a、Issue #69；尚未完成里程碑独立验收。

## 决定

本体提供 `AssetStore`，宿主按可信 companion_id 绑定现有 SDK 的 `assets.info/read/path` 和
`asset_writer.put`。生产 PluginHost 默认使用该后端，显式注入的测试后端仍覆盖默认值。
插件拿不到登记或共享方法。origin 仅为文字说明，不参与权限判定。不同伴侣写入相同内容
分别登记自己的元数据；物理去重不会扩大访问权。

### 格式和路径

- 新内容位于 `shared/assets/objects/<64位小写SHA-256>`，发布后设为只读。
- 临时写入位于 `shared/assets/pending/<随机标识>.pending`。
- `shared/assets/registry.json` 是单个原子替换的 JSON 文档，字段严格限定为
  `format: 1`、`revision: <32位随机十六进制标识>`、`registrations: [...]`。
  未创建登记时，进程内空快照的 revision 为 `0`。未知版本和非法结构拒绝加载。
- 每条登记包含 `companion_id`、`asset_id`、`size`、`media_type`、`origin`、`path`、
  `shared_with`（明确的伴侣 ID 数组）。每个 `(companion_id, asset_id)` 唯一。
  path 为规范化的实例相对 POSIX 路径；只允许上述固定对象路径，或
  `companions/<companion_id>/assets/` 内的明确私有文件。不读取包中历史绝对路径。
- 私有登记入口只接受已知明确文件，不发现旧文件，不移动到共享目录；私有文件缺失时
  拒绝访问，不尝试另一个伴侣或共享对象库内的同哈希文件。`path()` 只返回已只读的文件，
  私有文件仍可写时明确拒绝；登记入口不静默修改已有私有文件的权限。
- 同一可信调用者面对多个获授权来源时拒绝，即使字节相同也不按搜索顺序选择元数据。
  因而一个伴侣已经拥有同哈希登记时，另一来源向它共享也会被拒绝。大小写冲突路径、
  同一路径对应不同哈希、重复授权、越界、链接、reparse point 和多硬链接均被拒绝。

内部 `share(owner_id, asset_id, recipients)` 是明确登记授权入口，不属于 SDK。
本阶段没有自动共享、撤销共享界面、内容转换、GC 或旧素材扫描器。

### 写入与锁

内容发布及完整摘要核验在捕获门闩之外，在工作线程进行，不占用事件循环执行大文件 IO。
同哈希对象发布使用稳定 OS 锁 `shared/assets/object-<hash>.lock`。临时文件先写入并 fsync，
重新核验摘要，然后用同文件系统 `link` 的目标不存在语义原子发布，再逐个 unlink 自己的
临时路径并设置只读。最终文件只有一个硬链接；存在的同哈希对象先完整核验，绝不覆盖。
这次临时硬链接只用于原子不覆盖发布，不用于跨私有归属或恢复空间节省。

登记前先在门闩外核验最终文件（若当前已有私有登记，则核验该私有文件），固定文件身份。
短提交顺序为：伴侣 capture 门闩 → 全局 `shared/assets/registry.lock` → 登记的读改写。
只在此段核验登记未变与文件身份、生成新 revision、原子替换 JSON；不在门闩内复制或哈希
大内容。共享操作依序取得 owner 与新增接收者的伴侣门闩（ID 排序），再取全局登记锁。
锁复用现有跨进程 CaptureCoordinator/OS 锁，有界等待；内容锁不与捕获门闩嵌套。
并发注册不同伴侣在全局锁下合并，避免丢失更新；前置观察过期时明确报告变更，调用者可重试。

成功 AssetRef 仅在登记持久提交后返回。提交前强杀可能留下未引用对象或 pending 文件；
这些均在固定命名空间内可追踪，不自动删除、补登或重放。若强杀发生在临时 link/unlink
之间，双链接对象被拒绝而不是宣称可用。提交后、返回前强杀可留下有效登记，但没有虚构
已交付结果；账本继续执行自身的防重及结果未知规则。这里只保证进程强杀一致性，未声称
额外提供超出现有文件原子替换基础设施的断电/设备故障保证。

### 捕获和恢复接口

`snapshot()` 只读取完整原子登记版本，返回不可变 `AssetSnapshot`；不读取资产字节。
捕获者在对应伴侣门闩内调用 `resolve(snapshot, trusted_cid, asset_id)`，得到不可变
`ResolvedAsset(revision, companion_id, registration, path, identity)`；identity 包括
设备、inode、长度、mtime_ns、ctime_ns。它固定登记授权、实际路径和文件身份。

`iter_resolved`/`copy_resolved` 以 1 MiB 分块，核对打开句柄、路径前后身份、长度和 SHA-256；
`copy_resolved` 只创建不存在的目标并 fsync，可接受取消/预算 `check` 回调。读取过程失败
留下的目标仍属未完成成员，调用层不能发布为完整备份。`verify_resolved` 不累计字节，
`read_resolved` 才按现有 SDK 的 bytes 返回契约累计内容。所有读取都核验 resolved 的可信
伴侣授权。`check_identity` 为复制后/提交前的轻量身份复核，不替代完整摘要验证。

`AssetSnapshot.as_dict()` 与 `validate_registry(dict)` 是本体内部备份/恢复格式接口；
恢复层记录、逐文件写入和校验对象/私有路径，再按同格式恢复登记。包内内容去重不改变
多个合法目标路径需分别物化的要求；validate_registry 只验证格式/授权/路径，不能代替
恢复层核对内容、引用、捕获边界及 ready_for_switch 的全部条件。

## 验证范围

### 完整实例包映射

含资产的完整实例清单使用 schema_version 2；无资产清单继续使用版本 1，版本 1
不能夹带资产声明。版本 2 的 assets 按内容摘要去重，逐项保存唯一包内内容路径、长度、
摘要、合法 registrations 和引用该内容的伴侣集合。包中 registry.json 与清单的登记
集合必须完全一致。恢复先校验该集合、引用授权及内容，再向每个原登记路径分别写入，
不创建跨归属链接。预计空间计入包中未直接保存的每一个目标副本；所有目标字节和登记
核验后才继续原恢复状态机的 ready_for_switch 判定。中断产生的不完整目标不能视为完成。

配置依赖另存最终字段 Pointer、插件与角色、asset_id 和规范化 Schema 摘要，均受包的
认证保护。正常恢复重新从实际配置解析并比较完整依赖集合。只有既有凭据排除核验精确
通过、而缺项导致原 Schema 无法重新验证时，沿用认证清单内捕获时固定的依赖证明；仍
逐项核对 Schema 摘要、恢复后实际字段值和资产授权，不填充凭据、不猜测组合分支。
其他配置错误仍阻止恢复。不可变清单先转换为普通 JSON 值再计算规范摘要，冻结形式
不改变同一 Schema 的身份。

快照依赖由 BackupView 在 capture 固定深复制后的 AssetRef 值；materialize 完成后
重新验证类型与内容并和捕获值比较，变化按 provider_contract 拒绝。生产资产核验比较
登记元数据，不依赖插件提供的 origin 授权。配置、结构化账本和快照三类声明合并后才
核验与去重，不扫描普通文本或不透明句柄。

资产单测覆盖可信宿主绑定、相同哈希独立归属、明确共享、冲突拒绝、私有缺失不补齐、
损坏不覆盖、文件身份变化、软硬链接、流式末端验证、并发登记、真实插件上下文以及
测试子进程在登记提交前后被强杀的持久结果。备份加密包、空目录恢复和配置/插件资产
依赖的组合验收由备份集成测试提供，不由这些后端单测替代。
