# ADR 0041：平台离线提醒、不弹出的提醒种类和测试通知

状态：草案，随 supervisor-spec §5.3–5.6（B10）一起确认。

## 问题

QQ 在 NapCat 中掉线过两次，每次都是主人自己发现的，中间几个小时她的消息都发不出去。原因有两个：

- 协议端掉线时，平台状态是"离线"，不是 `auth_invalid`，守护进程不会提醒；
- 实例没有配置通知插件，所以守护进程已有的提醒也全部没有送达，日志里只有"通知未送达"。

## 决定

1. 守护进程按心跳中的平台状态计时。平台连续不在线满 15 分钟时提醒一次，种类为 `platform_offline`。一直没恢复时每 3 小时再提醒一次；恢复在线时清除冷却，不发恢复提醒。两个时长都可以配置。
2. `offline`、`connecting`、`unknown` 都算不在线。`auth_invalid` 已经有自己的提醒，不重复计入。只在伴侣运行中计时。两次心跳的间隔太长时（例如电脑睡眠）重新计时，避免误报。
3. 新增全局配置 `notify.mute`，列出不发送的提醒种类。`safety_belt` 不能写进来，因为群聊安全带每次触发都要提示。实例用它关掉 `backup_key` 的提醒，因为备份以后要重构。
4. 新增 `POST /supervisor/notify-test` 和 CLI `clytie supervisor notify-test`，通过已配置的通知插件发一条固定的测试通知。
5. `desktop-notifier` 默认改用 Windows PowerShell 已注册的应用标识，可以用 `app_id` 修改。
6. 不改 SDK。`notifier` 扩展点不变。

## 不选的方案

- **在 QQ 里提醒**：掉线的就是 QQ，提醒发不出去。
- **手机上的提醒（邮件、推送）**：消息会离开本机，要另外的账号和凭据，以后单独做。
- **用"确认已保管密钥"的命令消除备份提醒**：主人并没有另存密钥，用它等于记下一件没发生的事。
- **把全局冷却改成 3 小时**：其他提醒不需要这么频繁，只给平台离线用单独的间隔。
- **注册自定义应用标识（创建开始菜单快捷方式）**：要在系统里安装东西。先用 PowerShell 已注册的标识。
- **模型调用失败也提醒**：平台通着时，她会在聊天里回失败回应，主人能看到。

## 影响

- supervisor-spec §5.3–5.6、§9、§10；config-spec 的 `notify` 字段；api-spec 新增一个接口和一条 CLI 命令。
- 提醒由本机发出。电脑关机、睡眠，或者守护进程自己没有运行时，没有提醒。
- 第一次真正弹出桌面通知前需要用户同意（supervisor-spec §5.1），部署时用测试通知完成。
