# 公开仓库的内容规则

本仓库会公开。原则：**仓库里只放通用框架**，任何具体部署的信息（伴侣的名字、人设、号码、聊天、记忆、旧系统细节）都不进入仓库，包括提交说明、PR 和 Issues。

## 1. 进入 git

| 路径 | 内容 |
|---|---|
| `AGENTS.md`、`README.md`、`LICENSE` | 协作约定、项目说明、许可证（MIT） |
| `docs/` | 通用设计文档和 ADR，只用逻辑名称 |
| `src/clytie/` | 本体代码 |
| `plugins/<id>/` | 官方插件：清单、代码、测试、README、公开静态数据、升级脚本 |
| `schemas/` | JSON Schema |
| `tests/` | 测试和手写的假数据夹具 |
| `examples/home/` | 虚构的示例实例目录（虚构伴侣、虚构人设、假号码） |
| `scripts/` | 开发检查脚本 |
| `deployments/` | 外部组件的 Docker 模板，只有 `compose.yaml` 和 `.env.example` |
| `pyproject.toml`、依赖锁文件、`.gitignore`、`.gitattributes`、`.pre-commit-config.yaml`、`.github/` | 工程配置 |

## 2. 不进入 git

| 类别 | 放在哪里 |
|---|---|
| 实例目录的一切（配置、账号映射、凭据、人设、记忆、账本、资产、备份、导出） | `CLYTIE_HOME` |
| 部署专属的规则和文档（`AGENTS.local.md`、私有设计说明、旧系统迁移记录） | `CLYTIE_HOME` |
| 聊天记录、截图、录制的真实事件 | 不保存到仓库 |
| 模型文件、缓存 | 实例目录或系统缓存 |
| `.venv/`、`__pycache__/`、各类缓存、日志、临时文件 | 本机 |

`.gitignore` 覆盖以上类别，并默认忽略数据库、压缩包、音视频、模型权重扩展名；确实需要提交的文件单独加白名单。

## 3. 测试数据和示例

- 只用手写的假数据：虚构的伴侣、虚构的昵称和对话、明显虚构的号码段（在 `tests/README.md` 中说明）。
- 不允许把真实内容"脱敏"后放入仓库；需要真实格式时按格式手写。
- 设计问题的回归测试用改写过的句子，只保留触发问题的结构。

## 4. 自动检查

- **pre-commit**：密钥扫描；疑似账号号码扫描（按格式匹配，日期、版本号、哈希可加白名单）；禁止提交被忽略类别的扩展名；单文件大小上限（例如 1 MB）。
- **本机私有扫描**：pre-commit 额外读取 `CLYTIE_HOME/private-denylist.txt`（真实名字、号码、称呼等），命中就拒绝提交。这份名单只在本机，CI 中没有，所以必须安装 pre-commit。
- **CI**：通用扫描 + ruff + pytest。
- 仓库中不保存任何真实值作为黑名单。

本次 A4.3 的结构化虚构测量证据另有用户明确批准的有限保存例外：CI 在来源、白名单、固定 Schema 和通用扫描检查后，仅封装密文至仍为 PRIVATE 的仓库 artifact，状态为“加密待核验”；本机解密、身份/哈希核验及私有扫描完成后才能用于验收。名单和解密私钥仍只在本机，不进入 CI、Secrets 或 artifact。此例外不适用于源码、文档、评论和审查报告，不修改通用规则；完整边界与状态见 [本轮证据保存说明](../implementation/a4-3-evidence-retention.md)。

## 5. 误提交的处理

1. 立即停止推送，报告用户。
2. 涉及凭据时，先让凭据失效。
3. 是否改写历史由用户决定；GPT 不自行强制推送。
4. 仓库转为公开之前，由用户确认一次完整的历史扫描结果，以及所有 PR 和 Issue 的正文与评论的扫描结果。

## 6. 提交身份

提交使用 GitHub noreply 邮箱。

完整历史扫描仅对名称精确为 `GitHub`、邮箱本地部分精确为 `noreply` 且域名精确为 `github.com` 的官方提交者，豁免其提交者邮箱字段的通用个人邮箱告警。匹配区分大小写；作者、提交说明、文件内容和路径照常检查，私有名单扫描不豁免。
