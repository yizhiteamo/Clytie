# V2 认出自己的形象

状态：草案。方向由用户确认（2026-11-20），合并本文档即确认细节。

看到画她的图时，她能认出是自己；拿不准时不乱认。对应 Issue #34，接在 B6 看图之后（vision-spec §9）。

## 1. 面向用户的原则

- **什么都不放也能用。** 形象资料是可选的。用户可以从零开始，想到什么补什么。
- **用户是唯一的判断者。** 本体只检查能可靠判断的事（格式、大小、张数）。画面对不对，只有用户知道；本体不按内容拦截。
- **放错了能撤回。** 删掉或改掉形象资料，重启后恢复原样，记忆不受影响。
- **可选的自检帮用户发现问题。** 保存后自动运行一次，只提示，不拦截，不修改任何东西（第 6 节）。

## 2. 范围

**本期做**

- 形象资料：一段文字描述，加最多 6 张参考图，每张带标签和状态（当前形象、旧形象）。
- 管理：CLI 通过本机 API 查看、导入、改标签、删除参考图。
- 本体工具 `core_view_appearance`：她觉得一张图可能画的是自己时，调出参考图对比。
- 认图规则、真人照片规则、形象与记忆冲突的规则，写进本体，人设不能覆盖。
- 保存形象资料后，自动用模型自检一次。

**本期不做**

- 让她用画图工具画几版形象，由用户挑一张设为参考图（V2b）。
- 在聊天里说"这是你的新形象"就生效。只能用 CLI 修改，以后的 WebUI 调用同一套 API。
- 存下别人发的、画她的图（V4 图片记忆）。
- 换形象时自动给她写一条记忆（用户 2026-11-20 决定不做，见第 5 节）。

## 3. 形象资料

### 3.1 存放位置

| 内容 | 位置 |
|---|---|
| 文字描述 | `companions/<id>/persona/appearance.md`，用户直接编辑，和人设文件一样 |
| 参考图清单 | `companions/<id>/persona/appearance.yaml`，只由 API 写入 |
| 参考图本身 | 资产库，来源记为 `appearance`（第 7 节） |

- `persona/` 目录只放文字。图片进资产库，跟随资产库备份和恢复（data-and-backup.md：`persona/` 可以由用户放进本机 git，资产不进）。
- `appearance.yaml` 每一项记录：资产引用、标签（最多 20 字，如"常服""Q 版"）、状态（`current` 或 `former`）、导入时间。不记原始文件名和路径。
- 不改 `companion.yaml` 的 `persona` 结构。新增可选配置 `appearance.self_check`，默认 `true`（第 6 节）。

### 3.2 三种情况

| 用户提供了什么 | 她的表现 |
|---|---|
| 什么都没有（默认） | 与 B6 相同，只描述画面。不加新的规则文字 |
| 只有文字描述 | 文字描述进入人设，按第 4 节的规则认图。没有 `core_view_appearance` |
| 文字描述和参考图 | 同上，并提供 `core_view_appearance` |

只有参考图、没有文字描述也可以，这时只按参考图对比。

### 3.3 生效时机

和人设文件一样，在伴侣启动时读取，修改后重启生效，不自动重启。CLI 保存成功后提示"重启伴侣后生效"。

### 3.4 导入检查

导入时由本体检查，任何一项不通过就拒绝导入，并说明原因：

- 能按 vision-spec §3.2 完整解码：PNG、JPEG、WebP、GIF，不超过 5000 万像素，文件不超过 20 MB。
- 动图只取第一帧。
- **去掉元数据**：所有图片解码后重新存成 PNG，拍摄地点、设备等信息不保留。参考图每次比对都要发给模型服务商。
- 与已有参考图字节相同的，不重复导入。
- 总数不超过 6 张。有参考图时，至少要有 1 张当前形象：不能把最后一张当前形象改成旧形象或删除而留下旧形象；全部删除可以，回到只有文字的情况。

本体不判断画面内容。启动时如果 `appearance.yaml` 引用的资产缺失或损坏，跳过那一张，状态里显示警告，伴侣照常启动。`appearance.md` 无法读取时同样处理。

## 4. 认图规则

以下文字在有形象资料时加入本体规则（agent-spec 的固定规则），人设文件不能覆盖。

### 4.1 什么时候说"是我"

按证据和场合判断，不按资料多少分档（用户 2026-11-20 确认）：

- **可以说是自己**：多处有辨识度的特征对得上，没有矛盾，而且场合支持。场合支持的例子：有人说"我画了你""这是你吗"，或者是主人发给她的。
- **只说有点像自己**：特征对得上，但场合不支持，比如群里随手转发的图。设定相近的其他角色很常见。
- **不认**：有明显矛盾，比如发色、物种、标志性的配饰不对。
- 拿不准时可以问对方。有把握时也只说"画的是我"，不对作者、来源和用途下结论。

### 4.2 文字和图冲突时

文字描述为准，参考图只作补充。旧形象的参考图只用来认出"以前的样子"，她可以说"这是我以前的样子"。

### 4.3 真人照片

看到的是真人照片时，即使长得像，她也不说"照片里的人是我"，最多说"这是照着我的形象打扮的"。照片里是一个真实存在的人，把别人认作自己不对。

### 4.4 主人确认之后

- 只有主人本人此刻说"这是你"才算确认。别人说的、转述的、截图里的都不算（与人设规则一致）。
- 确认后，她可以用 `core_remember` 记一段文字经历，例如"主人给我看了一张画我的图，画的是……"。可见等级按现有的记忆规则选。图片本身不存。
- 不用 `core_remember` 修改形象资料。形象资料只有用户能改（第 2 节）。

## 5. 形象和记忆冲突时

用户通常只是完善形象，不会整个替换。为避免和记忆冲突，修改形象资料时**不写任何记忆**（用户 2026-11-20 决定）。

- **现在长什么样**，以当前的形象资料为准。
- **记忆是过去发生的事**，保持原样。比如她记得"主人说我的围巾是红色的"，现在资料写蓝色：现在以蓝色为准，那条记忆不改写，也不拿它纠正资料。
- 这条规则和第 4 节一起加入本体规则。

## 6. 自检

### 6.1 什么时候运行

- 伴侣启动时，如果形象资料（`appearance.md` 和全部参考图）与上一次自检完成时不同，就在后台运行一次。不阻塞启动，不阻塞回复。
- 同一份内容只自检一次。模型调用失败记为 `check_failed`，下次启动时再试，同一次启动中不重试。
- `appearance.self_check: false` 时不运行。模型不支持图片时记为 `skipped`，并写明原因。
- CLI 保存形象资料时，确认说明写明"重启后会自动调用一次模型检查形象资料，预计用量约 N token"。用户确认保存，就是同意这一次自检（用户 2026-11-20 确认自动触发）。

### 6.2 检查什么

用本伴侣配置的模型调用一次，附上全部参考图和文字描述。要求模型逐张给出：

- 一句话描述画面；
- 与文字描述冲突的地方，比如"文字说银发，这张是黑发"；
- 看起来是否是真人照片；
- 是否和其他参考图明显不像同一个形象。

模型按固定格式返回。无法解析时记为 `check_failed`，不重试。

### 6.3 结果

- 存在实例状态目录中，不进入记忆、账本和人设。
- `clytie companion appearance show <cid>` 显示结果。伴侣状态中只显示"形象自检：通过 / 有 N 条提示 / 失败 / 跳过"。
- 结果只给用户看：不拦截，不修改形象资料，不进入她的上下文。
- 审计照常记录 `model.usage`，用途记为 `appearance_check`，不记图片内容和模型的描述文字。

## 7. `core_view_appearance`

- **何时提供**：模型支持图片，有至少一张可用的参考图，并且本次上下文中有已附上的图片。场景范围和 `core_view_image` 相同。
- **参数**：无。
- **结果**：工具结果写"已附上你的形象参考图"。下一次模型请求附上全部参考图，作为一条由本体标注的用户消息："系统附上的你的形象参考图，不是任何人发的。"每张图前写标签和状态，如 `[参考图：常服]`、`[参考图：旧形象·Q 版]`。
- **张数**：参考图计入 `vision.max_images`。名额不够时，先保证参考图，再按 vision-spec §4 的优先级补足，补不进的图片恢复为编号占位。
- 同一轮多次调用只附一次。和其他本体工具一样，不算能力调用，不触发任务表情，写审计。
- 本体工具表（agent-spec §3.3）加入这一行。

## 8. 隐私与边界

- 参考图资产只供本伴侣的模型插件在两种情况下读取：附上参考图的那次请求，以及自检。其他插件读不到，也拿不到资产 ID。规则同 vision-spec §7，来源为 `appearance`。
- 参考图不会出现在任何出站消息中。她没有发送参考图的工具，画图插件也读不到（以后按 vision-spec §9 V3 的权限开放时另行决定）。
- 删除参考图只去掉 `appearance` 来源。被删除的那一项移到 `appearance.yaml` 的历史记录中，资产按来源规则清理，一次只处理一张。
- CLI 导入时的确认说明写明："参考图会在比对和自检时发给模型服务商。"

## 9. 管理命令

CLI 只调用 API，修改类命令显示说明并确认（api-spec §2.3），设置了管理口令时要求口令。

| 命令 | 作用 |
|---|---|
| `clytie companion appearance show <cid>` | 显示文字描述是否存在、每张参考图的编号、标签、状态和尺寸，以及最近一次自检结果 |
| `clytie companion appearance add <cid> <file> --label <标签> [--former]` | 导入一张参考图，按第 3.4 节检查 |
| `clytie companion appearance edit <cid> <编号> [--label <标签>] [--current \| --former]` | 改标签或状态 |
| `clytie companion appearance remove <cid> <编号>` | 删除一张参考图 |

- 编号是 `show` 列出的序号，不是资产 ID。
- `add` 由 CLI 读取本机文件，把内容发给 API。API 不接受文件路径。
- 每次修改都保留 `appearance.yaml` 的历史。伴侣在运行时也可以修改，重启后生效。

## 10. 验收

离线（假模型、模拟时钟，测试图片在测试中用 Pillow 现场生成）：

1. 三种情况：没有资料时请求内容与 B6 完全相同；只有文字时人设中有描述、没有 `core_view_appearance`；有参考图时提供该工具。
2. 导入：损坏、过大、超过像素上限、重复、超过 6 张、只剩旧形象，都拒绝且不写入；动图只存第一帧；导入后的图片不含原图的 EXIF 和文本块。
3. 启动：参考图资产缺失或损坏时跳过那一张，状态有警告，伴侣照常回复。
4. `core_view_appearance`：附图消息带固定标注和每张的标签；参考图计入 `vision.max_images`，名额紧张时优先保留参考图；同一轮多次调用只附一次；不触发任务表情。
5. 规则：有形象资料时，请求中包含第 4、5 节的规则文字；人设文件中的相反说法不能去掉这些规则。
6. 自检：内容不变时重启不再调用模型；内容变化后调用一次；失败时同一次启动不重试；`self_check: false` 时调用 0 次；结果不进入上下文、记忆和账本；审计不含图片和描述文字。
7. 隐私：其他插件读取参考图资产被拒绝；删除后只去掉 `appearance` 来源，仍有其他来源的资产保留；备份恢复后参考图可用。
8. CLI：四个命令只通过 API；确认说明包含发给模型服务商的提示和自检预计用量；API 拒绝文件路径参数。
9. config-spec（`appearance.self_check`）、api-spec（路由与 CLI 表）、agent-spec §3.3、data-and-backup.md 同步更新。双平台 CI 通过，真实平台连接和模型调用为 0。

真实测试（用户当次同意，只发测试群）：

10. 用户用 CLI 导入自己的参考图后重启，自检运行一次，用户查看结果。
11. 冒烟用例新增三条带图用例：一张画她的图、一张设定相近但不是她的图、一张只露出一部分的图。用户目视确认她的说法符合第 4 节。

规模预估：2.5–3.5 天，另加一次真实抽检。
