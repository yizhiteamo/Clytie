# A4.3 备份与维护实现规格

状态：设计审查会话根据用户已确认方向起草；尚未实现、未经验收。日期：2026-11-07。
本文件是 A4.3 的实施依据。用户确认的产品决定见 §0；为使契约可实现而选定的字段、协议和工程默认值在本文明列，不声称用户逐项指定了这些技术细节。若实现检查发现会改变产品行为、权限、公共契约或一致性保证的冲突，登记 Issue 后交设计审查会话与用户，不自行降低保证。

## 0. 已批准方向与范围

1. 在线备份不停止伴侣、不重启插件、不停用平台、不切换为全部静默。允许有界的短暂写入协调；不承诺资源消耗或延迟影响为零。不得直接复制运行中的任意目录就宣称一致。
2. 平时自动生成记忆备份、每日完整实例备份；时间、周期、合并窗口、份数和容量均可配置。默认值见 §3、§6。3 GiB 是用户举例，不是指定默认值；本规格选择 20 GiB 为常规自动备份目标容量，不预分配空间。
3. 容量是滚动目标：原有备份未超额时允许新备份使其超额；下一次成功备份后淘汰最早的可删除备份。先新建、校验，再删旧；不能截断单包，不因达到目标就停止正常备份。保护底线和磁盘真正不足例外见 §6。
4. 完整恢复写入新目标目录；校验后用户明确切换，不覆盖当前实例、不自动上线。直接恢复到最终目录，切换不再复制整套数据。
5. 长期目标、计划与检查点保留；只允许核验后的安全接续，不能重放结果未知的外部操作。完整实例恢复的回想进度例外见 §9；记忆导出包原规则不变。
6. 普通关窗允许必要后台收尾，不固定等待，不为副本离线无限阻止退出。强杀后核验记录，不重做原请求；沿用 A4.2 已批准的停止边界。
7. 备份失败不自动停止正常聊天；前置快照失败仍拒绝迁移、导入等危险修改。实际业务数据库写入失败按原故障规则处理，不能伪装正常。
8. 凭据、登录态和实例备份密钥不进包；主程序、模型权重、可重建缓存不重复归档；实例安装的插件代码、必要媒体与状态纳入。采用无损压缩，不减少记忆修订、不降低媒体质量。
9. 日常忘记不等于清除历史备份；保留修订与撤销状态。恢复旧点可能回到后来撤销之前，计划必须提示。
10. 本地甲为主，乙是可选副本，不能用乙替代甲。更换乙不自动搬完历史或清空旧乙；新乙先复制并校验最新有效备份。密钥不复制。
11. 不支持在线快照的插件使结果成为部分备份，不自动停插件，不替代完整恢复点。安装、启用、status 显示支持情况。
12. 已登记旧实例的数量、占用和清理入口持续可见；切换后通知，下一次恢复前再次展示。默认不自动删除旧实例，清理必须计划、确认并逐项核验。
13. 容量淘汰优先于每日/每周/每月期望保留，但不能突破最低有效恢复点和恢复引用保护。特殊迁移快照、失败现场、手动导出、旧实例单独管理，不被普通预算顺手删除。

范围：在线一致快照、自动调度、校验、轮转、副本、完整恢复与切换交接、旧实例登记、密钥 CLI、日志轮转、API 与状态。复用 A4.2 管理工作进程/操作日志等基础设施，不能另建绕开现有鉴权、锁与停止契约的业务通路。
不包含：真实部署迁移、云存储服务接入、WebUI 实现、自动安装模型/插件依赖、任意任务自动续跑、跨备份增量链/块级去重、彻底清除历史记忆、自动清空旧实例、密钥自动轮换。Issue #59 的严格隔离仍未完成，旧入口停用；Issue #63 不因本里程碑测试通过自动关闭。

## 1. 产物与职责

| 产物 | 用途与范围 | 密钥与恢复语义 |
|---|---|---|
| memory 备份 | 单伴侣完整记忆状态；保留修订、撤销、来源、淡化和必要资产 | 实例备份密钥；只能作为记忆恢复来源，不代表账本/整实例受保护 |
| instance 备份 | 配置、人设、所有配置内伴侣、记忆、账本、插件持久状态、必要资产、守护持久状态 | 实例备份密钥；重建新目录中的一致实例 |
| partial 备份 | 一次 instance 尝试中得到的明确覆盖集合，附缺项与原因 | 可核验/保留，不能作为完整实例恢复入口或满足完整备份成功时间 |
| .clytie-memory 导出包 | 原 A3.3/A3.4 用户主动携带或合并记忆 | 原口令/恢复码；原 UID、修订/冲突、撤销导入规则不变 |
| 特殊快照/失败现场 | 升级、迁移、导入的前置保护及诊断 | 各自既有规则，不计入常规自动备份目标 |

本里程碑 memory 备份通过 §8.5 的备份源适配器复用现有记忆导入计划、合并、修订及撤销逻辑，不新增第二套合并算法，不绕过 UID/预览/确认规则直接覆盖活动库。instance 恢复仍是新目录重建，不通过逐个调用 memory restore 拼装。
完整实例备份中已经包含的同一时点记忆不另生成重复事件包；只有能证明覆盖了待备份的记忆版本时才清除对应脏标记。跨包不依赖去重链，每个有效包可独立解密校验。

## 2. 内容与目录

常规文件位于 `backups/regular/<backup_id>.clytie-backup`，副本复制同一加密文件。备份索引、最新回执和操作记录原子写入；`backups/latest.json` 保持可供 status 使用，不能只保留一个混淆所有类别的成功时间。
首次启用备份时，在实例锁内独占生成持久 `instance_id`（随机 UUID），保存在 supervisor 的备份登记元数据中；不是账号身份，也不替代 companion_uid。包保留 source_instance_id，恢复目标生成不同的运行实例标识并记录来源。索引区分来源实例和运行实例，不能因为复制了旧清单就获得旧路径的管理权。

### 2.1 纳入

- 实例配置、部署文档、人设、配置历史、伴侣 UID 与持久身份；声明的配置字段中凭据仅保留引用，不携带实际值。
- memory 的事实、全部修订、记忆审计、撤销、来源登记、淡化；instance 另外包含账本和相互匹配的回想进度。
- 账本的任务状态、交付回执、防重、取消与历史审计；待处理不等于恢复后执行授权。
- 插件代码（实例安装目录内）、插件清单/版本/数据版本/可用性与卸载状态、插件声明的持久状态。主仓库插件记录代码版本与校验，不复制整个主仓库。
- 已解析出的必要共享资产与伴侣资产，只复制授权实例内的明确文件；内容相同的资产在同一包内只存一份。缺少必要资产列为缺项，不悄悄删引用。
- `supervisor/silence.json`、通知冷却和审计；A4.2 已完成管理操作的历史证据。活跃或恢复受阻的管理/迁移操作按 §4 处理，不能导入活跃的旧执行者身份。
- 备份/恢复来源标识、切换与旧实例登记的可迁移摘要。来源机器绝对路径是待核实说明，不能成为新机器自动删除授权。

### 2.2 排除与依赖说明

- `secrets/`、API 通行证、登录会话、实际凭据、密钥、私有扫描名单、进程锁/PID、`run/` 临时状态。
- 已有备份、副本、导出包、故障目录、旧实例，不递归套娃；活动恢复依赖不能仅因排除而消失，存在时不能产出完整 instance 包。
- Git 元数据、虚拟环境、模型权重、向量/其他可重建缓存、普通运行日志。记录必要模型/插件/依赖版本和重建要求，不自动联网补齐。
- 显式拒绝越界、符号链接/reparse point、路径穿越、大小写冲突、重复成员名及未知归档对象；配置指向实例外的资产列为缺项，不能借备份任意读取外部目录。
- 配置中的声明式 secret 字段或内联凭据必须通过 Schema/插件元数据识别并排除实际值，清单列出恢复时待重新配置项。不能以正则扫描通过证明任意文件无秘密；插件不得将凭据混入可备份状态。不透明配置/状态无法安全区分时列为缺项。
- 不纳入凭据属于明确排除，不因此把其他完整数据一律标 partial；恢复就绪状态必须另列凭据缺失。

### 2.3 包与校验

包头只含必要格式版本、随机包标识、算法及密钥指纹；详细路径、账号映射、内容清单、状态摘要在认证加密范围内。清单含 scope、组件版本、备份边界/时间、完整性分类、缺项、每文件原始长度与哈希、恢复依赖、代码版本。
复用成熟加密库和 ADR 0004 的实例密钥，不直接照搬整体 JSON/Base64 内存封装处理大包。使用流式无损压缩和有界内存的认证加密容器，格式/分块认证与截断保护写 ADR；必须验证整体清单与成员完整性，不能让分块校验掩盖缺块、重排或尾部缺失。旧快照格式仍可读，不静默改旧包。
先写本次独占临时文件 → 完成认证 → 解密到受控临时区域 → 校验哈希、数据库结构/完整性、组件关联 → 原子发布 → 持久登记有效结果。发布与登记间崩溃靠操作记录核验，不能重复生成或误报失败。错误密钥/损坏包不产出可使用的恢复目录。
校验分开显示：文件已发布、内容校验通过、结构/关联校验通过；不把未进行的完整恢复演练说成通过。真实恢复不启动任何平台或模型来验证。

## 3. 自动调度与触发

- 默认开启；memory 第一笔已提交的重要修改后 5 分钟内触发，期间合并。持续修改不能重置首笔计时而无限延后。重要修改含事实/修订/撤销/导入/人工恢复；纯检索计数、派生向量与频繁淡化维护不每次触发。
- 默认每日实例时区 `03:00` 执行 instance；也可配置每周指定星期。与现有时间/时区校验一致。夏令时重复时段只执行一次，缺失时段在当日下一个有效时刻执行；按计划日期持久防重。
- 未运行错过的计划，下次正常 ready 后补当前快照一次，不生成伪历史。默认启用 catch_up。维护模式不自动触发备份。
- 同实例一次只执行一个常规备份；同类新请求合并为一个待执行标记。一次 instance 成功若覆盖某伴侣的脏版本，则满足其待执行 memory；没覆盖的继续待执行。partial 不清除缺项组件的脏标记。
- 每日备份即使没有变化仍可保留当天恢复点；事件备份没有新变化不重复生成。主备份失败按 10、30、60 分钟退避，最多本触发三次；之后等待下一计划、实际新修改或人工请求，不紧循环。退避/结果持久化，重启不重置失败风暴。
- 静默不停止内部备份，通知仍服从 A4.1 outward 规则。备份不调用产品模型。
- 用户主动请求有稳定操作编号；响应丢失查编号，不换编号重发。自动触发也有持久去重键。用户明确要求额外创建的备份默认分类 manual，不被自动轮转；占用单列并提示。

## 4. 在线一致性与插件契约

### 4.1 本体协调

协调器准备 → 取得可证明的组件快照边界 → 释放业务协调 → 后台复制/压缩/加密/校验。SQLite 使用独立连接/事务和在线快照能力，不直接复制活动 db/wal 文件，不在 API/聊天事件循环执行大文件同步处理。
单数据库一致不足以证明完整实例一致。实现 ADR 必须列出逻辑一致性组：至少 memory 与其回想进度/所引用账本、插件状态与其版本/清单/配置、管理提交证据与对应数据、资产引用与内容。为组建立共同捕获边界或可核验版本链；不能拿各自不同时刻的有效文件冒充同一组快照。
跨组可以记录不同捕获时间，不承诺整个世界在同一微秒冻结；组间有引用的也必须核验。外部消息送达事实不可能靠本地快照倒退，恢复按 §9。
本体采用跨进程协调捕获与短暂提交门闩，固定锁顺序；捕获前等待组内正在提交的逻辑操作到安全边界，固定数据库读视图/文件版本后立即释放。长时间拷贝、加密、校验不得持有业务提交门闩。每次捕获门闩持有工程默认上限 250 毫秒、等待上限 2 秒；超时放弃本次捕获并释放，不能为凑成功延长聊天阻塞。已持有的 SQLite 视图/不可变文件持续有效至物化完成，之后释放；不得先释放再读取活动文件。
迁移、restore/apply、版本升级、配置切换等跨组件变更与该捕获边界互斥；不能调用危险操作的恢复入口来取得备份。遇到正在迁移或恢复受阻，标记组件 unavailable，本次为 partial/failed，原运行/恢复规则不变。
备份最多单工作进程、分批 I/O、可取消，忙时让步；不承诺固定耗时。若固定视图导致 WAL 或临时空间快速增长，取消普通备份并释放视图，不能拖垮业务磁盘。阻塞/异常的 provider 只能使备份失败/部分，不得通过杀伴侣或偷偷重启来解锁；违反插件契约的情况单独审计。

### 4.2 新 SDK 扩展点 backup.snapshot

这是在线备份要求下的新公共契约，须先同步 sdk-spec、清单 Schema 和 CHANGELOG，再实现。插件仍只 import clytie.sdk。
清单新增可选 `backup`：`mode` 为 `stateless | snapshot | unsupported`；省略按 unsupported。snapshot 模式需在 `contributes` 声明唯一 `backup.snapshot` factory，按现有 factory 约定返回提供者；其他模式不允许声明。stateless 表示没有需恢复的业务持久状态，宿主发现 plugin-data 内非声明缓存数据时拒绝该结论并报缺项。缓存不能由插件临时声明来掩盖已有业务数据。
已停止且无活跃执行者/恢复日志的插件，可在取得原生命周期及数据锁后做离线一致复制；无需为备份启动插件。运行中的 unsupported 插件有状态时为缺项。支持状态在列表、启用计划及 status 展示，旧插件仍能正常启用，不把新增字段变成隐式停用。

公共协议（以下 ticket/handle 是进程内对象，不持久化或跨 IPC 序列化）：

```
async prepare(request: BackupRequest, cancel: CancelToken) -> BackupTicket
async capture(ticket: BackupTicket, epoch: str, cancel: CancelToken) -> BackupView
async materialize(view: BackupView, sink: BackupSink, cancel: CancelToken) -> None
async release(ticket: BackupTicket) -> None
```

- `BackupRequest`：operation_id、companion_id、plugin_id、目标 data_version、准备 deadline；这些由宿主填充。提供者不自行选择其他实例/伴侣。
- prepare 在捕获门闩外准备资源，可在私有临时区域工作，不停止插件、发送消息、调用模型或改变业务事实；默认 10 秒。capture 在组捕获窗口内固定该 epoch 的稳定视图，不能在这里做大文件复制。准备期间业务改变时须重新验证，不允许返回旧快照却标上新 epoch。
- `BackupView`：epoch、data_version、revision（提供者的稳定版本标识）以及提供者私有只读句柄。提供者保证 materialize 对应 capture 版本；宿主验证 epoch/版本、完整成员和关联，无法证明则不能算完整。实现允许不可变版本、数据库读视图等方式，不要求所有插件采用同一种存储。
- `BackupSink` 只允许 `async write(relative_path: str, chunks: AsyncIterator[bytes]) -> BackupEntry`。宿主计算字节数与哈希；返回相对路径、size、sha256。路径限定当前插件备份命名空间，拒绝重复/穿越/链接，不把任意宿主文件句柄交给插件。sink 拒绝写入声明为凭据的内容；内容完整性仍由插件契约和测试保证，不以扫描代替。
- materialize 在门闩释放后运行，只读稳定视图；取消/超时后不再接受其迟到写入。release 在成功、失败、取消时均执行且应幂等，默认 2 秒；记录释放失败，不吞掉它导致的资源泄漏。迟到资源继续被跟踪，不能把失去跟踪的 provider 说成已结束。
- 该接口提供备份快照，不授予通用恢复执行脚本权限。每个 sink 相对路径精确映射到恢复目标 companions/<cid>/plugin-data/<pid>/ 下的同一相对路径；成员必须是同一 data_version 可直接加载的完整持久布局。数据库须输出可直接打开的一致数据库文件，不接受需要执行 SQL 导入脚本、反序列化可执行对象或运行转换程序才能还原的逻辑导出。需要转换的 provider 本阶段视为 unsupported，结果 partial。宿主只做安全文件重建和格式校验，插件只在用户后来正常启动时按原生命周期加载。

### 4.3 部分与失败

缺项表必须包含组件、原因码和覆盖边界，状态不得泛称成功。partial 可保存已核验材料，但不能用于完整实例恢复、刷新 last_instance_success、满足完整恢复点最低份数或触发有效完整包淘汰。partial 自身最多保留最近 3 份，按明确文件轮转并单列占用；它可占目标预算，但仅 partial 成功不触发对完整包的容量清理。完全无有效材料为 failed，不生成空的成功包。

## 5. 工作进程、停止与强杀

复用管理操作的稳定编号、执行者 PID+创建身份、OS 锁、阶段与提交证据。常规备份工作进程只写备份/本次临时区域，不接管活动伴侣的业务写权限；捕获请求由持有数据的组件响应。恢复工作进程只写明确的新目标。
阶段至少为 accepted、preparing、capturing、copying、verifying、publishing、committed、cancelled、failed、recovery_blocked。数据发布前记录明确目标/临时文件、校验值与阶段；目录重建见 §8。进程退出、HTTP 超时与断连不代表成功或取消。
关窗/EOF 拒绝新操作，取消可中断准备/捕获/复制；已进入必要发布或恢复提交的阶段先完成核验收尾。wait 等待，escalate 转协作取消；沿用 A4.2 的 120 秒提醒而非对数据提交强杀。普通伴侣总超时与迁移保护不变。
停止时有未备份记忆或到期完整备份，至多登记一次 shutdown 触发；业务安全停止后从稳定状态获取最终快照，不阻止其他伴侣先完成停止。shutdown 触发不能递归产生新触发；escalate 可取消尚未进入发布的备份。没有待办时立即正常退出，不固定等时间。副本复制可取消并留待下次，不能为了离线乙阻止停止。
强杀重启后只核验已登记操作、发布产物及明确临时文件，不重放旧请求；未发布且无法完成核验的标失败，下一次自动计划是新的备份。备份核验失败不阻止原健康伴侣启动；新恢复目录的不确定状态只阻止该目标启动。

## 6. 份数、容量与磁盘

### 6.1 保留集合

- memory 按伴侣分组，instance 按实例分组；同组内按完成时间与 backup_id 稳定排序。
- 高频 memory 层最近 12 份；长期层最近 30 天每天最新一份、之后一年窗口每 ISO 周最新一份、更早每月最新一份。层取并集，同一文件不重复存/计数。12 是高频层上限，不是所有长期 memory 包的总上限。
- instance 使用同样日/周/月长期层，不另套 12 份。所有自动 memory 与 instance 以及 partial 加密包的实际长度合计进入同一目标预算。手动包单列，不自动清理。
- 每个 memory 组、instance 组各自最近 3 份已验证有效包始终保护；不足 3 份全部保护。instance 最低保护仅算 complete；memory 不能顶替 instance。被活跃恢复、核验、复制引用的包临时保护。
- 超额淘汰可以打破日/周/月期望保留；状态显示因容量少了哪些恢复点。最低保护、明确恢复引用优先于容量和份数要求；不可满足时显示 retention_protected，不偷偷删。

### 6.2 用户批准的滚动容量算法

目标默认 20 GiB，显式可配置，也可关闭容量目标而只按时间/份数保留。默认不是硬拒写上限。所有数量按文件真实长度，GiB 明确为二进制单位。
1. 同一备份序列化锁内，记录新备份开始前自动包集合及总长度 S、当前目标 T；处理旧 pending 的核验，不能先扫掉未知文件。
2. 制作并验证新包 N；失败或取消不做容量/长期保留清理，旧有效包保持。先有新成果再删旧。
3. 成功后按高频/日周月规则及保护集合生成清理计划。若开始时 S 大于 T，再从剩余最早的可删除旧包依次选择，直到不含 N 的旧自动包总量不大于 T，或已无可删除项。即使 S 未超目标，份数/期限轮转仍执行。
4. 删除时重新核验身份、引用、保护集合和配置版本；变化则重新计算，不沿用过期计划。一次一个明确文件，写删除记录；失败保留占用并提示。
5. 当 S 不大于 T、新包使总量超过时，本次不额外按容量删除；下次成功备份再处理。正常结果可以达到目标以内的旧包加最新完整包；制作/验证期峰值还包含临时空间，不能宣传为不超过 T。
6. 例：原有 10 份共 2.9 GiB，目标 3 GiB，新增后超过允许；下一次成功备份后才从最早可删除旧包开始清理，必要时多删几份。若单包或受保护集合已超过目标，保留并显示不可满足，不截断、不减少备份内容。
7. partial 不作为淘汰 complete 的成功凭据。轮转故障不能把已提交新备份改成失败；结果分别显示 creation 和 retention。

### 6.3 空间预检与尺寸

开始前给出源数据估算、当前备份总量、现有旧实例/特殊快照占用、临时空间预算和目标盘剩余空间。压缩率未知按不压缩估算，额外格式开销及数据库/WAL/校验暂存由算法计算，不将假定压缩率当保证。默认保留 1 GiB 文件系统剩余空间裕量，支持配置。
工作中持续检查实际空间/临时预算；不足则安全取消普通备份，保留既有有效包。不得为开始新备份先牺牲保护底线或临时缩短保留。产品允许用户明确清理、增大预算或换盘，不能把设置目标容量等同于可用磁盘保证。
状态分别统计常规包、手动包、特殊快照、失败现场、旧实例、临时产物；不把“预算内”显示成整实例磁盘总占用受限。压缩只用无损方法，媒体本身不转码。各备份记录耗时、字节数、压缩比和校验结果，估算与实测明确区分。

## 7. 额外副本乙

- 默认关闭；启用时指定独立副本仓库，不能位于主实例/甲/恢复目标及其子目录；不能与甲是同一物理存储设备。验证设备身份，不能只凭盘符不同断言不同磁盘；无法可靠确认时报告不满足，不能假装已建立异盘保障。
- 仓库有随机标识及所有权记录；首次接纳需确认。每次复制先核验目录、设备/仓库身份、可写和空间；挂载点下掉盘后出现普通目录不能当作原设备继续写。
- 只复制已验证的加密文件；临时文件、长度/哈希核验、原子发布、副本回执。密钥永不复制。复制运行期间主包受引用保护；中断保留 pending 记录，不能把半文件算有效。
- 离线/失败不影响甲，status 区分本地成功和副本未更新；重连补每个备份组最新有效包，包含 instance 与各伴侣 memory，不补造离线期间全部历史。partial 默认不复制。
- 沿用已批准乙保留：每组最近 7 份，加最近一年每月一份，至少最近 3 份；只删除本仓库回执明确拥有的文件。乙占用单列，不计入甲的 20 GiB；保留配置可调，不因甲删除而同步删除乙。
- 改乙路径后先验证新仓库，复制/校验最新包，才显示新副本 ready。新目录失败时保留旧登记，状态为切换未完成，不能静默回退或清空任一仓库。明确关闭则停止复制，已有副本不删。
- 旧乙变为历史仓库，不再写入或自动清理，保留位置与最后已知占用/时间；不可访问时标 unknown/stale，不编造当前大小。历史副本迁移全部文件不在 A4.3 自动流程中，用户另行处理。

## 8. 完整恢复、管理入口与切换

### 8.1 计划与目标

只接受 complete instance 包。先解密校验，核对代码/Schema/插件版本与目标兼容性，再生成 plan；不兼容则 blocked，不自动拉代码、装依赖或执行未知迁移。前向格式不支持明确拒绝。
目标必须是用户明确指定的新空目录或不存在路径，不得是当前实例、备份仓库、源包目录、任何受管目录的祖先或子目录；拒绝链接与路径别名。计划记录源包/密钥指纹、组件覆盖、凭据缺项、旧恢复点风险、预计目标 R、临时 W、必要 B、可用空间、兼容性和目标指纹。空间在 apply 前再次核对，不因计划时够用就盲目继续。
已有实例完全保留，本流程不对它执行覆盖/迁移，不额外为只读旧实例生成一份等大的保护包；恢复只写空目标。若目标有任何非本操作拥有的内容，拒绝，不能用“已有备份”授权覆盖。新目标内的临时文件即最终数据，校验后提交完成标记，不再复制到旧目录。

### 8.2 灾难恢复时 API 如何启动

正常管理继续走 API。旧实例不可启动时，新增显式 `supervisor start --maintenance`：使用用户单独指定的管理 home（通过原 CLYTIE_HOME 选择），只启动本机管理 API，不启动伴侣、平台、插件、自动备份或模型。允许空管理 home，建立最小管理元数据/通行证，不伪造伴侣配置或空记忆。执行 restore apply 的管理目录必须与尚未恢复完成的目标分开。目标已提交 ready_for_switch 后，可以按 §8.4 在目标自身以 maintenance 模式启动 API 完成切换前确认；不能在 incomplete 目标启动任何模式。
这是本里程碑新增的恢复引导模式，不把 CLI 变成绕过 API 的离线业务实现。鉴权、Host/Origin、CSRF、管理口令及停止规则仍与 A4.2 相同；首次没有口令沿用原明确提醒/CLI 确认规则，不声称网页已可登录。恢复源密钥由用户显式提供本机文件路径，后端不记录原文、不通过 URL/CLI 参数接收密钥值，不自动扫描旧私有目录找密钥。

### 8.3 执行和提交

apply 绑定 plan、源包与空目标，确认并要求现有管理口令保护；持目标跨进程排他锁，先登记操作和恢复未完成标记，再逐项解密写入/校验。只清理本次登记的临时文件。取消后留下的目标明确标 incomplete，不能启动；用户可生成清理计划后重试，不能自动重跑恢复。
最终校验包含数据库、资产、UID、插件版本、账本/回想关联、管理状态及源清单。全部通过才提交 ready_for_switch 标记与目标结果，不能仅凭进程退出确认。强杀后核验已完成文件及阶段，只完成已规定的核验/提交，不再次解密重建整个请求；无法确定则恢复受阻。
凭据不恢复：源密钥只用于解密，不自动写入新实例；新实例首次备份按既有规则独立生成密钥。旧包/旧快照仍需旧密钥，必须提示继续保管。记忆恢复公钥/账号凭据缺失列为待配置；不借此自动生成恢复码或联网验证账号。
原管理操作日志/迁移执行者不能作为活跃进程恢复；已完成记录作为历史保留，必要路径绑定为目标内验证过的引用。未解决的跨文件恢复依赖使源包不能 complete。不恢复旧锁、通行证和网页会话。

### 8.4 切换

恢复完成不自动停止旧实例、修改环境变量、创建快捷方式或启动新实例。输出准确的目标目录、待配置项、旧实例停止要求和切换步骤。CLI/以后 WebUI 仅展示并调用既有管理入口，不复制数据。
切换有两个独立步骤：source_stopped 确认与 switched 完成登记。用户先在已就绪目标自身以 maintenance 模式启动 API，调用 restore source-stopped，绑定该目标恢复标识并确认源已停用。服务端检查同机源运行登记、OS 锁和进程创建身份；发现源仍活跃则拒绝，不能靠确认覆盖。源设备不同或信息不可访问时明确无法自动证明，由用户确认源已经停用并写审计。然后停止 maintenance，以正常模式启动该目标；首次业务启动前再次检查同机源状态，检查失败保持阻止，不启动平台。正常启动后再调用 acknowledge 记录 switched。两个操作幂等且可分别查询，不用业务已经启动作为 source_stopped 的前提。不能承诺跨机器单靠本地锁保证单实例；不把伴侣 UID 改成新的来绕过。
启动后仍按原配置保持静默状态、边界状态、通知冷却，不自动解除静默。缺凭据/插件版本按现有 blocked 规则，不接真实平台“试试看”。切换完成由新实例 API 核验本恢复标识、当前 home、源停用确认及启动状态后记录，通知用户旧目录仍在，含位置、大小或未知状态与清理入口。实例级运行代次与源区别，伴侣 UID 不变。
恢复完成标记带受认证包指纹、源实例标识、目标实例标识、操作编号和本机目标绑定；新实例只接纳本目标已提交标记，不能信任任意拷入的来源路径。旧目录未在当前机器核验身份前只显示为待核实历史位置，不可清理。

### 8.5 单独记忆备份的恢复入口

新增本体备份源适配器，不以第三方 memory.importer 身份加载。`POST /backup/memory/plan`（CLI `backup memory-plan <backup_id> --companion <cid> --mode new或merge或restore`）验证 memory 包、实例密钥和 companion_uid，将允许导入的记忆材料交给已有 Transfers 计划引擎。排除本机回想进度、进程/管理记录等运行状态；保留原生记忆的修订指纹、basis、来源、淡化与撤销，不降为第三方提议。
结果仍是原 `/memory/import/plans/<plan_id>` 可查询的计划，执行仍走原 `/memory/import/apply`，模式/UID/冲突/可信程度/前置快照/停止要求/撤销导入及口令保护不变。apply 与内容预览重新校验源包和解密密钥；计划只存 source_type=backup、包指纹、密钥指纹及绑定信息，不保存明文或密钥。不是从 instance/partial 包任意抽取一部分覆盖当前库。
源包在计划有效期、apply 或核验期间被引用保护；过期/完成/取消后释放，崩溃后按操作证据核验引用，不能永远占住也不能提前删。明文临时材料只在受控本次工作区，结果不返回原文，预览仍使用原明确内容入口。普通 memory import 的包口令/恢复码路径保持不变；源适配器字段及解密选择由服务端已保存的计划决定，不信任 apply 客户端换格式以绕过保护。

## 9. 工作连续性与不重放

### 9.1 回想

常规生成备份不修改任务/回想进度。memory 导出/导入和单独 memory 备份均不据此恢复跨账本进度，保持原语义。
complete instance 包中账本、记忆和 recollect_progress 属于同一可核验一致性组；恢复后保留进度，从尚未提交的窗口继续，已提交经历不重复生成。仍执行当前撤销过滤、可见范围、权限和防重规则。必须区分：首次尚未建立进度，或由包内保留期/裁剪证据证明的正常历史缺失，可以报告 continuity_unverified 并从恢复后新消息开始，计划明确该会话连续性不可恢复；不猜起点、不自动重做更早窗口。若是来源错配、进度越过包内可证明的账本边界、无证据的截断或其他一致性损坏，则拒绝 complete/ready_for_switch，不能以降级跳过掩盖错误。
备份之后丢失的聊天无法凭空补回。恢复旧点可能复活后来撤销的内容，计划显式提示；不能跨出包内证据假装已找回较新撤销。停用期间本已跳过的窗口保持跳过，不因实例恢复绕过已批准的停用规则。

### 9.2 周期计划和长期任务

保留周期配置，用户正常启用后继续未来触发，默认不补发停机错过的提醒；不重放旧 tick 队列。计划时区/防重沿用内核，备份本身的错过补当前快照是专用内部策略。
保留长期目标、步骤、检查点、已知外部结果，但 A4.3 不新增任意任务自动续跑引擎。原已开始 invocation 按账本恢复规则中断/未知，不直接把旧执行状态改为 queued。
具有后续专门恢复协议的任务可在校验外部结果/幂等凭据并获该协议授权后从安全检查点继续；本阶段没有该协议的任务显示待人工核验。结果未知的发送/上传/提交不自动重试，不能靠新任务编号绕过。不把“保留进度”或“用户切换确认”解释为执行全部旧任务的授权。

## 10. 旧实例与磁盘维护

恢复/切换记录绑定 operation_id、源/目标实例与恢复代次、canonical path、可验证文件身份、登记时点、占用及统计时点。保留所有已知旧实例摘要，不因多次切换丢失上一轮记录；外来机器路径只能显示说明，重新接纳前无清理权。
切换后即时通知，status 持续列数量/总占用/最后扫描时间，下一次恢复计划再次展示。默认数量达到 3 个或已知合计超过 20 GiB 时提升警告；这两个值可配置，只是提醒，不自动删除。目录失联显示未知，不把它算成零。
清理分两步：plan 逐文件列明登记身份、大小、修改情况、独有文件、密钥和恢复引用；apply 再校验并要求确认及管理口令。仅在能证明不是当前/活跃/必要恢复来源，且独有数据已有用户确认保留位置时执行。对于旧备份仍需要的唯一密钥、未验证独有数据或来源不明目录，阻止自动清理并报告，不能仅凭点过“已保存密钥”当作独立副本证明。
计划绑定内容指纹；变化即失效。逐个明确文件删除并记录，最后删除已空目录；遇到链接、未知新文件、权限错误停止并显示实际进度，不能递归删除、不能修改系统 ACL。失败后重新计划，不能声称已全清理。配置旧目录提醒不改变普通备份预算。

## 11. 密钥、特殊快照与日志

### 11.1 实例备份密钥

沿用 secrets/backup.key 和 ADR 0004，不自动替换，不进入任何包或乙。提供指纹、导出、保管确认状态：首次生成持续提醒，用户确认已另存后改为已确认，明确这不是已验证外部副本。正常聊天不因此停止。
`backup export-key <path>` 需要确认和 A4.2 管理口令保护，目标不得存在、不得在主/副本备份目录或公开仓库内；只返回指纹与导出状态，不在日志/API 历史结果显示密钥。文件按用户权限创建，不放宽 ACL。源密钥丢失时不生成新密钥假称旧备份可用。
`backup verify-key <path>` 仅比较用户明确提供副本的指纹并可对指定包校验，不记内容；遗失文件或错误密钥明确报错。新旧实例密钥独立保管，删除旧实例前检查旧加密产物仍可解密的条件。

### 11.2 特殊快照

账本迁移最近 2 份及内容保留期、失败现场保护、插件升级最近 3 份、记忆导入最近 5 份，继续原规则，不被 20 GiB 普通预算覆盖。
记忆 Schema 迁移快照此前未自动清理：本规格工程默认每伴侣最近 3 份已验证成功迁移前快照；仅新迁移成功、无活动/恢复受阻引用后，逐个明确文件清理更旧者。失败迁移现场不计入 3 份，不自动删。历史文件无可靠归属/回执时保留并提示，不通过文件名猜测后删。补同步 supervisor-spec 中此前待 A4.3 决定的说明。

### 11.3 日志

普通运行日志默认单文件 10 MiB、每进程保留最近 10 个归档，当前文件另计；可配置，逐个文件轮转，不备份。禁止打印私密原文或凭据的规则不变。
守护/管理审计分卷但本阶段不自动按普通日志份数删除，随完整备份保留；数据库内记忆/任务审计仍归对应数据库。轮转与并发写入协调，不能丢事件或把当前正在写的文件误删；status 单列审计占用，不声称所有日志有总上限。

## 12. 配置、API、结果和错误

### 12.1 配置（实例级 backup，全部可省略）

| 字段 | 默认及校验 |
|---|---|
| enabled | true；关闭不删除已有备份 |
| memory.enabled / memory.debounce_seconds | true / 300，整数 1–3600 |
| schedule.at / schedule.days | 03:00 / []；HH:MM，星期范围沿用 at，空为每日；实例 timezone |
| schedule.catch_up | true |
| retention.recent_memory | 12，整数且不小于最低保留数 |
| retention.daily_days / weekly_weeks / monthly_months | 30 / 52 / null；正整数或相应层 0 禁用，monthly null 为不按月龄到期；容量仍可淘汰 |
| retention.minimum_per_group | 3，不小于 3；降低保护底线不作为普通配置开放 |
| retention.target_gib | 20，正数或 null；允许小于单包，显示不可满足而非截断 |
| disk.reserve_gib | 1，正数 |
| mirror.enabled / mirror.path | false / null；启用必须明确目录并通过仓库确认 |
| mirror.recent / mirror.monthly_months / mirror.minimum | 7 / 12 / 3；minimum 至少 3，其余不得小于保护底线的有效含义 |
| old_instances.warn_count / warn_gib | 3 / 20，正数，只影响提醒 |
| logs.rotate_mib / archives | 10 / 10，正整数，普通日志，不覆盖审计 |

配置计划显示下次执行时间、保留影响、预算范围与超额语义；调整预算不当场删文件，下一次成功自动备份按新版本计算。降低保留期限/关闭备份/修改副本目录需要确认，其他更改也审计；Schema 未知字段报错。A4.3 提供 API/CLI，WebUI 以后复用。

### 12.2 管理入口

所有路径位于 `/api/v1/backup`；CLI `clytie backup ...` 仅调用 API。

| 路径 / CLI | 行为及保护 |
|---|---|
| GET /status、/list；status、list | 分类别时间、覆盖、占用、缺项、保护阻碍、副本与旧实例，默认不返回私密内容 |
| POST /create；create --scope memory或instance [--companion] | 明确生成 manual 包；返回 operation_id，复用查询/取消，身份去重 |
| GET /operations/<id>；operation <id> | 阶段、提交与校验结果；无密钥或私密内容 |
| POST /operations/<id>/cancel；cancel <id> | 确认；协作取消，不覆盖已提交事实 |
| POST /verify；verify <id> | 独立校验、结果版本和时间，不把模型联网启动当验证 |
| POST /config/plan、/config/apply；config plan/apply | 版本绑定、确认、保留注释，复用 A4.2 配置写回与历史 |
| POST /restore/plan、/restore/apply；restore plan/apply | 源、目标、空间与兼容性计划；apply 确认及管理口令 |
| POST /restore/source-stopped；restore source-stopped <id> | 目标 maintenance API 登记启动前源停用确认，确认及管理口令；同机源活跃拒绝 |
| POST /restore/acknowledge；restore acknowledge <id> | 正常启动后核验并登记切换完成；确认，不自动改环境变量或启动平台 |
| POST /memory/plan；memory-plan <backup_id> | memory 备份源适配到原记忆计划；后续查询/预览/apply/undo 沿用原入口与保护 |
| POST /cleanup/plan、/cleanup/apply；cleanup plan/apply | 分类明确的备份/旧实例清理；apply 确认及管理口令，重新核验保护 |
| GET /key/fingerprint；show-key-fingerprint | 只显示指纹/保管确认状态 |
| POST /key/export、/key/verify、/key/acknowledge；export-key、verify-key、acknowledge-key | 导出确认及管理口令；核验不回传密钥；保管声明不等于核验 |

全部非 GET 审计，默认只用逻辑编号/原因码/数量，不把秘密、真实源内容或任意错误原文放入日志。需要展示本机路径时只给已认证管理用户，不传播到外发通知。管理 API 的 plan 根据服务器数据判断保护等级，不能信任客户端声称低风险。
结果至少分开 creation（complete/partial/failed/cancelled）、verification、retention、mirror、restore_readiness；总体成功不能覆盖其中失败。常见原因码含 capture_busy、snapshot_unsupported、snapshot_inconsistent、space_insufficient、retention_protected、mirror_unavailable、mirror_identity_mismatch、restore_incompatible、restore_target_not_empty、restore_recovery_blocked、continuity_unverified。映射沿用 API 的鉴权/确认/冲突规则，ADR 给出完整映射表与 JSON Schema，不用解析自由文本驱动逻辑。

## 13. 离线验收清单

全部用虚构数据、假模型/平台/通知、MockClock、本机回环及临时实例，不读取真实数据，不下载模型、不发真实通知。每项给代码位置、测试名、结果与未覆盖部分；Windows/Linux 覆盖实际可用路径。

1. 范围与排除：配置秘密、secrets/run/已有包/模型缓存/外部链接不进入包；必要资产、插件代码/版本、静默/冷却/审计可恢复；缺资产/未知秘密状态不假称完整。
2. SDK：旧清单正常启用但 unsupported；stateless 非空数据矛盾、provider 编码/方法/Schema 错误、超时、迟到写、释放失败可检测；插件只用 SDK，sink 越界/重复写拒绝。
3. 在线单库：真实并发 SQLite 写入与分批快照、持续聊天假请求、事件循环响应；恢复库结构与内容完整。不得用串行复制测试冒充在线。
4. 跨组件：真实并发回想提交/账本写入与捕获边界、插件状态和版本/配置变更、资产关联；在边界前后注入变更，不能恢复成不匹配状态；门闩超时不阻止聊天、不杀插件。
5. 迁移/管理冲突：活跃迁移、受阻恢复、启动争锁、配置写回与备份同场组合；不触发错误恢复、不删除依赖来源，不自动停止伴侣。
6. 格式：无损还原、错密钥/截断/成员缺失/重排/大小写冲突/路径攻击拒绝；大文件有界内存；临时空间与加密正文无泄漏日志。
7. 调度：首笔固定窗口不被持续修改延期；无变化不事件备份；每日/每周/时区夏令时、错过只补一次、防重与重启退避、单并发；instance 覆盖版本后才消除 memory 脏标记。
8. 分类：partial 不刷新完整成功、不满足最低份数、不淘汰 complete；memory 成功不掩盖 instance 缺口；失败不清理旧有效包。
9. 容量：用小字节假文件等比例验证 2.9/3 示例、下次才清理、先生成验证再删除、一次多删、份数独立轮转、日周月去重、每组最低保护、引用保护、单包大于目标、手动/特殊包不误删。
10. 空间：源估算/压缩不确定、真实写入中空间不足、WAL/临时上限、清理失败分别报告；不靠删除保护包开始新备份，不把目标当硬磁盘上限。
11. 停止：真实独立工作进程的关窗/EOF/API cancel/wait/escalate、其他伴侣并行停止、提醒不强杀提交；shutdown 触发只一次、副本离线不拖停。
12. 强杀：只杀备份worker、只杀守护、杀树；发布前后、登记前后各点核验，旧有效包不丢、半包不登记、不重做原请求、不遗留不可跟踪执行者。
13. 副本：设备断开/身份变化/同盘/无法验证、temp发布中断、校验错误、重连最新每组、旧仓库不删、新仓库失败、引用保护；主成功与副本失败分别报告。
14. 完整恢复：新空目标、空间预检、版本不兼容、错误包、凭据缺项、无自动网络、无额外整目录复制、目标中途取消/强杀/部分写入，源不变，失败目标不启动。
15. 灾难入口：源实例不存在或坏配置时 maintenance 管理home可启动API但无伴侣/模型/平台/自动备份；恢复写入时目标与管理home隔离；ready_for_switch 目标自身可启动 maintenance 完成 source_stopped，停止后正常启动、再 acknowledge，两阶段不循环依赖；incomplete 目标拒绝所有启动，正常API鉴权保护不被绕过。
16. 连续性：complete instance 回想进度/账本一致可继续、已提交不重复；正常无进度/有裁剪证据可降级，错配或损坏必须拒绝；memory 备份源适配复用计划/apply/undo，所有模式、UID、冲突、源包变化、引用保护、密钥错误与内容预览覆盖，进度不被导入；停用窗口不回填；长期目标保留，未知外部效果/旧invocation不自动续跑，周期仅未来触发。
17. 切换与旧实例：旧实例仍活着拒绝同机双启、跨机不可证明需确认、UID不变、旧目录登记跨多轮保留、占用失联标未知、独有文件/唯一密钥/活动引用阻止清理、变更使计划失效、逐文件失败可追溯。
18. 密钥：首次提醒、保管确认不等于证明、导出确认/口令/路径/已存在拒绝、错误副本、旧包仍需旧钥、新实例不自动携带旧凭据、日志零密钥。
19. 特殊快照与日志：现有各类规则不回归；记忆迁移只有成功且无引用才清理；普通日志轮转并发不丢写，审计不套普通删除规则。
20. API/CLI：异步结果去重、断连查询、配置写回/版本/注释/确认、restore与cleanup口令、状态分轴、信息不泄露，维护模式与正常模式边界。
21. 性能证据：至少小文本库、大数据库、多小文件、大资产四种虚构规模；报告无备份/有备份的相同负载 P50/P95/P99 响应、写入等待、备份耗时、峰值内存/临时磁盘。不能预设本机几秒或声称零影响。固定负载/种子/机器条件，结果可重现；明显业务停顿、无界增长或超出已定捕获界限是阻塞，不能只报测试数量。
22. 恢复演练：从生成的真实加密 complete 包在新临时目录恢复，逐项验证数据/进度/配置/审计与缺项，不调用真实账号；每种平台保留完整证据。正式开发自检、扫描、双平台必要 CI 后按 AGENTS 原生独立审查，最多三轮。
