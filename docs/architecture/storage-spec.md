# 存储 I/O 所有者：A4.3 / Issue #72

状态：用户已确认，待实现及验收。本文落实用户批准的完整草案和后续修正；不表示 A4.3 已通过。正式审查预算已用 1/3，不重置。

## 1. 范围与不变项

每个运行伴侣一个专用 StorageOwner 线程，统一拥有记忆和账本连接；在线备份使用独立只读快照线程。目标是将本体存储 I/O 移出事件循环，同时保留完整业务延迟、持久性、一致性及恢复保证，不把延迟搬进无限队列后宣称解决。

不直接用 to_thread 包装已有连接，不关闭 SQLite 线程检查，不把连接交给公共线程池。不合并记忆和账本数据库，不新增通用跨库事务框架。不降低 SQLite 同步级别、不删除 fsync、不放宽跨进程互斥，不自动重试已执行或结果未知的业务。

停止伴侣后的独立管理工作进程保留，在自身执行线程创建、使用及关闭连接，复用同一业务校验，不成为第二个在线写入者。plugin-versions.metadata 仍遵守 kernel-spec §15 的异步尝试、注入时钟及无工作线程规则，不纳入本方案。

## 2. 连接、命令与上下文

- 记忆、账本连接在所属 StorageOwner 线程创建、读取、提交、回滚和关闭。迁移及启动前核验仍按原协议；核验未完成不能发布可用所有者。
- 事件循环通过内部异步接口提交完整的本体存储命令。所有读取也经过所有者，包括健康统计、投影、检索材料、修订检查及停止时查询；不能保留绕过入口的 .db 或游标访问。
- 命令只能来自本体的受控接口，不能成为插件可提交任意 SQL、函数或文件路径的入口。插件仍只 import clytie.sdk；现有 SDK 权限及结果含义不变。
- 输入固定可信 companion、scene、conversation、权限、预期修订及取消上下文。每个命令绑定并在 finally 清理，不能继承上一个命令的私密场景。原来无绑定场景的调用仍按 public_group。
- 返回独立数据快照，不返回连接、游标、引用可变内部状态的对象或依赖连接的迭代器。外部修改返回值不能改变所有者内部状态。大文件及资产仍通过原受管引用和流式路径，不把其正文复制进排队项。
- 存储线程不调用插件、模型、平台或网络，不等待事件循环执行普通存储命令；线程内嵌套的本体同步操作沿用本命令事务/协调，不能排到自己后面再等待。
- 时间和期限来自注入 Clock。事件循环负责异步计时和发出控制通知；线程用同步信号交接，不引入业务 time.sleep，也不在事件循环同步 join。

## 3. 事务与跨库协调

写命令顺序固定为：取得必要协调 → 开始事务 → 读取并校验 → 修改及审计 → 提交或回滚。影响正确性的读取、权限投影和预期修订检查必须在相应事务或既有协调保护内，不能只在入队之前检查一次。

事务内不 await、不调用插件/模型/平台、不等待网络。需要外部计算的流程采用读取快照 → 外部计算 → 带修订校验提交；原修订冲突和权限规则不变。

记忆和回想进度仍在记忆库同一事务提交；账本发送前登记、收据、防重和取消仍按原事务协议。锁顺序保持既有生命周期/迁移保护、固定顺序的捕获门闩、SQLite 事务；所有者不能改变已有运行锁的授权边界。

同一所有者执行跨库逻辑命令，共同捕获门闩覆盖完整逻辑边界，正常运行时不能被其他命令或捕获插入。串行线程、共同门闩及 SQLite WAL 均不能被描述为多库整体原子提交。多阶段操作继续依靠已有日志、提交证据及恢复顺序；数据库与文件组合变更同样如此。

实施前列出全部跨库写入链路和对应的安全边界：涉及数据库/文件、提交先后、审计/日志、提交后响应丢失、强杀后核验及捕获可见状态。发现已批准保证没有恢复协议时单独报告，不能新增假原子性或偷偷降低保证。

## 4. 容量、排序和收尾凭证

内部初始默认值，不新增用户配置：普通容量 64 个未完成请求，包含正在执行项；另保留 16 个必要收尾名额；每伴侣最多一个待处理或执行中的捕获请求。两个伴侣不共用阻塞队列，但共享磁盘仍可能竞争。

已就绪命令按 FIFO 执行，同一业务链严格保持依赖顺序。收尾预留是容量凭证，不是占据 FIFO 队头的未就绪命令；外部结果就绪后，对应收尾命令才入执行队列。不能因预留者尚未产生结果而阻塞其他就绪命令。

凭证由可信本体在可能产生外部副作用前取得；取得失败不能先调用工具/平台再等待容量。一次凭证覆盖完整操作生命周期，可以顺序提交多次持久记录，例如发送前登记、收到结果、重试决定、最终状态；不能在第一次写入后便释放。该凭证同时最多有一个排队或执行中的命令，其后续命令保持业务依赖。

只有对应外部执行者已结束、所有必要结果/取消/迟到结果与审计均完成并且没有待收尾责任时，才能释放凭证。取消请求、HTTP 断线、第一次响应或超时本身不证明责任结束。忽略取消的迟到执行者继续受跟踪并占用其凭证，不能释放后再无容量地补写；状态如实显示。重复释放幂等，不把同一凭证归还两次。

普通队列满时，对尚未接受的新请求明确返回 storage_busy，不无限排队、不偷偷重试。已接受业务必要收尾不得丢弃。平台入站落实背压或明确失败，不能假接收后丢消息；每个入口的接受点及忙碌映射须列入实施清单和组合测试，不统一吞成普通 ValueError 或成功。

控制通道不占普通队列。取消和状态查询可以及时受理：受理取消不等于执行者退出；缓存状态必须带观察时点，不冒充最新数据库核验。状态只含阶段、队列数量、等待及错误类别，不含记忆、SQL 参数、凭据或密钥。

## 5. 捕获屏障与只读快照所有权

沿用 backup-spec §4.1 的总等待 2 秒、总持有 250 毫秒；等待包含排队及取得门闩，不按插件数累加持有预算。准备及重 I/O 在门闩外。

1. 在门闩外准备组件、配置及只读资源。快照连接由独立快照线程创建，保持 SQLite 线程检查。
2. 捕获命令排到 StorageOwner 后，先到达此前逻辑操作的安全边界，进入捕获屏障并按既有协议取得跨进程门闩。
3. 在共同边界内，由快照线程建立并实际读取记忆、账本的 WAL 只读视图，同时固定关联进度、边界状态和资产/插件证明。普通存储命令在屏障期间不执行；事件循环控制处理继续。
4. 固定成功后立即释放业务门闩、恢复队列。只读线程在同一连接/视图上完成分批复制，再关闭连接；不能释放视图后重开活动源冒充原边界。
5. 压缩、加密、校验及大文件复制不长期占用业务队列。视图、WAL、临时盘及迟到执行者仍受原资源限制和停止规则约束。

捕获失败、超时或取消禁止迟到视图提交。不可抢占 I/O 尚未返回时保留跟踪，不强杀线程、不谎称连接或锁已释放；工程期限不是硬实时抢占承诺。释放失败不得宣称完整捕获。

插件 capture 不得重入被屏障暂停的本体存储队列。检测覆盖跨 await、子任务及宿主转交的异步调用链，不能只按线程编号判断。重入立即拒绝并按提供者缺项处理，不排队等待屏障结束。所需读取移到 prepare，并在 capture 校验版本；准备后的变化不能返回旧视图并改标 epoch。该规则不禁止其他无关业务正常等待存储队列。

## 6. 先行 SQLite 原型门槛

生产接线前，用虚构数据完成独立离线原型并保留测试证据：

- 只读线程建立固定视图后持续真实写入，复制结果仍对应捕获边界；不能只证明最终数据库完整。
- 记忆、账本、回想进度及关联状态在边界前后变化，不混入不同代次。
- 超时/取消后读事务和视图真正释放，WAL 不被遗留读者永久保留；检查工作线程确已退出。
- 具体 SQLite 在线备份路径必须证明逐批取消检查确实发生。把同步 backup 调用放入 async 包装并不构成证明。
- 使用真实线程/连接，关键竞争与强杀使用真实本机进程，不能仅以 fake 或串行 mock 代替。

## 7. 取消、提交和恢复

| 状态 | 行为 |
|---|---|
| 排队未开始 | 执行前取消，无数据修改，释放其普通容量 |
| 已开始、提交前 | 安全点响应取消；完成回滚后才报告取消 |
| 提交或必要收尾已开始 | 等待真实结果，不强行中断线程或提前关闭连接 |
| 已提交、响应未送达 | 保留提交事实，不改报未执行或已取消 |
| 调用方断线/取消等待 | 底层执行者仍由所有者跟踪，Future 取消不等于执行结束 |
| 所有者异常/强杀 | 按原持久证据核验，不偷偷新建替代写入者，不重放内存队列 |

提交开始与取消的竞争以明确状态转换串行裁决：提交前取消已经生效则回滚；提交已开始则保存实际结果。上层任务取消与底层存储已提交事实分别记录，不改变原工具、收据或管理操作的取消契约。

复用已有稳定业务/管理编号、修订、日志及事务内提交证据；没有证据时不能猜成功或猜未执行，更不能自动重做。进程退出、响应丢失和 PID 存在都不能单独证明提交结果。unknown 发送不重发、旧任务不重放、恢复受阻标记及第二写入者排除均保持。

## 8. 停止及所有者退出

停止先拒绝新业务，保留已接受任务及插件停止回调所需收尾。wait、cancel、escalate 沿用原语义；控制指令不排在普通存储队列后面等待才受理。

在原生命周期顺序内，先结束业务生产者、插件停止回调及必要收尾，核对快照读者和持久责任，再由所属线程关闭连接并退出。异步等待退出，事件循环不执行同步 join；不能先关库再让停止回调写入。

普通伴侣停止期限、超时强杀、force_stop 审计/通知、迁移保护和独立管理工作进程例外不变，不把普通线程改造成新的无限等待例外。强杀后按既有恢复协议核验；一个伴侣的所有者故障不阻止其他伴侣停止。所有者异常时不在原执行者尚不确定的情况下创建第二个写入者。

## 9. 功能验收

1. 创建/读写/回滚/关闭的线程归属，错线程访问拒绝；所有调用路径不泄露连接或游标。
2. 完整事务读改写、修订冲突及跨场景隔离；外部计算期间不持事务。
3. 普通队列满、16 个预留耗尽、就绪 FIFO、同链多次写入、未就绪凭证不阻塞队头；入站接受和副作用前取得容量。
4. 收尾不被普通请求挤掉；取消、迟到结果、重试记录完成前不释放凭证；重复释放不增加容量。
5. 捕获共同边界、持续写入、跨异步调用链重入拒绝、版本变化、超时、迟到视图和资源释放。
6. 出队/取消、提交/取消、提交后响应丢失；控制受理与真实完成分别断言。
7. wait/cancel/escalate、插件停止回调写入、无工作时及时退出、所有者异常隔离。
8. 真实进程强杀及重启后无第二写入者、不重放、不重复提交，原运行锁和持久证据生效。
9. 原 A3/A4 的记忆投影、修订/撤销、回想、工具结果/收据、管理、恢复、资产、迁移及安全停止组合链路不回归。

时间边界用 MockClock；真实本机进程、真实 SQLite、假模型/平台/通知及临时虚构实例提供 Windows/Linux 组合证据，不读真实部署数据。

## 12. 门闩外备份节流同步（Issue #72，用户已确认）

备份复制、物化、打包、摘要及副本可观察读写按 backup-spec 的“门闩外重 I/O 有界调度”节统一执行：每实例一路、等待 8 阶段、256 KiB 粒度、16/4 MiB/s 正常/繁忙预算、512 KiB 突发。StorageOwner 只发布可信压力元数据，不在其业务队列中执行令牌等待。100 ms 信号、20 ms 繁忙触发、低于 5 ms 持续 1 秒恢复、过时信号保守处理；完整定义以该节为准。
固定读视图最多 5 分钟，每库新增 WAL 256 MiB，触限协作取消并核验实际释放，不自动放宽、不强杀线程。§5 捕获期限、§7/§8 取消提交停止规则及 §10 性能门槛保持。线程关闭警告和原始证据归档缺口独立处理，不能由节流效果抵消；冻结一组参数完成机制验证后再做一次完整三臂矩阵，后续调参需用户确认。

## 14. 原生 SQLite 校验边界（Issue #72，用户已确认）

backup-spec 的“SQLite 原生校验的字节预算例外”适用于创建、复制后及恢复的全部必要原生校验。完整检查不删减；后台执行、门闩之外、实例唯一重 I/O 槽位，嵌套复用。连接仍在所属线程创建/使用/关闭；progress_handler 仅检查取消，执行前后也检查。取消后等待实际执行和资源关闭，才释放槽位，不抢占线程或提前宣布结束。必要提交及恢复沿用原规则，不新增提交中的人为令牌等待。

可观察复制/读写/摘要保持既定预算；原生内部读页是明确例外，字节未知，不填零、不按文件大小或回调数估算，不用预读宣称受控。不引入 VFS、绑定或自定义读取后端，不改变业务所有权。真实调用链回归核验互斥、嵌套、排队/执行取消、异常、正常释放和禁止错误发布。性能窗口覆盖所有校验及慢样本，记录起止、取消受理、实际退出并与业务延迟关联。§10 门槛、合法夹具、次数预算、证据流程和一轮已用的审查状态不变。

## 15. 管理操作限定槽位交接（Issue #72，用户已确认）

按 backup-spec 的“限定版管理操作槽位交接”执行。宿主在可退出的前置检查后、materializing 及恢复责任之前，于 Owner 队列/事务/门闩之外取得操作持有的共享槽位。凭证显式绑定实例、操作及本次执行，不凭相同操作编号自动复用，不授予数据权限。

准备、快照、文件处理、Owner 应用与必要恢复串行借用；交接前等待旧执行者真正结束，接收者确认才可开始。暂时无借用者时仍由操作持槽。不得借用中等待需要同一凭证的执行者；尤其禁止 Owner 等捕获线程、捕获线程等 Owner 的循环。拒绝重叠、错误、失效和已释放凭证，不无限等待。连接及游标不跨线程，原创建/关闭归属不变。

EOF 后禁止新普通业务阶段；已产生的必要核验/回滚/恢复/释放使用既有凭证，不重向失效通道取槽。正常 I/O 仍收费及响应取消，必要收尾保留原例外但不扩大到整个操作。等待者取消不等于执行者结束；只有真实资源关闭和原协议收尾完成后可释放。无法确认时保留占用并报告，不超时抢占或自动回收。

强杀使旧凭证失效；重启按管理日志、提交证据及跨进程锁核验，不恢复凭证、不重放或重做。§7/§8 停止与恢复、plugin-versions.metadata 规则不变。真实调用链、真实进程及资源释放验收见主规格；原 bridge 失败不删改、不延长期限。性能与正式审查预算不变。
