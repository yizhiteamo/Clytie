# C 漫画工具与漫画简报

状态：草案。方向由用户逐项确认（2026-11-25），合并本文档即确认细节。本期实现 C1 漫画工具（第 1–9 节）。C2 漫画简报（第 10 节）在 C1 合并后实现。决策记录见 ADR 0039。

她能把一件事画成多格漫画：自己当主角，需要时让角色表里的角色出场。每日一报可以做成漫画，由她播报新闻。

## 1. 范围

- 能力插件 `comic-maker`：工具 `draw_comic`、角色表、字体库、页眉页脚（第 2–7 节）。
- `image-gen` 新增服务 `image.render`：带参考图画图，供其他插件调用（第 8.2 节）。
- 本体：
  - 新权限 `appearance.read`：插件可以读取本伴侣当前的形象资料（第 8.1 节）；
  - 能力之间的服务调用：带上调用方的上下文，并把资产交给被调用方（第 8.2 节，platform-capabilities-spec §3 的规则第一次实现）；
  - SDK 0.20（第 8.3 节）。
- 不做：
  - 画完后由她看图核对、错字重画（要等 V6"自己画的图直接可见"或"插件调用模型可以带图"）；
  - 由程序把台词排进对话框；
  - 两位伴侣同框（第二位伴侣上线时再定）；
  - 动态漫画、视频；把漫画发到 QQ 空间等动态（以后的"她的动态"）。

## 2. 风格基线（来自用户提供的参考漫画，2026-11-25）

- **版式**：竖长页，约 2:3（1024×1536）。每页 6–9 格，每行 1–2 格，格子宽窄不一；包袱或高潮用全宽格或特写。
- **叙事**：日常小剧场，铺垫 → 发展 → 反转或吐槽。每页 2–3 个角色；同一场景的背景前后一致。
- **角色**：Q 版二次元，每个角色有固定的标志，例如发色、头饰、尾巴或翅膀、服装配色。
- **文字**：对话框里是短句，一般不超过 2 行，每行约 6–8 字。拟声词直接画在画面里。
- **画风**：浅色、干净的线稿，平涂，有表情符号和效果线。
- 插件配置 `style` 保存默认的画风说明，用户可以改；她在分镜里也可以指定这一次的画风。

## 3. 工具 `draw_comic`

- 能力插件 `comic-maker` 提供，清单标为 `heavy`。
- **参数**（她先写分镜，插件负责画）：
  - `title`：漫画标题；
  - `pages`：至少一页。每页有 `panels`，至少一格。每格写：
    - `scene`：场景和动作；
    - `characters`：出场角色，`self` 表示她自己，其余写角色表的 ID；
    - `dialogue`：台词，每句有说话人和短句；
    - `sfx`：可选的拟声词；
  - `style`：可选，这一次的画风。
- **上限**（防故障，可以配置）：每次最多 10 页，每页最多 10 格，每句台词最多 30 字。页数和格数按内容决定，不固定四格（用户 2026-11-25）。
- **校验**：在画第一页之前校验整份分镜，任何一项不通过就整体拒绝，不产生画图费用，并说明是第几页、什么原因（实现时补充，2026-11-25）：
  - 角色 ID 必须在角色表里，并且允许在当前会话使用；
  - 用了 `self`，伴侣却没有形象资料时，拒绝并说明原因；
  - 超出上限时拒绝，不截断。
- **画法**：
  - 每页整页一次画出。对话框和台词由画图模型直接画，同参考漫画；
  - 每页附上这一页出场角色的参考图；从第二页起，再附上一页作为画风参考；
  - **参考图超过每页上限时**（`image.render` 每次最多 8 张；实现时补充，2026-11-25）：不拒绝，按下面的顺序挑选，挑满为止：
    1. 第二页起，上一页（1 张）；
    2. 每个出场角色各 1 张主参考图，按角色在这一页第一次出场的先后；
    3. 剩下的名额按同样的先后轮流分配：每个角色的第 2 张、第 3 张……
    - 每个角色的参考图顺序：`self` 按 `appearance.yaml` 的顺序；角色表按导入的顺序，第一张是主参考图；
    - 一页出场的角色太多，有角色一张参考图也分不到时，它只按外观描述来画；工具结果中写明哪一页、哪个角色没有附上参考图；
  - 提示词由插件按分镜、风格基线和角色的外观描述生成，并要求每格的分格、对话框和台词与分镜一致；
  - 尺寸用竖版 1024×1536，画质沿用 `image-gen` 的配置；
  - 一页画失败时，这一次整体失败，已经画好的页不发出。她可以照实说，或者稍后重画。
- **结果**：
  - 按页的顺序返回图片资产；
  - 工具结果写明一共几页、每页出场了谁，不复述台词；
  - 她再配一段自己的话，和图片一起发出（agent-spec §3.5）。
- **工具说明中写明的规则**（她能看到）：
  - 台词要短；准确的事实，比如数字、产品名、来源，写在配的文字里，不放进对话框；
  - 不画真人的长相，用文字或剪影代替（第 6 节）；
  - 角色只能从角色表和 `self` 中选。

## 4. 角色

### 4.1 主角：她自己

- `self` 用本伴侣的形象资料：`appearance.md` 的描述，加上状态为"当前"的参考图（appearance-spec §3）。插件通过 `appearance.read` 读取（第 8.1 节）。
- 主角不写死任何形象。换了人设或形象资料，重启伴侣后，主角就跟着变。
- 没有形象资料时，不能用 `self`，其余照常。

### 4.2 角色表

- 由 `comic-maker` 保存，存在插件数据和资产库中。仓库里只有机制和虚构示例，具体角色都在实例里。
- 每个角色有：
  - ID：小写字母、数字和连字符；
  - 名字；
  - 关键词：在新闻里怎么认出它，例如公司名、产品名；
  - 外观描述；
  - 最多 6 张参考图；
  - 可选的出处署名；
  - 可选的会话限制：只允许在哪些会话使用。不写就是都可以（用户 2026-11-25 确认不限私聊）。
- **导入**：用户通过 `comic-maker` 的 CLI 命令导入，命令调用插件的本机 API。参考图的检查同 appearance-spec §3.4：格式、像素、大小，以及完整解码。导入时提示："参考图会随画图请求发给画图服务商。"
- 二创角色的参考图由用户提供。用户已知晓二创可能涉及原作者的权利，自行决定在哪里使用。

### 4.3 角色表段落

- `comic-maker` 提供一个上下文段落：列出当前会话可以用的角色名字和关键词，并说明有没有 `self`。预算 300 字，超出时只列名字。
- 只在 `draw_comic` 对当前说话人可用时提供（主动开口时，按 `proactive.tools` 判断）。
- 怎么判断（实现时补充，2026-11-25）：
  - 段落在清单中声明 `when_tool: "draw_comic"`。宿主只在这次请求最终交给模型的工具中有 `draw_comic` 时，才调用这个段落；否则根本不调用。这样判断的依据和她实际能用的工具完全一致；
  - `ContextRequest` 新增 `has_appearance: bool`：本伴侣有没有可用的形象资料（有描述或"当前"参考图任一项）。段落处理器只拿到这个真假值，拿不到描述和参考图，读取形象仍然只能在工具调用中用 `appearance.read`（第 8.1 节）。

## 5. 字体库与页眉页脚

- 用户通过 `comic-maker` 的 CLI 命令导入 TTF 或 OTF 字体，并指定用途：`title`（标题）、`caption`（说明）、`sfx`（预留给以后的程序排版）。
- 导入检查：
  - 能被字体库正常读取；
  - 单个文件最多 30 MB；
  - 必须包含常用简体中文字符；
  - 导入时请用户确认字体的许可证允许这样使用。
- 仓库不内置字体文件。插件 README 给出推荐清单，都是 SIL OFL 许可证：
  - 思源黑体（Noto Sans CJK SC）：标题、说明，最稳妥；
  - 资源圆体：圆润，适合对话风格；
  - 霞鹜文楷：手写感，适合旁白；
  - 站酷快乐体、站酷庆科黄油体、得意黑：适合标题。
- **页眉页脚**：有 `title` 和 `caption` 字体时，程序在每页上方排标题和"第 N 页"，下方排日期，以及配置的说明文字（例如"内容来自公开报道"），可以关闭。没有导入字体时不排，漫画照常画。
- 程序排版只用于页眉页脚。台词由画图模型画在画面里（第 3 节）。

## 6. 真人

- 不画真实人物的长相。真人只用文字提到，或者用不露脸的剪影代替。
- 角色表里不能登记真人的照片。导入检查无法识别是不是真人，所以由导入时的提示和工具说明约束。画图服务本身也会拒绝一部分真人请求。
- 新闻中的真人：让主角或角色表里的角色转述，不画本人。

## 7. 使用范围和费用

- `draw_comic` 是 `heavy`。保障模式下只有主人能用（agent-spec §5）。
- 默认只有主人能用。群友默认不开放，主人可以在 `permissions` 和 `tool_scopes` 中开放。
- 主动开口时，按 `proactive.tools` 的每天次数，建议 `draw_comic: {daily: 2}`。
- 每页一次高质量画图，约 30–90 秒；三页的漫画约 2–4 分钟。普通聊天中照常显示任务表情（kernel-spec §13.5）。
- 每页的画图记在同一条记录下（第 8.2 节）。

## 8. 本体与 SDK

### 8.1 插件读取形象资料：`appearance.read`

- 新权限 `appearance.read`。插件可以读取本伴侣当前的形象描述和状态为"当前"的参考图。只读，不能修改。
- 读取得到的参考图是临时引用，只在这一次工具调用中有效，过后再读会被拒绝。插件拿不到可以长期保存的资产 ID。
- 启用插件时逐项列出这个权限，由用户确认，并写明"参考图会随画图请求发给画图服务商"。
- 这修改了 appearance-spec §8 原来"画图插件读不到参考图"的规定，与 vision-spec §9 V3"插件使用图片"走同一个入口：临时引用、只在本次调用有效、按使用范围检查。

### 8.2 能力之间的服务调用

platform-capabilities-spec §3 的规则这一期第一次实现：

- 服务在清单中声明 `context: true` 时，宿主在调用它的处理函数时多传一个 `call`：这次服务调用来自哪条记录、说话人（可以为空，例如主动开口）、会话，以及取消令牌。没有声明的服务不变。
- 服务在清单中可以声明 `scope_as`：一个本插件的工具名。宿主先按调用方这次工具调用的说话人和会话，检查这个工具的权限和使用范围（`permissions`、`tool_scopes`、保障模式）。不允许时，服务调用返回 `denied`，不调用处理函数。
- **资产**：
  - 调用方在参数中给出的资产引用，必须是调用方这次能读的；
  - 宿主把它们交给被调用方，只在这次服务调用中可读；
  - 被调用方返回的资产，调用方在这次工具调用中可读。
- **记账**：被调用方产生的用量、产物和审计，记在调用方这次工具调用所属的记录下。取消用同一个令牌。
- `image-gen` 新增服务 `image.render`：
  - 声明 `context: true`、`scope_as: "draw_image"`；
  - 参数：提示词、参考图资产（最多 8 张）、尺寸（`1024x1024`、`1024x1536` 或 `1536x1024`）；
  - 返回一张图片资产。画质沿用 `image-gen` 的配置；带参考图时使用画图接口的参考图输入，具体接口以官方文档为准，在 PR 中写明依据。

### 8.3 SDK 0.20

- 新权限 `appearance.read`，对应 `ctx.appearance.current() -> {description, references: list[AssetRef]}`。
- 服务清单新增 `context`、`scope_as`；处理函数在 `context: true` 时多收一个 `call`。
- 上下文段落的清单新增 `when_tool`（本插件的一个工具名），`ContextRequest` 新增 `has_appearance: bool`（第 4.3 节）。
- 都是新增，已有插件不用修改。

## 9. 验收（C1，离线）

1. 分镜：
   - 参数校验；三项上限；未知角色、会话不允许的角色、没有形象资料却用了 `self`，都被拒绝并说明原因；
   - 超出上限时不截断。
2. 画图：
   - 每页附上这一页出场角色的参考图；从第二页起附上一页；超过 8 张时按第 3 节的顺序挑选（两个角色各 6 张时，上一页 1 张、各自主参考图 1 张，再轮流补满）；分不到参考图的角色在工具结果中写明；
   - 整份分镜在画第一页之前校验，任何一页不通过就整体拒绝，没有画图调用；
   - 提示词包含分镜、风格和外观描述；
   - 一页失败时整体失败，不发出已经画好的页；
   - 多页按顺序作为资产返回，并按顺序交付。
3. `appearance.read`：
   - 未声明权限时读不到；
   - 临时引用过了这次调用就不能再读；
   - 只读到状态为"当前"的参考图；
   - 没有形象资料时返回空。
4. 服务调用：
   - `context: true` 时处理函数收到正确的记录、说话人、会话和取消令牌；
   - `scope_as` 按调用方的说话人检查，不允许时返回 `denied`，处理函数没有被调用；
   - 资产只在这次调用中可读；
   - 用量和产物记在调用方的记录下；
   - 取消时一起取消。
5. 角色表和字体：
   - 导入检查，包括格式、大小、像素，字体的中文字符；
   - 会话限制；角色表段落的内容和预算；`draw_comic` 不在本次工具中时不调用段落处理器；处理器只拿到 `has_appearance`，拿不到描述和参考图；
   - 页眉页脚：有字体时排版，没有字体时跳过，可以关闭。
6. 工具说明中有台词要短、不画真人长相、只用角色表的规则。
7. 文档同步：`plugins/catalog.md` 加入 `comic-maker`，CHANGELOG 记录 SDK 0.20。双平台 CI 通过，线上画图调用为 0。

上线：合并后经用户当次同意部署；在测试群请她画一个两页的小漫画做真实检查。

规模预估：6–8 天。

## 10. C2 漫画简报（C1 合并后实现）

- 每日一报时，同时满足以下条件，`proactive-chat` 在交给她的说明中加一句"可以把每日一报做成漫画"：
  - 本伴侣有形象资料；
  - `draw_comic` 列在 `proactive.tools` 中，当天次数没用完。
- 说明内容：
  - 她当主角播报；
  - 新闻涉及角色表里的角色时，让它出场；
  - 漫画里只放简短台词；准确的事实和链接写在配的文字里；
  - 不画真人长相。
- 做不做漫画由她决定。条件不满足时，每日一报照旧只发文字（content-spec §10.5）。
- 大新闻仍然只发文字，因为画漫画要几分钟。
- 验收（离线）：满足条件时提示做漫画，不满足时不提示；漫画失败时她仍然可以只发文字。

规模预估：1–2 天。
