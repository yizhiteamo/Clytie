# 记忆回想与印象实现规格（A3.4：回想整理、群里看到的事、群友印象、软遗忘、黑话）

本文件是 A3.4 的实现契约，在 `memory-spec.md`（A3.3）之上增加功能，不改变 A3.3 中"用户已确认"的规则。标注"用户已确认"的条目不能在实现中改变。细化 `design/memory.md` 第 5–8 节。实现中如有歧义，先只读询问 Claude，涉及需求或隐私的登记 Issue 并停下。

目标沿用 A3.3：记忆要最自然。A3.3 让她当场记住要紧的事；A3.4 让她像人一样**过后回想**：聊完一段之后想一想刚才发生了什么，记得群里和主人一起经历的事，对常见的群友有印象，久远的群里小事慢慢淡，被想起的事记得更牢。

- 测试一律使用临时实例目录、假模型、假向量模型、MockClock 和虚构数据。不下载模型，不读真实实例或记忆库，不调用线上模型。
- **不回溯历史**：A3.4 上线、导入或恢复之后，回想只处理之后的新对话，不自动把以前的账本整段拿去回想（第 2.6 节）。

## 1. 总原则

1. **事实只来自主人自己的话。** 回想和印象写出的记录一律是 `basis = observed`，排序在主人亲口说的之后，永远不进核心记忆（memory-spec §5.1 的核心记忆只取 `owner_confirmed` 和 `owner_stated` 的偏好）。
2. **别人说的关于主人的话只能记成"某人说过某话"**（memory-spec §2.4）。在结构上保证：群聊窗口的回想**不能**写 `fact`、`preference`，只能写 `episode`、`profile`、`jargon`（第 2.3 节）。所以群友的话永远不会变成关于主人的事实，也改变不了她对主人身份的认识。
3. **每条经历都要有出处。** 回想写出的经历必须引用窗口里的具体消息，本体逐条核对（第 2.4 节）。没有出处的经历不写入，防止她"回想"出没发生过的事，避免破坏 L6。
4. **投影和来源限制照旧。** 新记录同样受 memory-spec §3 的可见等级和来源会话限制；回想和印象只能读到所在会话投影内的记忆。
5. **背景运行，不打扰聊天。** 回想在会话安静下来之后才进行，不占用回复，不会让她在聊天中途停下来。失败只记 WARN，不影响聊天。

## 2. 回想整理（经历）

### 2.1 什么时候回想

- 一个会话在 `memory.recollect.idle_minutes`（默认 30 分钟）内没有新的入站和出站消息，并且上次回想之后有新消息，就对这段新消息做一次回想。
- 只回想**主人私聊**和**群聊**。陌生人私聊不回想。
- 如果群聊窗口里主人和她都没说话，也没有人回复或提到他们俩，就**不调用模型**，直接推进进度（第 2.6 节）。
- 同一会话每天最多回想 `memory.recollect.daily_limit` 次（默认 12）。超出的部分并入下一次。
- 窗口文字超过 `memory.recollect.window_chars`（默认 12000 字）时按时间切成几段，逐段回想，每段单独提交。
- 账本中暂停期间入账的消息（agent-spec §7.3）和 `dropped_on_restart` 不参与回想，与"最近任务"的规则一致。
- 用户已确认（D1）：只用安静触发，不另设每天固定时间。

### 2.2 谁来回想

- 回想由本体调度，调用 `memory.consolidator` 扩展（sdk-spec §5.6）。本体负责选窗口、投影、核对出处、写入；扩展只负责"看完这段，写下值得记的"。
- 仓库自带一个默认实现（内置插件），用她的人设回想，所以经历是她自己的语气。模型调用照常记审计和额度。
- 用户已确认（D2）：回想默认使用伴侣配置 `model` 中当前的聊天模型，**跟着聊天模型走**：主人更换聊天模型（例如以后接入的 Codex CLI 插件及其中的模型）时，回想自动随之更换，不需要另改配置。只有配置了 `memory.recollect.model` 时才使用另一个模型。更换模型不影响记忆库。
- 扩展签名在 sdk-spec 中扩展为兼容版本：
  `async run(window: RecollectWindow, reader: CandidateReader, cancel) -> list[RecollectItem]`
  - `RecollectWindow`：会话场景、按顺序编号的消息（`[消息N] 说话人称呼：原文`）、她在这段里已经用 `core_remember` 记下的记忆。这段里用 `core_forget` 撤销的记忆**不交给扩展**，原文、编号都不提供，只提供撤销的条数（用户已确认，Issue #35 U2：撤销后任何上下文都看不到，回想也不例外）。主人说"别记这个"的原话本来就在窗口消息中。
  - 窗口中的聊天原文**保持原样**（用户已确认，Issue #36 P1）：撤销表示她不再从记忆中想起这件事，不删改聊天记录。"不提供撤销原文"指不从撤销记录派生任何内容或编号；聊天消息中本来就有的相同文字不遮盖、不删除。
  - `reader`：本会话投影内的已有记忆，用来避免重复、发现应该合并的条目。
  - `RecollectItem`：`kind`、`content`、`visibility`、`evidence: list[消息编号]`，以及可选的 `about`（印象对应的说话人）、`merges`（建议合并的 `[记忆N]`）。
  - 旧签名 `run(window_start, window_end, reader, cancel)` 尚无实现，直接替换，写入 CHANGELOG。

### 2.3 能写什么

| 窗口 | 允许的 `kind` | `visibility` 缺省 | `origin_conversation_id` |
|---|---|---|---|
| 主人私聊 | `episode`、`event`、`fact`、`preference` | `private` | 主人私聊 |
| 群聊 | `episode`、`profile`（第 3 节）、`jargon`（第 5 节） | `memory.recollect.group_visibility`（默认 `relationship`） | 这个群 |

- 全部 `basis = observed`，`source_type` 按窗口：私聊为 `private`；群聊中主人或她参与的为 `owner_group_interaction`，其余为 `group`。
- 私聊回想可以补记她当场漏记的事实和偏好（主人说过、她当时没记）。因为是 `observed`，主人以后亲口确认时会按 memory-spec §1.3 升级。
- **群里看到的事只记和主人或她有关的**：主人参与的、她参与的、有人对主人或她说的、在说主人或她的。和他们俩都无关的群聊不写经历，最多更新群友印象和黑话。
- 别人说的关于主人的话写成带说话人的经历，例如"小林在群里说主人周末去爬山了"，不写成"主人周末去爬山了"。
- 群聊经历涉及主人时，本体加保留标签 `core:with_owner`；只有当出处中至少有一条是主人发的消息，或者是直接回复、提到主人的消息时，才允许加这个标签。这个标签决定不淡化（第 4.1 节）。
- 主人在这段里说过"不用记""别记这个"的内容不写入（写进回想的规则）。
- 本体在内部拦截与撤销内容重复的条目（用户已确认，Issue #35 U2）：与这段里 `core_forget` 撤销的记忆规范化后相同的丢弃；配置了向量模型时，与撤销内容的余弦相似度大于 `memory.recollect.retracted_similarity`（默认 0.85，真实模型选型时校准）的也丢弃。比对只在本体内进行，撤销原文不进入回想扩展、对话模型、日志和审计，审计只记"因与撤销内容重复丢弃 N 条"。同义改写仍可能漏过，这是已知限制。
- 语义比对的向量（用户已确认，Issue #36 P2）：
  - **有限例外**：只有伴侣配置 `memory.embedder` 指定的向量模型可以接收撤销原文，仅用于这次比对。优先复用同一 `embedder_id` 的已有缓存向量；没有时临时计算，结果不写入向量表、不缓存、不写日志。其他插件和模型都拿不到。这个向量模型在写入时本来就处理过这条记忆，不增加新的泄露途径。
  - **做不了就退一步**：没有配置向量模型、向量模型出错或超时、候选向量计算失败时，这一段只做规范化相同的比对，回想照常写入并推进进度；`status` 显示不含原文的提醒（"有 N 次回想没能做语义比对"），日志 WARN 每小时最多一次。不使用其他 `embedder_id` 的旧向量。
- 每次回想最多写 `memory.recollect.max_items`（默认 8）条，`content` 每条不超过 300 字。
- 用户已确认（D3）：群聊经历的缺省可见等级可以配置，默认 `relationship`。来源限制已经保证群里的经历只在这个群和对内场景出现；敏感的由模型标 `private`。

### 2.3a 私聊经历在群里（用户已确认）

主人可能在别的群里说起和她私聊时的事，她应该能附和。不新增投影规则，按 A3.3 的可见等级实现：
- 本体规则和 `core_remember` 的 `visibility` 说明中写明三档的含义：`relationship` 是"你们之间、可以在别人面前提的事"（一起做过的事、她给主人起的外号等）；`private` 只用于不能对外说的（身体状况、家里的事、秘密、主人交代过不要说的）；`public` 是谁都可以知道的。日常共同经历用 `relationship`，真正拿不准时仍用 `private`（A3.3 规则不变）。回想写私聊经历时按同样的含义选择。
- 主人说"这个可以在群里说"时，她用 `core_remember` 的 `replaces` 把那条记忆改为 `relationship`；说"这个别在群里提"时改为 `private`。写进本体规则。
- `memory.private_scenes` 的规则不变（用户已确认，Issue #35 U1）：只能包含成员只有主人和本部署伴侣的对内场景（如家庭群），有外人的普通群不能加入。它按场景整体开启，开启后这个场景的所有会话都能看到私密记忆、人设私密段落以及 kernel-spec §13.1 可见的主人私聊账本。在普通群里说私聊的事，靠 `relationship` 等级和主人的口头修订实现。
- 群里不当面否认，见第 7 节。

### 2.4 本体核对（不通过的条目丢弃，记审计，不重试）

1. `kind` 必须在第 2.3 节的表内。
2. `evidence` 至少一条，编号都在本窗口内。
3. `core:with_owner`、`about` 必须与出处中的说话人相符。
4. `merges` 指向的记忆必须在本会话投影内可见（第 2.5 节）。
5. 与已有可读记录按 memory-spec §1.3 去重。命中时不新建。
6. `source_ref` 写入窗口第一条和最后一条消息的追踪号，可以追溯，不对外暴露。

### 2.5 合并近似重复

- 回想可以建议把几条说同一件事的记忆合并。本体只在**全部是 `observed`** 的记录之间执行合并：保留最早的一条，把内容修订为合并后的说法，其余撤销，撤销原因写"并入另一条记忆"。修订和撤销都保留在修订表中。
- 只要有一条是主人说的（`owner_confirmed`、`owner_stated`），后台就不动它们，只能由她在聊天中用 `replaces` 修订。主人亲口说的话不会被后台改写。

### 2.6 进度、防重和取消

- 每个会话保存一条回想进度：已回想到的最后一条消息（账本序号）。写入经历和推进进度在**同一个事务**中完成：要么都成功，要么都不发生。
- 进程中途退出时，没提交的回想作废，下次从原进度重新回想。已提交的不会重复回想。
- 关闭、暂停、取消时发出取消信号；回想中途取消不写入。
- 进度是本机状态，**不进入导出包**。新实例、导入或恢复后某会话还没有进度时，从"现在"开始，不回想以前的账本。
- `status` 显示：各会话最近一次回想的时间、结果（写了几条、丢弃几条），以及失败计数。

## 3. 群友印象

### 3.1 内容

- 每个群友一条 `kind = profile` 的记录，`subject` 是对方的 `actor_id`，`basis = observed`，不超过 200 字。
- 只记公开、无害的内容：她怎么称呼对方、对方说话的风格、对方和她平时怎么互动。
- 用户已确认（D4）：可以记泛泛的兴趣（"喜欢聊游戏"），不记具体事件；具体事件只作为那个群的经历。
- 不给主人建印象；主人的事走事实、偏好和经历。其他伴侣也作为群友处理。
- 印象只在群聊回想中更新：这个人在窗口里说过话才更新，没有新内容就不调用模型、不修订。

### 3.2 在哪里用（design/memory.md §6：跨群共享，使用时不提来自哪个群）

- 印象是例外的**跨群记录**：`origin_conversation_id = null`，另加保留标签 `core:profile`。投影规则：
  - 对内场景：都可见。
  - 群聊：只有当本批次的说话人、被引用的消息作者或被提到的人就是这位群友时，才注入这位群友的印象。
  - 陌生人私聊：不可见（与 A3.3 一致）。
- 注入时不带来源群，规则中写明"不要提起是在哪个群认识的"。
- 用户已确认（D5）：印象跨群共享，依靠"只记无害内容"和"只在对方在场时出现"控制风险。

### 3.3 删除

- 只有主人能删：主人私聊中她用 `core_forget` 撤销（第 4.4 节的冻结记忆同样可以），或者以后的 WebUI。
- 群友说"忘掉我"时，她用自己的口吻带过。群友本来就没有写入和撤销工具（memory-spec §2.1），这一条已经在结构上成立。

## 4. 软遗忘与"想起即加深"

### 4.1 谁会淡

| 永不淡化 | 会慢慢淡 |
|---|---|
| 主人私聊来源的一切记录及其衍生 | 群聊经历中不带 `core:with_owner` 的 |
| `owner_confirmed`、`owner_stated` 的记录 | 群友印象 |
| 带 `core:with_owner` 的群聊经历（主人和她一起经历的事） | 黑话 |
| 对内场景（如家庭群）来源的一切记录，包括其中的经历和黑话 | |

由本体按 `basis`、来源会话、`kind` 和保留标签判定，模型和插件不能改。

- 同时命中两栏时**永不淡化优先**（用户已确认，Issue #35 U3）。
- 群友印象是跨群记录（`origin_conversation_id = null`，第 3.2 节），不属于任何场景来源，一律按"会慢慢淡"处理。

### 4.2 怎么淡

- 每条会淡的记录有两个状态：上次被想起的时间 `last_recalled_at`（初始为创建时间），以及半衰期 `half_life_days`（初始为 `memory.fade.half_life_days`，默认 30 天）。
- 淡化程度 `weight = 0.5 ^ (距上次想起的天数 / half_life_days)`，在读取时按当前时间计算，**不需要定时任务改写记录**。
- 检索排序（memory-spec §4.1 第 5 步）：最终分数为融合分数 ×（0.5 + 0.5 × weight）。永不淡化的记录 weight 视为 1。
- `weight` 低于 `memory.fade.freeze_below`（默认 0.1）时视为**冻结**：不再自动带进上下文。

### 4.3 想起即加深

- 一条会淡的记录被带进上下文（第 5.1 节的"想起的记忆"），或出现在 `core_recall` 结果中，就算被想起：`last_recalled_at` 更新为现在，`half_life_days` 乘以 `memory.fade.reinforce`（默认 1.5），最多到 `memory.fade.max_half_life_days`（默认 365）。
- 越常被想起，忘得越慢，这与人的记忆相似。

### 4.4 冻结与恢复

- 冻结的记录不被自动想起，但**她主动回想时还能想起来**：`core_recall` 在正常结果之后附上匹配度高（语义分数在 `memory.semantic_min_similarity` 之上并且关键词命中）的冻结记录，最多 3 条，标注"很久以前的事，记不太清了"。被这样想起后解冻，并按第 4.3 节加深。
- 主人可以在以后的 WebUI 中恢复冻结的记忆；A3.4 提供本体接口和 CLI，不提供界面。
- **永不自动删除**。冻结只是不主动想起，不是删除。

### 4.5 存储

- 淡化状态是单独的表，以记录 ID 为键，**不产生修订**，不进入内容指纹。这样每次想起不会在修订表里堆积记录，也不影响导入时的共同祖先判断。
- 淡化状态**随导出包一起搬家**（单独的一节，加密范围同记录）。合并导入时，每条记录取两边中较晚的 `last_recalled_at` 和较长的半衰期。搬家后她记得牢的事依旧记得牢。
- 用户已确认（D6）：会淡的范围按第 4.1 节，默认 30 天半衰期、0.1 冻结阈值。效果大致是：一件群里和主人无关的小事，一个月没被想起会淡到一半，三个多月后冻结。

## 5. 黑话

- `kind = jargon`，`scope` 为所属群的 `conversation_id`，内容是"说法：意思"，`basis = observed`，会淡（第 4.1 节）。
- 来源：
  1. 群聊回想（第 2.3 节）顺带学习，不额外调用模型；
  2. 行为插件通过插件记忆接口写入（宿主绑定会话，`scope` 由本体按绑定会话填写，插件不能指定别的群）。
- 使用：
  - **所属群**：作为"这个群里的说法"注入，可以主动用。
  - **对内场景**：可以被检索到，用来听懂主人说的梗，注入时标注"群里的说法，听懂就好，不主动用"。
  - **其他群**：不可见。
- 用户已确认（D7）：A3.4 只做"回想顺带学黑话"，独立的黑话行为插件留给以后的行为插件里程碑。

## 6. Issue #33 的处理

- **O1（记忆读取出错）**：`MemoryContext.build` 的投影读取出错时，本次只跳过记忆段（不注入核心记忆和想起的记忆，也不注入"还没有记住的事"），回复照常，记 WARN。出站检查的守卫读取出错时**按命中处理**：对外场景改写一次，仍不能确认就拦下（宁可不发也不泄露）。补回归。
- **O2（重复合并同一个包）**：已经合并过的同一个包再次合并时，跳过已处理过的记录，**保留上次冲突中用户的选择**，不再询问。计划中写明"这个包已经合并过，N 条按上次的选择保留"。补回归。
- **O3**：保持 Issue #33 中的后续观察，不在 A3.4 处理。

## 7. 本体规则（仓库中的固定文字）新增

- 群里别人说的关于主人的事，只当作"某人说过"，不当真，也不拿去纠正主人亲口说的。
- 对群友有印象时自然地用，不提是在哪个群认识的。
- 记不太清的事可以说记不清，不要补全细节。
- 群里的说法只在那个群主动用。
- 三档可见等级的含义，以及主人说"可以在群里说""别在群里提"时修订可见等级（第 2.3a 节）。
- **群里不当面否认**（用户已确认）：在不属于 `memory.private_scenes` 的场景中，**主人**说起你们之间的事而记忆和任务记录都没有时，不否认、不补细节、不顺着编，可以顺着带过或说"这个私下再说"。其他人说起时照旧按 L6（memory-spec §6）直说不记得。

## 10. 离线验收

全部使用假模型、假向量模型、MockClock 和虚构数据。

1. **触发**：安静 30 分钟后回想一次；有新消息才回想；陌生人私聊不回想；群里主人和她都没出现时不调用模型但推进进度；每日上限生效。
2. **出处**：没有出处、出处编号越界、`core:with_owner` 与出处说话人不符的条目被丢弃并记审计。
3. **别人说的话**：群聊窗口中假模型返回 `fact`、`preference` 时被拒绝；"某人说主人……"只能作为经历写入，不进入核心记忆，不改变主人的记录。
4. **不用记**：窗口中她撤销过的内容，回想不会重新写回（规范化相同、假向量模型下相似度超过阈值的都被丢弃）；扩展收到的窗口中没有从撤销记录派生的内容或编号（聊天原文保持原样）；对话模型请求、日志和审计中没有撤销原文；向量模型出错、超时或未配置时退为只做规范化比对，回想照常写入并推进进度，`status` 有提醒；临时计算的撤销向量不写入向量表。
5. **合并**：只合并全是 `observed` 的记录；含主人记录时不动；修订和撤销可追溯。
6. **防重与恢复**：回想写入和进度推进是一个事务；模拟中途崩溃后重新回想不产生重复；取消时不写入；新实例或导入后不回想以前的账本。
7. **投影**：群聊回想读不到私密记忆；群聊经历在其他普通群不可见、在对内场景可见；私聊经历在群里不可见。
8. **印象**：只在对方在场（说话、被引用、被提到）时注入；注入文字不含来源群；群友没有写入入口；主人私聊中可以撤销；对方没说话时不调用模型。
9. **淡化**：MockClock 推进时间，会淡的记录排序下降，到阈值冻结；永不淡化的类别（含 `core:with_owner`、家庭群来源的经历和黑话）不受影响，群友印象照常淡化；淡化不产生修订。
10. **加深**：被注入或被 `core_recall` 命中后半衰期变长；冻结记录被主动回想命中时解冻。
11. **永不删除**：任意时间推进后记录都还在库中。
12. **黑话**：所属群可主动使用；对内场景标注"只听懂"；其他群不可见；插件不能写别的群。
13. **搬家**：淡化状态随导出导入保留；合并取较晚时间和较长半衰期；回想进度不进导出包。
14. **O1、O2**：投影读取出错时只跳过记忆段；守卫读取出错时按命中处理；重复合并同一个包保留上次的选择。
15. **规则**：本体规则包含第 7 节新增的条目，主人私聊和群聊的模型请求都有回归。
16. **私聊经历在群里**：`relationship` 的私聊记忆在其他群可见、`private` 的不可见；主人用 `replaces` 改可见等级后投影随之变化；群里主人说起而找不到时，模型请求包含"不当面否认"规则，群友说起时仍是 L6 规则。
17. **回想模型**：未配置 `recollect.model` 时回想使用当前聊天模型；更换聊天模型配置后回想随之更换；配置后使用指定模型。

真实模型的效果（回想写得是否自然、是否会把别人的话当事实、群友印象是否越界）在切换上线前用真实模型抽检，需要用户本次明确同意，并先给用户看测试用的虚构对话。
