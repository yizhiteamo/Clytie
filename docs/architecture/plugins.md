# 插件系统

目标：所有功能都是模块化插件，可以按伴侣启用和配置，可以在创意工坊中浏览、安装、更新和卸载，依赖关系自动解析。

## 1. 插件包

```
plugins/<id>/
├─ plugin.json      清单
├─ __init__.py      入口：注册扩展点实现
├─ ...              实现代码
├─ data/            自带的公开静态数据
├─ migrations/      私有状态的升级脚本
├─ tests/           离线测试（使用 sdk.testing）
└─ README.md        创意工坊详情页内容
```

官方插件在仓库 `plugins/` 中；从创意工坊安装的插件放在 `CLYTIE_HOME/plugins/<id>/`。

## 2. 扩展点（contribution points）

插件的"类型"只是分类标签，真正决定插件能做什么的是它声明的扩展点。一个插件可以同时实现多个扩展点（例如睡眠插件同时有行为扩展、定时任务、服务、状态卡片）。

| 扩展点 | 作用 |
|---|---|
| `channel` | 接入一个平台 |
| `model` | 提供一个生成模型 |
| `embedder` | 提供文本向量（记忆检索用） |
| `tool` | 提供一个给模型调用的能力 |
| `behavior.<环节>` | 在消息流程的某个环节施加影响（见第 3 节） |
| `context_section` | 向上下文贡献一段内容（有预算） |
| `schedule` | 注册定时任务（由本体调度器驱动） |
| `service` | 向其他插件提供一个具名服务（如 `sleep.state`） |
| `event_subscriber` | 订阅事件总线上的事件 |
| `memory.retriever` / `memory.importer` / `memory.consolidator` | 记忆检索器、导入器（如旧系统导入）、经历整理器 |
| `notifier` | 提供一种通知渠道（守护进程和边界保护用来通知主人） |
| `cli_command` | 新增一个 CLI 子命令 |
| `api_route` | 新增 API 路由（只读状态或插件自己的操作） |
| `webui_panel` | 在 WebUI 中提供状态卡片或页面 |
| `config` | 配置 Schema（WebUI 据此自动生成设置页） |

新增扩展点需要修改 SDK，按 `sdk.md` 的版本策略进行。

## 3. 行为环节

| 环节 | 用途 | 可返回的指令 |
|---|---|---|
| `message_received` | 消息进入后（已过防重和过滤） | 无（只观察、记录） |
| `before_attention` | 决定回应方式 | 正常 / 只回表情 / 简短回应 / 不回应 / 改为某种模式（如呓语） |
| `attention` | 说话时机 | 回应 / 不回应 / 延迟 N 秒后再判断 |
| `after_generation` | 回复生成后 | 拆分 / 改为卡片 / 附加引用 |
| `before_send` | 交付前 | 调整交付形式（不能改内容、不能绕过出站检查） |
| `task_completed` | 任务交付后 | 无 |

规则：
- 同一环节按优先级执行，同优先级按插件 id 排序，结果可复现。
- 多个插件给出冲突指令时，按本体定义的合并规则处理（例如"不回应"优先于"正常"），合并规则写在 SDK 中并有测试。
- 边界检查和出站检查在所有插件之后执行，插件无法跳过。
- 插件出错时记录日志并按清单中声明的安全默认值处理，不影响本体和其他插件。

## 4. 清单 `plugin.json`

| 字段 | 说明 |
|---|---|
| `id` | 小写加连字符，全局唯一 |
| `name` / `summary` / `category` | 显示名称、简介、分类（能力 / 行为 / 平台 / 模型 / 记忆 / 工具） |
| `version` | 语义化版本 |
| `requires.sdk` | 兼容的 SDK 版本范围 |
| `dependencies` | `{id: 版本范围}`，可标记 `optional` |
| `conflicts` | 不能同时启用的插件 |
| `contributes` | 实现的扩展点及其参数（工具描述、环节优先级、服务名、定时规则……） |
| `permissions` | 需要的权限（第 5 节） |
| `config` | 配置的 JSON Schema 及界面提示 |
| `data` | 私有状态的版本号、卸载时的处理（默认保留） |
| `failure_default` | 出错时的安全默认值 |

能力插件的工具描述包括：何时使用、**何时不用**、正反例（含否定、转述、讨论三类）、参数 Schema、适用对象、是否重任务、风险、交付方式。

## 5. 权限

| 权限 | 含义 |
|---|---|
| `memory.read.public` | 读取当前场景可见的非私密记忆 |
| `memory.read.private` | 读取私密记忆（只在私聊场景生效） |
| `memory.write` | 写入或修订记忆 |
| `message.proactive` | 主动发起消息 |
| `message.react` | 表情回应 |
| `peer` | 使用伴侣通道 |
| `model.invoke` | 自行调用模型（计入额度） |
| `network` | 访问网络 |
| `assets.write` | 写入资产库 |
| `subprocess` / `gpu` | 启动子进程 / 使用 GPU |

官方插件在伴侣进程内运行，权限通过 `ctx` 的接口范围控制。第三方插件开放前，需要另行设计签名、审核和进程隔离（SDK 的可序列化约束就是为此预留）。

## 6. 依赖与生命周期

```
发现 → 校验清单 → 安装 → (按伴侣)启用 → 配置 → 运行 → 停用 → 卸载
```

- 启用前解析依赖：缺少时给出补齐方案，确认后一并启用；版本冲突或 `conflicts` 时拒绝并说明原因；依赖必须无环。
- 停用一个仍被其他已启用插件**必需**依赖的插件时，分两步：
  1. **计划**：只读查询，返回将被连带停用的全部依赖方（包括间接依赖方），按依赖倒序排列。未确认时不做任何改动。
  2. **确认后执行**：调用方带上计划的标识确认后，宿主按倒序依次停用依赖方，最后停用目标插件。计划生成后如果依赖关系发生变化，计划失效，必须重新生成。
- 每次连带停用写一条记录（目标插件、连带停用的插件、时间）。重新启用目标插件时，宿主提示"上次连带停用了这些插件"，用户可以选择一并恢复。
- 本体模块不能停用，也不会被连带停用。
- 可选依赖方不阻止停用，只会收到"服务不可用"事件，继续运行。
- 配置按伴侣保存；支持热加载的插件立即生效，否则提示重启该伴侣。
- 升级前按 `data-and-backup.md` 第 4.2 节为插件私有状态生成加密快照，校验通过后再执行 `migrations/`；升级失败时自动恢复。
- 卸载默认保留私有状态和它写入的记忆；彻底清除需要用户单独确认，且只删除该插件自己的目录。
- 本体模块在创意工坊中显示为"本体"，不能停用或卸载。

## 7. 创意工坊

- 索引 `plugins/catalog.json` 由各插件清单生成（id、版本、简介、分类、依赖、权限、更新说明）。
- 先只提供官方插件；格式按以后可以加入第三方来源设计（来源地址、签名字段预留）。
