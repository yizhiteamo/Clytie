# A3.1 账本与交付实现说明

实现版本 0.4.0；所有运行测试均使用临时目录、手写假事件、假能力、假平台和 MockClock。没有真实平台连接、线上模型调用或真实实例数据读取。A3.2 的模型循环、出站过滤与完整对话链路不在本阶段。

## 验收清单

1. `test_kernel_service` 跑通入站、防重、能力领取、执行、封口、交付、收据、完成事件和状态表情；完成日志包含 trace、task、排队/执行/交付耗时。`test_kernel_migration` 验证任务摘要、完整内容、歧义和只读查询；CLI 只调用 API。
2. `test_kernel_ledger` 验证重启不重放、发送中转 unknown、不补发与迟到收据；`test_kernel_delivery` 验证有限重发、窗口、拆分组继续发送和挂起发送转 unknown；`test_kernel_service` 验证引用、编号、缺省三种取消选择、排除自身、权限与交付待完成时取消。
3. `test_kernel_service` 验证普通聊天不能直接加表情，声明例外后才允许；宿主检查 ReactOnly 权限。`test_kernel_reactions` 验证四态替换、合并、终态、无撤回、失败不重试、重启修正、适用范围。
4. L2 的统一聊天/任务账本与 L5 表情规则由上述回归覆盖；`test_kernel_scheduler` 验证事件隔离、递归/容量上限，以及调度漏点、顺序、不重叠、取消和夏令时。`test_kernel_short_lock` 用真实跨进程锁与 MockClock 验证另一伴侣的任务、Tick、取消照常推进。

## 技术澄清与边界

只读询问 Claude 后，采用本体 ContextVar 排除取消自身、后台空上下文、短锁取消后的恢复与审计、只读系统锁探测、按内容入账时间执行保留期。已补 kernel-spec 技术澄清，物理存储选择见 ADR 0005。Issue #16 的四态回应和 Issue #17 的固定周期范围已按用户决定实现，并各自独立提交规格与同步文档。

任务查询不开 HTTP 服务；不提供真实发送装配入口。迁移受阻的解除由用户按 status 提示操作，A3.1 不实现解除 CLI。模型、真实额度、完整边界检查在 A3.2；安全停止的全局编排在 A4。

本机完整回归第一轮为 580 项通过；之后补充的迁移加载表、保留期及表情权限定向回归 18 项通过。最终完整回归、双平台 CI、扫描与自动验收结果在 PR 中提供对应提交证据。
