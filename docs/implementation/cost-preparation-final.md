# 四 CPU 正式准备：成本假设定稿

这是正式运行前的工程估计，不是性能通过、执行授权或操作系统耗时保证。沿用 `plan-four-cpu-cost-02` 的 profiles、窗口、负载、预热与参数，不通过重新拟合 CPU、延窗或降低采样取得绿色结果。对应固定产品为 e4dfacca7e3493918ded15a82239139f8394e763；工具应在全部接线完成后另行固定。旧成本草案和失败证据不覆盖。

## 成本包络的解释

`measurement_fixture.setup` 只复制公开 examples/home，创建两个合法数据库、一个虚构 snapshot 插件和固定 payload。业务只读 records、更新 metadata，不追加业务记录。两库各六十四 KiB 页增长、生成元数据一 MiB、payload 之外六十四个归档成员及六十四个目录，确定为本计划的**工程余量**，不再标为等待测量才能选择的参数。

源码核对覆盖 fixture 的配置改写、plugin-versions 持久化、runtime_capture 的在线文件清单、source 的配置/人设/审计发布、deployment_capture 的限定目录以及 temporary 的注册和清理。成员类别包括两库、两配置、人设、虚构插件两文件、版本表、审计 rotation index；大资产另有 registry。管理操作 JSON、可选边界状态及审计段计入额外成员余量。插件生命周期恢复文件在捕获前有拒绝检查，不能当作任意成功归档文件；仓库 fake 插件是 repository 引用，不整棵复制进包。此夹具没有部署文档和配置历史。六十四不是声称逐次恰好有六十四个文件，也不是产品文件数上限；它为固定夹具的少量状态文件留出余量，不能推广到真实实例或任意插件。

临时收据按实际 schema 计算：路径键、identity 的 device/inode、state，文件另有 size/sha256。正常成功路径注册文件数 `N=2n+2`，目录数 `K` 按祖先去重；保存次数 `2N+2K+6`。沿用每文件一 KiB、每目录七百六十八 bytes 的条件包络：要求 JSON 转义后的完整路径不超过五百一十二 bytes，非负 identity/size 整数每项最多二十位。状态字符串和字段标点、散列在剩余额度内。路径条件是估计适用范围，不是已测得的所有 runner 路径事实；执行接线使用短 ASCII 工作目录，不扩大或改动产品路径协议。若平台实际布局超出该条件，记录估计失配，不能无声声称原包络仍成立。

`TemporaryArtifacts._save` 的完整状态反复写入不走令牌预算；每次 atomic_write 一次 fsync，Windows replace 重试不重新计算一份 payload 写入。收据累计写量使用最大状态乘保存次数的宽松包络，多小文件约三十五 GiB，**不是同时占用磁盘量**。预算内工作保持 `12D+8A+8F+2P`；直接内容工作与收据单列，避免重复计费。容器仍使用既有格式包络；清单不再重复算为普通文件。

固定 reserve：startup 三十秒；native 为三十秒与历史 pack/verify 阶段最大值之和十倍中的较大者，再加每百条记录一秒；fsync 每次五十毫秒；release 一百二十秒及收据写量按每秒十六 MiB；backlog 三百秒。native 内部读页仍未知，不填零，不拿文件大小冒充实测；旧组件只是量级锚点。所有服务时间是预先选择的估计，不是最低吞吐、期限豁免或新产品限速。实际失败仍失败。

## 作业时间分配

每个平台四规模、三组，共二十四个四臂 job。每臂新进程，结束并释放后才启动下一臂，不能在父进程保留四套 Recorder。每 job 六百秒用于 checkout、安装、版本/来源和准入核对；每臂六百秒用于独立造数与预热，另六百秒用于原件验证、封存、散列、上传及交接。共额外五千四百秒。下列分配是工程预算，不另设截断原件或抢占原生 I/O 的新期限。

| small_text | 251.975 | 2207.9 | 7607.9 | 13 992.1 |

| many_small_files | 3261.525 | 14 246.1 | 19 646.1 | 1953.9 |

大库造数预算六百秒相当于约每秒五十五条完整记录，包含 `_save`、临时索引移除、VACUUM 和合法性统计的工程假设；不是已测得速率。原件最高加量估计约六百六十五 MiB，六百秒后处理相当于约每秒一点一 MiB 的端到端处理余量，实际还包括多次扫描及网络等待；不是上传服务保证。四臂 maximum 已包含每臂三百秒积压，不能再把同一余量挪作 setup。

全矩阵窗口及积压约 58.698 runner 小时，以上额外分配三十六 runner 小时，合计约 94.698；二十四 job 六小时硬外框合计一百四十四 runner 小时。机制八场另列，不混入矩阵合计。每平台 large_database 与 large_asset 各 normal/cancel 一场；取消场也按完整 maximum 分配，不预支提前取消节省。实际入口每平台一个 job、每 job 四场。每 job 准备六百秒只计两次；每场 setup 六百秒及封存上传六百秒仍计八次。每平台四场 maximum 合计 9382.3 秒，加准备和前后处理五千四百秒，共 14 782.3 秒，距离六小时剩 6817.7 秒。两 job 八场共约 8.212 runner 小时。此前按八个独立 job 多计六次准备预算的版本保留在本机成本证据第一版；本次依实际入口修正，不修改测量窗口。矩阵九十六场加机制八场共一百零四场，合计约 102.910 runner 小时；这是尚未执行的预算，不累加历史已通过场次。机制后本机核验、排队和本机下载解密不在 runner 合计中。串行执行不会减少 runner 用量；账户额度未知不能伪称已获保证。六小时到达或取消后须核验真实执行者退出；未知退出保留失败及消费登记，不补跑。

## 原件、RSS 与磁盘

`capacity-increment-03` 的加量情景 storage 约为四十三、六百三十四、四百三十、一百三十一 MiB；全部 raw 约四十六、六百六十五、四百六十、一百三十九 MiB。该情景包含逐文件尾块、外层调用、额外 charge 等待、一整段积压采样及行宽余量，是敏感性估计，不是统计区间。它没有显示单流一 GiB、总原件一千二百八十一 MiB 的必然算术冲突。ZIP_STORED 结构和封装清单也占总原件额度，不能把全部 raw 顶到上限后假设封装免费。

Recorder 的 bytearray 全程驻留；child 结束复制 bytes，父进程导入时 child 完整 bytes 与父 buffer 重叠，finish 又复制各流。大库加量情景仅两份内容约一千三百三十 MiB；bytearray 余量、验证集合、请求对象、SQLite/native 缓存及解释器另计。以活动测量及验证进程合计四 GiB 作为工程规划量，不是 RSS 上限，也不是新的性能通过门槛。seal 把原件读入 contents，以磁盘 TemporaryFile 写 ZIP 后流式加密，不能算成必然再驻留一整个 ZIP。

磁盘按每个大库四臂各保留 raw 和密文约五点二 GiB，加当前 ZIP/child 流、四套虚构实例和备份、工作树及安装余量，采用额外十二 GiB 的工程规划量。此值不授权删除历史或失败材料；若保留全部工作流材料，应按 job 数累计另行管理。累计收据写量不能再加成三十五 GiB 峰值占盘。

已核验 Windows/Linux runtime 原件实际只含 environment 的 cpu_count、machine_sha256、os、release_sha256，以及 Python/SQLite 版本。两者均四 CPU；Windows 为 Python 3.10.11 / SQLite 3.40.1，Linux 为 Python 3.10.22 / SQLite 3.46.1。原件没有 RAM、可用内存或磁盘字段，故这些容量明确为未采集，不能从 CPU 数推断。采用上述规划假设完成成本冻结输入，不为消除所有 OS 不确定性新增环境采集或采样；实际容量失败照实保留。

## 冻结与结果边界

成本假设可作为冻结输入；它不代替最终工具清单、来源核验、机制准入和唯一运行登记。大库繁忙档视图复制估计仍接近五分钟，整体窗口没有解除视图期限风险。冻结后不见结果调整窗口、采样、负载或门槛。

每臂独立保留原件并加密，不能把九十六臂串接成一个限额内对象。公开端只按既定许可处理密文与收据；完整原件还须本机认证解密、结构核验和私有扫描。内存不足、容量超界、封装失败、上传状态未知、退出未知均不能变成通过，不自动重复发布或重跑。本次没有运行夹具、负载、环境采集、CI dispatch 或正式审查。

最终核对另外发现：成本汇总曾把机制的大资产误写为多小文件，且使用了后者窗口。第四版本保留；第五版本按既定大数据库与大资产八场重算，未改变任何单臂窗口、预算场次或执行计划。
