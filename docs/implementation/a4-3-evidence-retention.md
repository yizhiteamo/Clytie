状态：用户已确认“CI 加密待核验 → 本机解密后私有扫描”。本机保存工具回归及真实虚构夹具加解密已通过；尚无实际远端 artifact，未开始新机制验证或矩阵，不宣称性能原始数据已归档。正式审查仍已用 1/3。

## 本轮有限例外

用户在本轮明确批准：仅本次 A4.3 性能验证产生的结构化虚构测量原件，允许在通用扫描的数字编号、时间戳等命中已被逐类核实为误报后，加密保存到仍为 PRIVATE 的本仓库 Actions artifact。真实敏感、来源不明或无法解释的命中不得上传。此项仅覆盖 AGENTS 及 repository.md 中本轮原始测量证据的有限保存限制，不修改扫描器、不添加全局豁免，不授权访问更多私有数据或泛化到未来任务。

原先批准要求首次上传前完成私有扫描，因 repository.md §4 明确名单不进入 CI 而缺少执行通道。用户随后明确修订：**仅此批文件可在指定检查后先上传密文，本机解密及私有扫描在后**。旧批准及执行缺口保留在历史提交中；没有将旧失败证据改写为通过。私有名单和解密私钥始终留在本机，不上传 CI、不进入 GitHub Secrets 或 artifact。

CI 状态只能是“加密待核验”，不能声称已私有扫描。误报说明标记“经用户批准的虚构测量误报保存例外”，不能写成“扫描全部通过”。完整 CI 日志、环境转储和异常原文不在例外内；其他源码、文档、提交、报告、Issue、评论和摘要继续执行原双扫描规则。

## 文件白名单与核验

只考虑明确列入清单并有严格 Schema 的文件，不上传缓存目录或任意 glob 匹配结果。预定白名单：每次执行的 `requests.jsonl`、`storage-phases.jsonl`、`resources.jsonl`、`release-events.jsonl`、`run-manifest.json`。文件与 Schema 的实施版本需在运行前冻结；没有完整记录或校验失败时作为证据失败处理，不删除慢请求或失败样本。

- 请求、锁/事务、资源及释放事件仅保存稳定虚构编号、阶段枚举、数值、时间及状态；禁止 SQL 参数、聊天、记忆正文、凭据和真实部署路径。
- 运行清单仅保存完整候选及参考提交、CI 运行/作业标识、冻结参数、负载计划及必要平台信息。环境信息采用固定字段，不枚举或转储环境变量、用户目录或机器凭据。
- Schema 检查字段类型、大小上限和明确路径，拒绝额外字段、意外文件、链接、路径越界、自由异常文本及未定义类型；核对生成器只使用虚构实例及假后端。来源、Schema 或扫描器失败即停止，不默认放行。
- 原件不修改、不重编码规避扫描。SHA-256、扫描结论、误报类别、依据与索引另存；扫描命中原文不进入 PR。
- 上传前重新核实仓库 PRIVATE；状态未知或已公开即停止。既有权限保持，不新增协作者、不扩大 Actions 权限。

## 专用密钥、封装与上传

使用成熟维护的公钥封装和认证加密实现，不自行设计密码算法。独立证据密钥对只在本机生成，不复用实例备份密钥或账号凭据；私钥位于源码仓库及 artifact 暂存目录之外的受控位置，沿用或收紧文件权限，不放宽 ACL。私钥内容不得打印、写日志/报告或进入命令参数。CI 只取得公钥和可核对指纹。

记录格式版本、工具版本、公钥指纹及保管/恢复方法。先用虚构文件完成加解密与完整性验证，再启动正式测量；正常测量期间不自动轮换。旧证据保留责任结束前不得删除对应私钥。涉及新的权限、外部服务或批准范围冲突时先报告。

加密范围包括原始文件、完整清单和逐文件 SHA-256、完整候选提交、CI run/job/attempt 身份、测量方法、参数、必要环境信息、数据种子、扫描结果、已批准误报类别与来源说明。原件字节不变；明文哈希清单及详细元数据不暴露在密文之外。

封装完成并核验输出后才允许上传。artifact 仅含密文及最小非敏感说明，上传使用精确密文路径，不用目录通配符。加密失败、取消和 always() 路径也不允许上传明文或失败后退回明文；临时明文不是持久归档。仅上传成功不等于测量、私有扫描或证据验收通过。

## 本机核验与状态

沿用现有授权下载渠道，不新增常驻服务、自托管 runner 或后台任务。先验证认证加密完整性，再安全读取包内材料；拒绝路径穿越、链接及覆盖已有证据，核对候选/运行身份、文件清单和全部哈希，然后执行通用及私有扫描。私有扫描不可用时不能跳过。

状态严格区分：

1. 加密待核验。
2. 核验失败或私有扫描失败。
3. 核验完成，私有扫描通过，通用误报按批准例外记录。

解密后的原件不得重新明文上传。有通用误报的原件不能标为“双扫描全部通过”；实际私有命中或来源异常时，停止使用和传播，保留本机事件证据并报告用户处理对应 artifact，不自行扩大例外。本机核验未完成，不将该证据用于正式验收通过结论。

artifact 请求保留十四天；上传后读取平台返回的创建/到期时间，核实实际接受期限并记录。如果无法核实，报告归档未完成及风险。

PR 仅发布双扫描通过的摘要和证据索引，不放原件或公开外链。仓库转公开前，用户必须逐项核查本例外的 artifact 及相关访问范围，不能仅依赖到期自动删除。

## 实施入口与本机证明

技术选型见 ADR 0028。`scripts/measurement_evidence.py` 保存固定字段校验、原字节封装和本机扫描；`scripts/measurement_transport.py` 提供 `keygen`、`seal`、`ci-seal`、`upload-gate`、`download`、`verify`。只允许五个明确文件，每个最多六十四 MiB、每行最多十六 KiB；没有路径字段或自由异常文本。数字误报仅在严格字段及字符串扫描全部通过后按类别记录。原测量生成器尚须接入这些字段，不能把字段声明当作来源证明。

`ci-seal` 核对实际 checkout 完整提交、运行、尝试、作业逻辑编号及平台，再加密；不装载私有名单。原始文件不能多、不能少，失效的 Schema 或扫描器不能产出上传凭证。内层清单含原件摘要、扫描类别和工具/格式版本；密文外仅有格式、接收者指纹、密文大小及摘要和待核验状态。

`.github/actions/encrypted-measurement-artifact/action.yml` 是尚未接入测量运行的复合步骤：封装成功并重新确认 PRIVATE 后，精确上传密文与最小说明，请求十四天；没有 always 上传、目录通配符或明文后退。失败不输出上传路径。`download` 在本机核对仓库、artifact 名称、所属运行和实际到期时间；只安全提取这两个文件。`verify` 另开新目录，完整认证后才解析内层，核对预期运行身份、所有摘要及双扫描，不覆盖旧证据。作业数字编号及 CI 链接在下载交接时与逻辑作业、平台对应保存。

本机工具回归四十项通过，覆盖真实 age 加解密、错误密钥/篡改/截断、清单摘要、错误运行身份、非法输入与路径、未知仓库或 PUBLIC 拒绝、取消/失败无上传凭证、本机私有扫描失败/不可用及受控保留期限记录。GitHub 元数据及下载网络在测试中使用假执行器；这不是实际 artifact 保留期证明。Windows 的 ACL 脚本参数传递失败曾阻止密钥生成，修复为常量编码脚本和最小环境后验证通过，没有放宽 ACL。

另使用仓库外新建的专用受控密钥，贯穿生产 `seal` / `verify` 和真实本机私有扫描，得到“核验完成，私有扫描通过，通用误报按批准例外记录”。证据位于本机忽略目录的 `bounded-io-first/local-encryption-proof-01/`；明确标为 `encryption_fixture_v1`，不计性能次数、不证明性能通过。专用密钥保管索引另存于该轮本机证据目录；外部保管副本尚未验证。密钥不会自动轮换。

测量采集准备另提供 `scripts/measurement_recording.py`：只接受四类固定 Schema 记录，含失败与取消样本；每个文件的内存缓冲受同一大小上限约束，非法记录或容量耗尽会使本次采集失败，不丢弃个别样本继续报告成功。测量期间不逐样本 fsync，缓冲的内存成本计入 RSS；最终写入新目录并 fsync 后仍只是本机/CI 暂存，必须继续执行加密及本机核验流程。五项采集器回归与既有工具合计四十五项在本机通过，尚未启动批准的机制验证或矩阵，也没有真实远端 artifact 可宣称已交接。测量器自身被强杀而未保存的数据不得补造。

采集驱动组件继续补齐：固定到达负载保留积压、失败及取消，不重新排期；RSS 只采样明确的测量进程并前后核对创建身份；快照观察区分连接关闭与实际线程退出。StorageOwner 观察覆盖真实排队、执行及收尾等待；完成回调尚未调度时在采集结束处同步核验，仍有未结束命令则采集失败。失败采集不能封装，且不妨碍已经接受的业务完成实际清理。新增组件后工具回归本机合计六十九项通过。组合驱动、冻结输入及机制/矩阵仍待完成；本段不是新的性能结果，也不能沿用较早提交的功能 CI 作为这些组件的 CI 证明。
