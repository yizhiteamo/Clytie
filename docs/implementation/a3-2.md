## 技术澄清和实现选择

按 AGENTS.md 第 4 节只读询问 Claude：主动话题无请求人而 ContextRequest.actor 原为必填。现改为 `Actor | None = None`；普通回复显式传发送者，主动话题传 None，不伪造主人。插件上下文按目标配置场景绑定；提交插件自己的定时、服务等调用不取得目标场景的权限。说明见 agent-spec §15.4、sdk-spec §5.6 和 CHANGELOG。

账本模式从 1 升至 2，为入站 JSON 补齐 reason / merged_into 字段；仍走既有运行锁、加密快照、事务迁移和失败现场恢复。历史内容不重放，unknown 不重发。模型调用结果写回前检查取消；迟到结果只进审计。元数据仍存入已有记录，不增加第二本聊天账本。

## 第 1 轮验收修复

- 过滤正则保留转义语义，配置与运行时共用 `compile_input_pattern`（IGNORECASE）。只对输入文字做 NFKC/小写；覆盖大写字面量、\S 与 \Z。
- 边界通知独立后台执行，使用注入时钟、沿用事件回调的 2 秒内部预算；异常和超时只写 WARN/status，不影响当前回复或同会话后续请求。工具始终返回“已记录”。解除暂停保留 notified_at，滚动限频不重置。
- `tests/test_agent_review.py` 覆盖：通知异常/卡住、跨群经模型登记后暂停、可防重及不可防重暂停事件均不进入任何行为、自然语言取消本人的任务/拒绝他人任务/大写编号归一化/无任务不提供工具、多层人设和不成对私密标记、agent_type 拒绝。

## Issue #26 单独授权修复（不追加自动验收）

execute 在工具创建后的外部 CancelledError 路径共用宽限超时收尾：取消未结束工具、用 token.reason 或 cancelled 完成 invocation，再登记迟到结果监视并重新抛出取消。已有收尾用局部标记保护，避免宽限到期与外部取消重叠时重复写入。task.result() 自身的取消保持原有处理；cancel() 的计时顺序未改动。

- `test_deadline_and_external_cancel_finish_invocation_once`：在截止宽限分支写入取消结果的同一轮调度注入外部取消，取消结果只写一次；迟到结果只生成审计，不改写取消终态。
