# Issue #72 实施清单

依据：用户批准的 storage-spec.md 和 ADR 0026。沿用 m4-3，不切换审查流程；正式预算已用 1/3。本文是开发检查点，不是验收结论。

目标：让运行记忆/账本有唯一线程所有者，保留事务、权限、恢复和持久性，同时满足批准的双轴性能目标。

技术：Python 专用线程、线程安全控制通知、SQLite WAL、现有跨进程锁、MockClock。初始实现不引入公共线程池连接共享、数据库合并、通用跨库日志或新节流策略。

## 1. 先行原型

- [x] 在 tests/test_storage_snapshot_prototype.py 使用等价真实 WAL 文件建立两库与关联状态，连接均在创建线程使用；跨线程访问必须拒绝。
- [x] 只读线程同时固定两库及关联状态后释放门闩，写线程持续提交新代次；分批复制后只含固定代次，不能混用重新打开的源。
- [x] 在逐页 backup progress 回调注入暂停，证明同时业务写入继续；取消必须在后续批次被观察到。
- [x] 用 MockClock 推进捕获期限，核对部分建立视图后退出、关闭和 WAL checkpoint 恢复；线程真实退出，不以 Future.cancel 代替。
- [x] 本机 Windows 运行 `.venv/Scripts/python.exe -m pytest tests/test_storage_snapshot_prototype.py -q`：3 passed。Linux 及生产组合验证待后续 CI，原型不能代替最终验收。

## 2. 所有者与容量

- [ ] tests/test_storage_owner.py 先写线程归属、独立返回值、上下文重绑和两伴侣隔离测试，观察缺少实现的失败，再实现 src/clytie/storage/owner.py 的专用线程与受控命令入口。
- [ ] 测试普通容量 64、收尾预留 16、未就绪凭证不阻塞、就绪 FIFO、多次顺序持久记录、取消后迟到责任与幂等释放；控制通知不消耗普通容量。
- [ ] 测试 queued/running/committing/finished 竞争及实际执行跟踪；不使用取消 asyncio Future 代表线程结束。
- [ ] 新增真实子进程故障注入，验证所有者异常不自建替代、原 OS 锁排除第二写入者；运行上述目标测试与原锁回归后独立提交。
