# A3.3 记忆核心实现与验收证据

## 范围与提交

本分支实现 memory-spec 的记忆核心，沿用已有 Agent、统一账本和插件宿主。数据库、源副本、密钥、包和计划均由测试在临时实例生成；未读真实实例或旧记忆，未下载模型，平台发送与线上对话/向量/重排调用为 0。Claude 只读技术询问与验收按用户授权执行。

规格及用户决定与实现分开提交。Issue #27–#30 的决定已分别落入规格和同步文档；#30 对应 `c96d028`（规格）与 `b500d19`（同步）。实现覆盖 SDK 0.6、记忆存储、投影、检索、上下文、管理 API/CLI、Schema 和契约测试。没有批量删除：临时 SQLite 及附属文件、过期快照只逐个删除明确路径；崩溃遗留文件仅提示，交给用户处理。

## 规格各节与技术选择

§0/§12 的 A3.4、真实模型、常规备份、在线管理与旧系统迁移未实现，保持范围。§1 对应 store/追加历史/可信测试；§2/§5/§6 对应 MemoryContext 和 Agent 回归；§3 是所有读取路径共用投影；§4 为 Retrieval；§7 是只返回布尔值的本体守卫；§8/§9 为 package、crypto、transfer 和 MemoryAPI；§10 为 Schema 与插件启用/扩展检查；§11 如上；§13 文档已同步。

- ADR 0006：SQLite 当前表 + 追加修订、指纹链、中文单字/双字词、派生向量；RRF 常数 60，同分按可信程度排序。向量和重排调用使用注入时钟的 30 秒上限。
- ADR 0007：cryptography 的 Scrypt、AES-GCM、P-256 ECDH/HKDF；实例只存恢复公钥，两个独立解密路径。SQLite 临时校验文件仅在实例内，明确单文件清理，status 不读残留内容。
- ADR 0008：不含原文与密钥的计划、候选指纹、冲突选择格式、导入器候选编码、来源映射、分叉历史和反向导入。
- Claude 只读确认的技术约定：`ImportCandidate` 字段；固定两路检索不增加第三条插件检索排名路线，A3.3 不调用既有 retriever；候选投影与返回 ID 过滤仅测试适配器；Python 3.10 的临时 SQLite 兼容；唯一 SystemClock 适配文件与无库只读计划。原始询问中曾有扫描误报的输出不发布、不豁免；PR 仅列这些已确认约定。
- SystemClock 仅在 API 入口构造；业务仍注入 Clock。架构检查只允许精确路径的三个 OS 时钟 API，其他路径及 time.sleep/random 继续拒绝，测试覆盖别名。
