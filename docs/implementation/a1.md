# A1 实现说明与验收证据

本文记录实现结果与已知边界，不修改已确认的架构规格。

## 实现

- Python 下限为 3.10，采用 src 布局、uv 锁文件、ruff、pytest/pytest-asyncio。CI 在 Windows 和 Linux 运行通用扫描、静态检查、离线测试、示例校验和构建。
- `sdk.types` 提供 53 个冻结数据模型，`sdk.behavior` 提供 7 个指令；JSON 数组和对象在进程内使用深度不可变容器，输入数据会复制，UTC 时间和范围条件由模型校验。
- SDK 定义平台、模型、能力、行为、记忆及其他明确的调用协议，以及 API 路由、面板、服务和定时声明。合并与形式检查是纯函数，不执行插件或发送消息。
- `CancelToken` 支持父子传播、原因和等待；`MockClock` 支持确定性推进及同刻注册顺序。所有明确接受令牌的假接口测试取消传播，平台与模型另测耗时步骤取消后不产生交付。
- `sdk.testing` 提供 22 个可复用契约检查入口：19 个扩展点协议，以及时钟、取消令牌和基础上下文。两个参考插件仅使用 SDK，不调用真实服务。
- 三份 draft 2020-12 Schema 配合语义校验检查实例、伴侣和插件。配置对象递归合并，数组/标量替换，`null` 不充当删除指令；合并结果只读。错误汇总文件、JSON 指针、期望与实际值。
- CLI 调用本地只读状态 API。A1 不依赖 HTTP 服务，不创建数据库，不启动服务，不导入插件，不访问网络，不读取 secrets 内容。
- 私有扫描名单只存在实例目录；检查缺失或空名单时拒绝提交。扫描覆盖文件与提交说明，历史扫描另检查可达提交中的内容、路径、作者/提交者身份和说明。诊断不回显私有命中值。

## 验证方法

```text
uv sync --locked
uv run --no-sync pytest
uv run --no-sync ruff check .
uv run --no-sync ruff format --check .
uv run --no-sync python scripts/check_architecture.py
uv run --no-sync python -m clytie status --home examples/home --json
uv run --no-sync pre-commit run --all-files
uv run --no-sync python scripts/audit_history.py
uv build --no-sources --no-build-isolation
```

`test_sdk_types.py` 枚举所有数据模型，新增类型但没有往返样例时失败；行为指令另有往返测试。`test_repository_safety.py` 使用内存虚构样本验证拒绝行为。`test_architecture.py` 验证时间和随机 API 的别名也会被发现；生产及参考插件代码再整体扫描。`test_status.py` 阻止网络、子进程、数据库与 secrets 内容读取，并验证退出码及输出。

Windows Python 3.10 创建 asyncio 事件循环需要本机 socketpair；某些受限沙箱会阻塞该步骤。测试不依赖外部网络、平台账号或模型账号。正常本机环境和 CI 可直接运行。

构建产物包括三份 Schema，并已验证从 wheel 本身导入资源。构建产物留在忽略的 `dist/`，不进入 Git。

本机 Python 3.10 的最终验证输出摘要（CI 结果与完整历史扫描统计见 PR）：

## 尚未规定的契约与限制

1. `Plugin` 启动/注册方法、`CandidateReader` 和 `ApiClient` 的具体操作尚未定义，只保留协议边界；不声称这些空协议通过了功能契约测试。候选记录权限投影由后续本体实现，假检索器仅返回空命中。
2. `EventEnvelope.notice` 的允许键、各本体事件的专用负载、任务完成摘要的字段尚未规定。现阶段只验证可序列化 JSON 对象；`CompanionState.states` 是保存已有状态摘要的只读技术容器，不新增状态语义。
3. 上下文的日志、存储、事件发布及可选服务对象没有完整方法规格；A1 只定义基础属性和不透明对象。权限裁剪、事件前缀执法、账号映射注入由 A2/A3 宿主实现。`assets` 的未授权属性缺失与始终可读的组合仍需明确。
4. 取消规格同时要求异常不得吞掉和能力返回 `cancelled` 结果。本实现传播 `Cancelled`/`asyncio.CancelledError`；宿主将取消转换为账本结果的边界、宽限期和截止触发仍由后续本体实现。
5. 插件清单尚未给出模型、平台、嵌入等贡献点的完整 JSON 编码；假插件清单使用空 `contributes`，由离线测试直接构造实现。SDK 的 API 路由与面板声明只验证已有字段，不执行 HTTP 或脚本。`schedule.days` 元素含义尚未定义，保持 JSON 列表而不解释星期编号。
6. `boundary`、`context` 只描述用途，未规定子字段；Schema 只接受空对象或 `x-` 注释，拒绝未定义普通键。`channels.account` 保留非空引用字符串，不猜测编码与解引用规则。
7. `model.config`、`channels[].config` 相对 `plugins.<id>.config` 的优先级未规定：前两者各自应用插件默认并校验，三层合并严格限于规格第 5 节。不同插件目录同名时报告歧义，不选择覆盖顺序。

以上问题需要后续设计明确；没有用实现自行补充公共行为，也没有把未完成项标记为已验收。A1 的设计验收、PR 合并和公开仓库操作由用户决定。
