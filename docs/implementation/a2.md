# A2 插件宿主实现说明

## 范围

`clytie.plugin_host` 提供离线发现/清单校验、确定的启停计划、按伴侣与账号装配、注册及分发、ctx 裁剪、故障隔离、热加载、私有状态与版本记录、加密升级/恢复、卸载保留状态和官方 catalog。四个参考插件均从清单构造、start、factory/handler 装配后运行契约测试。

用户确认的规格分成三个独立提交：`5b871fc`（连带停用）、`75da3d0`（备份/通知）、`520e73a`（记忆权限）。技术询问后采用的内部编码见 plugin-host-spec，AEAD 选型见 ADR 0004；SDK 不兼容更新记在 CHANGELOG 的 0.3.0。

第 1 轮验收提出 D1/D2，用户确认后以 `16fca61` 独立提交就地升级与失败恢复规格。宿主不再安装或交换代码包；仅数据版本变化才进入“只读计划 → 确认 → 快照校验 → 迁移 → 记录 → 删除日志 → 启动”。提交前迁移失败保留完整故障目录、恢复私有状态、保留旧版本记录并停止插件，不自动回退代码或修改 enabled。

本地测试和双平台 CI 的实际输出、扫描结果与最终提交哈希在 PR 中记录。私有名单扫描仅在本机运行，CI 只做通用扫描。完整历史检查包括作者/提交者、提交说明、路径和内容。

## 运行边界

测试只使用手写虚构数据和临时实例目录；不会读取真实实例配置、密钥、记忆、人设或资产。线上平台发送与模型调用均为 0；授权的 Claude 技术询问和自动验收单独保留原始 JSONL。没有批量删除、系统环境变量、开机启动或计划任务。

加密快照留存与用户确认的故障目录清理只在临时目录测试，每次删除一个经校验的明确文件并记录；恢复本身不删除文件，整目录保留供排查，不自动清理。清理计划逐目录列出位置、文件数与大小；内容改变则失效，执行期间发现链接或新增文件立即停止。status 通过本地 API 显示保留目录、大小与总占用，之后迁移成功才标记可以清理。备份两个 CLI、常规备份、真实调度、数据库与管理 API 不在 A2。桌面通知只用假后端，尚未实机弹窗；第一次真实通知仍需用户同意。

## 第 1 轮问题的修复对应

- F1：在途集合只持有宿主创建的单次调用任务；入站流单独跟踪取数任务，停用关闭流；drain 超时不能跳过 stop。
- F2：迁移只注入始终属性，模型/平台使用 primary 单元已经校验的第四层配置，不需要平台身份或依赖服务。
- F3：按已确认规格删除代码包暂存及交换入口，重启后的第二次迁移有回归覆盖。
- F4：迁移不修改 unit_configs，失败不重建旧插件；回退代码后普通插件仍可启用和传入新配置。
- F5：ctx 及能力对象只公开 SDK 成员，普通属性访问无法获取宿主或后端；该封装不宣称隔离恶意 Python 反射或任意文件访问。
- stop 取消：新的迁移必须在插件停止后才能计划；快照之后的失败清理与恢复作为完整操作受保护，重复取消在恢复完成后才传播。

## 第 2 轮问题与确认后的恢复协议

- U1：独立规格提交 `1b723c6`。第一个脚本前原子写迁移日志；恢复失败持久化阻止加载、新迁移和关联故障目录清理。已有版本而私有目录缺失时拒绝创建空目录。status 持续显示错误、阶段、三个位置、快照和解除方式。
- U2：独立规格提交 `d1912c4`。migrating 日志按旧记录自动恢复、新记录只清残留并审计、缺失/其他记录阻止加载三分支处理；restoring 不自动重试。
- U3：独立规格提交 `1eb1224`。所有脚本成功后写一次当前版本项，再删日志，最后 start；启动失败不恢复旧状态。崩溃回归覆盖脚本前、提交前、写记录后和删日志后。
- 解除只提供只读计划和确认执行：重新恢复复用已校验的临时目录，或接受当前目录并显示快照一致性；日志/目录/快照变化使计划失效，两种操作均持久化审计。重复恢复失败仍阻止加载，故障与不完整临时目录保留。
- M1：解密也在位置报告的异常保护内。
- M2：多单元 start 失败清理抵御重复取消，全部 stop 完成后才传播取消。
- M3：原子写使用唯一临时文件；崩溃遗留文件不阻止后续写入，不自动删除残留。
- 不再回滚版本文件：自动迁移和恢复不回写版本记录；用户确认解除时按后续 Q1 规则修复异常项，迁移成功时只更新当前插件项，其他插件记录保留。

这些补充均来自用户确认的规格；技术询问只澄清了两文件提交的崩溃窗口，U2/U3 经用户决定后才实现。第 3 轮未通过后已停止；用户明确授权修复 R1/Q1 后继续验收，追加一轮，原有默认轮数规则不变。结论和双平台验证以 PR 为准。


## R1/Q1 与用户授权的追加验收

- 规格独立提交：`39f230f`（迁移串行锁与解除版本）、`06522ee`（普通冲突非阻塞与多插件全部取锁）、`14b8dc6`（解除写版本前允许改选、写版本后禁止改选）。
- `locking.py` 用 Windows 字节锁 / Linux flock 及进程内持有表保护稳定锁文件；异常与取消均释放，进程崩溃由 OS 释放。持有者记录真实 OS 进程创建时间与 pid；不用 PID 轮询决定接管，不把模拟时钟当成进程身份。当前验证平台为 Windows、Linux。
- 所有启停/卸载、热加载、迁移和解除入口先按固定 id 顺序取得完整锁集合；锁冲突不读恢复日志、不做部分装配，返回当前操作。内部加载要求调用方持锁。版本记录的读改写还有伴侣级短锁，避免覆盖其他插件项。
- `test_host_locking.py` 覆盖真实离线子进程互斥/崩溃接管、同进程多个宿主、迁移期间加载/重载不读日志、普通冲突与旧计划重校验、多插件获取中途失败无部分修改和交叉操作无等待。
- Q1 计划明确展示版本前后值：正常记录不改；缺失/异常时重新恢复写日志旧项，接受当前目录必须明确 old/target；损坏日志只能接受当前目录并显式输入范围内整数。计划的版本项不可修改，版本变化也使计划失效。
- 解除前持久化完整选择；恢复目录后先写版本再删日志。写前受控失败允许重新计划；写后崩溃与再次失败都保持已提交选择，只允许幂等继续。每次选择、失败与改选追加审计。`test_host_resolution_versions.py` 覆盖缺失/异常记录、损坏日志、无默认选择、写后崩溃、再次失败及完整审计。
- 公共扫描现允许含 a–f 字母的 7–40 位十六进制串；纯数字、非十六进制、长度越界仍检查，私有名单不豁免。32 项扫描测试通过后，第 3 轮完整原文已重新扫描并发布，未删改原结论。
- 锁原语和恢复意图字段是只读技术询问后的内部编码；普通冲突与受控失败改选涉及行为，均在用户确认后实现。没有新增 SDK 扩展点或线上操作。


## 第 5 轮前 N1–N4 修复（用户确认）

- N1：版本读取不取锁，Windows 句柄允许原子替换；仅读改写等待伴侣级短锁，使用有上限的轮询等待，不调用 time.sleep。超时抛出专用异常，普通启动清理后保持停用，不伪装成操作冲突、启动失败或恢复未完成。迁移提交写入失败返回 migration_failed，runtime 与 states 一致，保留旧版本与 migrating 日志并提示下次自动恢复。版本已写、仅清理日志失败时明确报告已提交，下次只清理残留日志。plugin-host-spec 第 7 节同步修订短锁技术细节，插件操作锁的立即返回规则不变。
- N2：close 按伴侣独立尝试锁定运行中插件，待迁移等未运行插件不取锁；返回每个伴侣 stopped / not_stopped 及原因，一个伴侣忙不阻止其他伴侣关闭。
- N3：status 与 plan 共用 Journals.action_options。损坏日志提示“接受当前目录（需要输入数据版本）”；resolution_only 只提供 accept_current；已提交选择、缺失目录或损坏快照均按实际可计划性裁剪。
- N4：interrupted 辅助函数传入完整 executor / target_version。真实迁移脚本失败后，让生产恢复写临时目录失败，检查持久化日志中的 previous_version、target_version、pid 与 OS 进程创建时间，再从该日志确认重新恢复。
- tests/test_host_review_five.py 覆盖跨进程版本锁提交/启动竞争、无锁读取与原子替换并发、专用超时、提交 I/O 失败和重启恢复、两伴侣关闭与未运行插件迁移锁、九种日志形态的 status/plan 双向一致性，以及生产日志和解除路径。所有数据和进程均用于离线临时实例。

用户明确授权仅追加第 5 轮自动验收；本轮若未通过立即停止，不自行继续。最终测试、双平台 CI、扫描与验收结果以 PR 描述及完整评论为准。


## 第 6 轮前修复（用户确认，A2 最后一轮）

close 对每个伴侣的运行集合、排序、锁和停止步骤分别隔离异常，记录未停止插件的原因并继续其他伴侣。排序只考虑运行集合中的依赖边，依赖方先停；缺失依赖不阻止停止，剩余无法排序的节点按插件 id 停止。已完成停止后才传播的取消按实际停用状态记录。

版本短锁仍使用有上限的轮询等待。新增测试实际占住写锁，走完 Operations.metadata 的全部 501 次尝试并抛超时，不替换 _record_version；多插件启用在后项超时时，MetadataLockTimeout.enabled 和 patch 带上本次已完成启用列表及对应配置补丁，调用方可保存实际结果。新增 test_host_review_six.py 覆盖依赖热加载失败后的跨伴侣关闭、排序和停止异常隔离、缺失依赖/环的停止顺序、真实超时及部分启用结果。

用户仅授权第 6 轮：若只剩不阻塞项，视为通过并登记后续 Issue；若有阻塞则停止，不进行第 7 轮。验收通过不构成合并授权。
