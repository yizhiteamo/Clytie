# 原生独立审查接入

这是用户批准的后续默认协作流程，不是产品功能，不开始 A4.3。规范以 AGENTS.md 当前默认审查条款及用户批准内容为准。A4.2 / PR #58 的历史例外和各轮记录不追溯改写；Issue #59 保持开启，旧隔离接入继续 `review_incomplete`。

## 当前工具能力与限制

本次准备直接检查会话提供的工具定义，不启动模型或真实实例探针。实际执行是否成功由文档 PR 的正式第 1 轮调用记录确认，不能仅凭工具定义写成已通过。

| 要求 | 当前入口与核对方式 |
|---|---|
| 新的独立上下文 | `collaboration.spawn_agent`，首轮显式 `fork_turns="none"`，只传批准内容、固定候选和证据入口 |
| 固定模型与推理 | 同一次调用显式 `model="gpt-6-astra"`、`reasoning_effort="high"`；本会话可用模型列表包含此组合。不使用继承默认值，也不修改全局配置 |
| 来源与完整结果 | 保存工具返回的代理标识/规范任务名、调用参数、完整最终报告和哈希；通过原生消息/完成通知取得结果，用 `collaboration.list_agents` 核对来源状态 |
| 复审上下文 | 用 `collaboration.followup_task` 向原独立代理交付新候选，沿用其审查上下文；代理不可继续时，重新建无开发聊天的独立代理，保留原报告与同一 PR 已用轮次 |
| 只读职责 | 明确禁止修复、写文件、提交、推送、发布及合并。当前 spawn 参数没有单独的只读沙箱设置，子代理共享现有环境；职责约束不是严格文件系统隔离 |

可核实的模型证据是工具定义、显式调用参数和调用接受/失败结果；本接口没有额外的供应端模型路由证明，不能声称已独立证明后台路由或依靠子代理自述升级证明等级。工具报错或无法满足指定组合时停止报告，不换模型或入口。

官方说明同样区分模型设置与继承的权限；自定义只读指令不产生独立只读沙箱。参考：https://learn.chatgpt.com/docs/agent-configuration/subagents 。本仓库采用的具体参数名以当前会话工具定义为准，不把其他版本的 CLI 参数照搬到原生入口。

## 每轮证据与操作

1. 外层先完成适当自检、测试、双扫描及必要 CI。纯文档改动不新增镜像实现的测试；执行文档路径、差异检查和现行扫描，CI 仍按仓库工作流执行。
2. 在 `.cache/auto-review/pr-<编号>/native-round-<轮次>/` 分别保存用户批准内容、`view.json`、`diff.patch`、`checks.txt`、测试/扫描记录、完整 base/head、规则版本与调用元数据。证据对应固定提交，每轮另存，不能覆盖旧轮或把开发总结当成结论。
3. 先核对同一 PR 所有入口的已用轮次，登记本轮正式调用。首轮用上述显式参数；传入只读边界和用户批准依据。只读访问仓库固定提交和本轮必要证据，不读取真实实例、记忆、人设、私有规则、私有名单或不必要凭据；不启动 MCP 业务、产品模型、真实平台或旧隔离探针。
4. 实现会话在审查期间不改待审候选。原生工具返回完整报告后由外层保存 `report.md`，另存来源、base/head、轮次、模型参数、报告哈希与实际能力限制。报告缺失、截断或配置/提交不匹配时记“审查未完成”，不能以摘要替代。
5. 外层使用现行通用及私有扫描检查完整报告，保存各自结果。通过后再次核对 PR head，再发布完整报告及来源；不通过则保全本地原文、只报告命中类别，不豁免、不删掉问题或改写结论。发布意图、结果和核对状态单独记录，状态不确定不重复发布。
6. 实现会话先核实意见，再修批准范围内的缺陷；未解决的阻塞不能自行删除或降级。新需求、架构、公共契约、隐私权限、迁移规则和规格冲突交用户。复审沿用同一 PR 的最多三轮预算；通过后只通知用户等待合并，不打 tag、不推进里程碑。

本次只接入原生协作入口，不修改旧工具代码、全局配置或权限；可以复用旧工具中纯粹的报告扫描函数，但不能调用其 `run` 或隔离预检。本文件不是独立审查报告，正式来源和结论在流程文档 PR 的逐轮证据中保存与发布。
